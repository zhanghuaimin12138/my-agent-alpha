# context-logmanager (messages, log/session persistence, context management, system-prompt builder)

## Purpose
This subsystem is gptme's memory spine. It defines the single `Message` dataclass used for every turn (user, assistant, tool output, system prompt), persists conversations as append-only JSONL directories under `~/.local/share/gptme/logs/<conv-id>/` with branches, compacted "views", a WAL-style event log, and content-addressed file attachments; it transforms that stored log into the final provider prompt (file-content enrichment, ephemeral TTL pruning, token-limit truncation, orphaned-tool-pair repair); and it builds the layered startup system prompt (identity + tool docs + user/project/workspace context + dynamic date/git-status sections) that is seeded into the log as pinned hidden system messages. The `context/` package adds opt-in context management (budget config, file/lesson selection strategies, zlib-based novelty analysis, adaptive compression, a cheap-model "scout" pre-pass), and `session.py` provides an in-memory session registry for the server/ACP frontends on top of LogManager.

## Key Abstractions
- **Message (gptme/message.py:280)** — frozen dataclass, role: Literal['system','user','assistant'] | content: str | timestamp: datetime | files: list[FilePath|URI] | file_hashes: dict[str,str] | call_id: str|None | pinned: bool | hide: bool | quiet: bool | ephemeral_ttl: int|None | metadata: MessageMetadata|None | terminal_display_content: str|None. There are NO separate tool_call/tool_output message types: tool calls live inside assistant content as fenced blocks parsed by ToolUse.iter_from_content (gptme/tools/base.py:839, fields tool/args/content/kwargs/call_id/start/_format), and tool outputs are stored as role='system' Messages carrying call_id. Equality/hash use (role, content) only; replace()/concat() (330) merge same-role messages preserving flags with min TTL.
- **Log (gptme/logmanager/manager.py:72)** — frozen wrapper around list[Message] plus a persistence cursor (persisted: tuple[Message,...] compared by identity, persisted_path, persisted_size). read_jsonl(path, limit) loads and stamps the cursor; write_jsonl(path, append=True) appends only messages past the cursor when _can_append() verifies same path, same size, trailing newline, and object-identity of the persisted prefix — otherwise rewrites atomically via NamedTemporaryFile+fsync+os.replace and returns an updated Log. This makes the common case O(new messages) while keeping edits/truncations safe.
- **LogManager (gptme/logmanager/manager.py:219)** — __init__(log, logdir, branch='main', lock=True, view=None). Holds _branches: dict[str, Log] (main → conversation.jsonl, others → branches/<name>.jsonl) and _views: dict[str, Log] (views/<name>.jsonl). log property returns the current view if set else current branch; append() snapshots attachments by hash then dual-writes to main+view when a view is active; write(branches=True, sync=False) persists everything and optionally fsyncs files+event logs+directories. Exposes workspace (logdir/workspace symlink with ChatConfig fallback, 451), name, fork(), branch(), diff(), create_view/switch_view/switch_to_master with a views/.current marker restored on load, undo(n), edit(new_log). Class method load(logdir, initial_msgs, branch, create, lock) resolves relative paths against get_logs_dir() and re-attaches the append cursor (787-836).
- **prepare_messages(msgs, workspace, logdir) (manager.py:1137)** — The stored-log → provider-prompt transform: (1) _active_prompt_generation moves the newest generated system prompt to the front and retires older/legacy ones; (2) enrich_messages_with_context embeds attached file text (hash-addressed first); (3) prune_ephemeral_messages drops TTL-expired messages, repairs orphaned tool pairs, merges adjacent same-role messages (call_id-bearing and cache-boundary messages exempt); (4) limit_log hard-caps to the model window (should never fire — compaction handles it earlier; warns if it does); (5) optional GPTME_EVIDENCE_REPLAY re-injects compacted-away evidence from conversation.jsonl. Called by chat.step (gptme/chat.py:924) and by the overflow-recovery retry (chat.py:861).
- **get_prompt(...) -> list[Message] (gptme/prompts/__init__.py:573)** — Signature: (tools, tool_format='markdown', prompt='full'|'short'|'full-noexamples'|str, interactive, model, workspace, agent_path, context_mode, context_include, include_user_context, include_examples, initial_prompt, prompt_generation, profile). Builds named sections in three tiers — core (joined into ONE system message via _join_messages), cacheable (workspace/agent-config, kept as separate messages), dynamic (systeminfo/timeinfo/runtime/context_cmd/chat-history) — inserts the SYSTEM_PROMPT_CACHE_BOUNDARY text between cacheable and dynamic, then marks every message hide=True pinned=True (+ optional metadata.prompt_generation). Callers append these once at session start (gptme/cli/main.py:1450, gptme/acp/agent.py:793).
- **SYSTEM_PROMPT_CACHE_BOUNDARY (prompts/__init__.py:63)** — A literal system message ('# System Prompt Cache Boundary — Static bootstrap content ends above...') inserted into the log. Anthropic's _transform_system_messages folds all leading system messages up to (excluding) this boundary into the single top-level system param (llm_anthropic.py:1263-1275), and _merge_consecutive_messages refuses to merge across it — it is the explicit prompt-cache breakpoint.
- **ConversationMeta (logmanager/conversations.py:69)** — frozen dataclass summarizing one conversation dir: id, name, path, created/modified, messages, branches, workspace, agent_*, model, total_cost/tokens, models_usage, last_message_preview. Built by _meta_from_file using either a full scan (cost/token aggregation) or an 8KB tail scan with an (path,mtime) LRU-cached line count — the fast path powers list/search endpoints.
- **eventlog recover_messages(logdir) (logmanager/eventlog.py:273)** — WAL recovery: find latest checkpoint event, load its payload['messages'], replay subsequent message_append/undo/message_edit events, return message dicts (None when no events.jsonl exists). Checkpoints every 50 events; write_checkpoint also compacts away superseded events under the same flock sidecar used for appends.
- **ContextConfig / ContextSelector (gptme/context/)** — ContextConfig (config.py:11): enabled, budget (0<x≤1 fraction or int>1 absolute tokens, else dynamic min(0.9*window, window-max_output-headroom)), scout_model, nested selector config. ContextSelector.select(query, candidates: Sequence[ContextItem], max_results) with rule/llm/hybrid strategies; file_selector feeds workspace files (git ls-files) weighted by mention/recency/git-status. Opt-in — the default path uses none of this.
- **BaseSession / SessionRegistry (gptme/session.py:21/56)** — BaseSession(id, log: LogManager|None, conversation_id, cwd, active, created_at, last_activity) with touch()/deactivate(); SessionRegistry is a dict wrapper: create/get/remove/list_sessions/cleanup_inactive(max_age_minutes=60). Purely in-process handle tracking for ACP (log passed directly) and server (conversation_id, lazy load) — durable state lives entirely in LogManager files.

## Data Flow
STARTUP: cli/main.py picks a logdir via get_logdir (1598) → generate_conversation_id produces 'YYYY-MMDD-<slug>' (util/auto_naming.py:69) → get_prompt(tools, workspace, ...) (prompts/__init__.py:573, called at cli/main.py:1450) assembles [core_system_msg, workspace_msgs..., CACHE_BOUNDARY, dynamic_msgs...] each pinned+hidden → chat() seeds a fresh LogManager and appends these to conversation.jsonl.
TURN: user Message appended via LogManager.append (manager.py:542) — attachments snapshotted to files/<hash> (manager.py:569, util/file_storage.py:45), log written incrementally (Log.write_jsonl append path, manager.py:158), a message_append event appended to events.jsonl (manager.py:494→eventlog.py:129). chat.step (chat.py:895) then calls prepare_messages(log.messages, workspace, logdir) (manager.py:1137): active-prompt-generation selection → file-content enrichment (util/context.py:262) → ephemeral-TTL pruning + orphan repair + same-role merging (manager.py:1005-1072, util/reduce.py:553) → limit_log hard cap (util/reduce.py:624). The resulting list[Message] goes to the provider adapter: msgs2dicts (message.py:809) → _handle_tools converts assistant-content tool blocks into API tool_calls and system+call_id messages into role='tool'/tool_result (llm_openai.py:1790, llm_anthropic.py:1432), _transform_system_messages folds the leading system block into the Anthropic system param and places cache_control breakpoints (llm_anthropic.py:1232, 1394-1440). The streamed assistant Message (tool calls embedded in content) is appended to the log; execute_msg parses ToolUse blocks (tools/base.py:839) and runs them, appending each tool output as a system Message with call_id. On a context-length error, _reply_with_overflow_recovery compacts via compact_for_overflow, stores the result as a new view (views/compacted-NNN.jsonl), switches to it, retries prepare_messages, and logs a compaction event (chat.py:823-892).
SHUTDOWN/RESUME: write(sync=True) fsyncs transcripts, event logs, and parent directories (manager.py:610-687, durability.py:75). Resume = LogManager.load(logdir) re-reading conversation.jsonl (and restoring the active view from views/.current, manager.py:940); if the JSONL is damaged, eventlog.recover_messages rebuilds state from checkpoint+events (eventlog.py:273). Listing/searching uses conversations.py's tail-scan fast path.

## Design Highlights
- Three-role Message + call_id convention: storing tool calls inside assistant content (markdown/XML blocks) and tool outputs as system-role messages keyed by call_id keeps the on-disk log provider-agnostic and human-readable; provider adapters rehydrate native tool_calls/tool_result only at request time (llm_openai.py:1790, llm_anthropic.py:1432). One format survives provider API churn.
- Append cursor on an immutable Log: comparing persisted messages by object identity (not count) plus file size + trailing-newline check makes appends O(new messages) while still catching in-place edits, truncation, and reordering; full rewrites go through temp-file + fsync + os.replace so a crash never destroys the previous transcript (manager.py:128-205).
- Dual-write views instead of destructive compaction: compaction writes a compacted copy to views/compacted-NNN.jsonl and switches the active pointer (views/.current); conversation.jsonl always keeps the full history, so compaction is reversible and auditable (manager.py:871-969).
- Explicit SYSTEM_PROMPT_CACHE_BOUNDARY message: a literal marker in the log separates static bootstrap from session-volatile context, doubling as the Anthropic cache breakpoint and a merge barrier (prompts/__init__.py:63, llm_anthropic.py:1269).
- Ephemeral messages with turn-count TTL (ephemeral_ttl) drop thinking blocks from context without touching disk, with a computed stable cache boundary just before the first ephemeral message (manager.py:1075) and orphaned-tool-pair repair so pruning never produces API-400 sequences (util/reduce.py:553).
- Content-addressed attachments (files/<sha256><suffix>) plus Message.file_hashes let prepare_messages re-embed the file as it existed at message time even if the working copy changed — snapshot semantics for free (manager.py:569, util/context.py:262).
- WAL with checkpoints: events.jsonl + every-50-events checkpoints + flock-serialized appends + compaction gives crash recovery cheaper than full replay (eventlog.py).
- Prompt-generation marker: runtime model/tool changes append a NEW generated prompt tagged metadata.prompt_generation; prepare_messages sends only the newest generation while every old prompt stays on disk — append-only history with a mutable effective prompt (manager.py:1094).
- Everything degrades gracefully: _gen_read_jsonl drops unknown fields from newer log versions (manager.py:1261), _migrate_metadata upgrades old flat token metadata (message.py:218), missing timestamps fall back to file mtime (manager.py:1250), orphan tool results are demoted to user messages instead of poisoning requests (llm_openai.py:1803).
- Cheap-listing trick: conversation listings read only the last 8KB of each JSONL for preview/model, with an (path, mtime)-keyed LRU cache for line counts (conversations.py:161-238).

## MVP Guidance
- Replicate first (the load-bearing 20%): (1) a single frozen Message dataclass with role/content/timestamp/files/call_id/pinned/hide plus to_dict/from-JSON round-trip; (2) one JSONL file per conversation (append-only, one dict per line) under a logs dir with date-prefixed ids; (3) a LogManager with append/write/load and a simple file lock; (4) prepare_messages as an explicit pipeline (embed file attachments → trim to window); (5) a get_prompt() that returns a small list of pinned hidden system messages (identity, tools, user, project, date) appended once at session start.
- Adopt the tool-call convention early: assistant content embeds tool calls as fenced blocks; tool outputs are system-role messages carrying call_id; write one converter to your provider's native format at request time. This single decision keeps your log portable and debuggable.
- Copy the cache-boundary idea cheaply: put static prompt content first, volatile content (date, git status) last, and a marker line between them — you get provider prompt caching without any provider-specific code in the log layer.
- Add next in this order: atomic writes via temp+replace; the append-cursor optimization only when logs get big; branches/undo as copies (backup branch before edit is trivially simple and effective); content-hash attachment storage.
- Skip entirely for an MVP: the events.jsonl WAL + checkpoints (only needed once you promise crash durability), views/compaction machinery (start with truncate-in-prompt only, never rewriting disk), the whole context/ package (selector strategies, zlib novelty analysis, adaptive compressor, scout pre-pass — all opt-in extras), conv-checkpoints sidecar, model_selection_trace, evidence replay, TOML round-trip editing support, and the fast tail-scan conversation listing (a full scan is fine at small scale).
- Keep session.py's shape (registry of id → LogManager handles with last-activity cleanup) only if you build a server; the CLI needs nothing beyond a module-level 'current log' reference (their ContextVar pattern is worth copying for thread-safety).

## Open Questions
- Exact split of responsibilities between the TURN_POST autocompact hook (gptme/tools/autocompact/) and prepare_messages's limit_log: the code comments say compaction should always fire first and limit_log is a 'last resort', but the budget/trigger arithmetic lives in tools/autocompact/config.py + decision.py which is outside this subsystem's file scope.
- How server.py / webui consume LogManager concurrently (partial cache updates via get_conversation_meta_direct are hinted at in conversations.py:420) — the server-side session layer extends BaseSession but was not read here.
- The `_current_log_var` ContextVar is set in LogManager.__init__ but I did not find an explicit reset on __del__/exit; whether stale references leak across server request contexts depends on caller discipline not visible in this scope.
- context/scout.py and context/selector/ are wired through config ([context] enabled, scout_model) but their activation call sites (hooks vs chat.step) sit outside the assigned files; the injection sentinel suggests a GENERATION_PRE hook path.
