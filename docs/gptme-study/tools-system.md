# tools-system

> 译自英文原版(见 git 历史 aaf0543),由 Claude 翻译

## 目的(Purpose)
gptme 工具系统是 agent 的能力层:一个声明式的 ToolSpec 注册表,它 (a) 以三种格式(markdown 代码块、XML 标签、原生函数调用)把工具文档渲染进系统提示词;(b) 把 assistant 输出反向解析回任意格式的 ToolUse 调用;(c) 通过统一的 `execute(code, args, kwargs) -> Generator[Message]` 接口执行这些调用,该接口包裹在钩子(hook)之中(确认、遥测、执行前/后);(d) 附带约 40 个具体工具——一个有状态的有允许列表(allowlist)/拒绝列表(denylist)/shellcheck/标志位表安全机制持久 bash shell,一个进程内 IPython REPL,文件 read/save/edit 工具,一个仅函数(functions-only)的子代理(subagent)编排器(以线程、子进程或 ACP 方式派生嵌套 agent),一个浏览器工具,以及一个把外部 MCP 服务器转换成原生 ToolSpec 的 MCP 适配器。同一个 ToolSpec 抽象同时服务于面向模型的文档、执行分发、面向用户的斜杠命令(slash command)和生命周期钩子。

## 关键抽象(Key Abstractions)
- **ToolSpec** — 冻结数据类,gptme/tools/base.py:467。字段:name、desc、instructions、instructions_format: dict[ToolFormat,str](按格式覆盖,替代自动函数清单)、examples: str | (tool_format)->str、functions: list[ToolFunction]|None(注册进 IPython,不直接可执行)、init: ()->ToolSpec(加载时调用,可返回修改后的副本 —— python.py 以此改写其 instructions)、execute: ExecuteFunc、block_types: list[str](markdown langtag + API 名)、available: bool|callable + available_hint、parameters: list[Parameter]、load_priority(排序)、disabled_by_default、requires_tools(伴生闭包)、is_mcp、hints: frozenset(如 'read-only'、'destructive'、'code-exec' —— 供 hint: 允许列表使用)、read_only、hooks: dict[name,(HookType.str, fn, priority)]、commands: dict[str,Callable](斜杠命令)。__eq__ 按 name;__lt__ 按 (load_priority, name)。

- **ExecuteFunc** — 通用工具入口:execute(code: str|None, args: list[str]|None, kwargs: dict[str,str]|None) -> Generator[Message] | Message。三条通道汇于此:markdown 代码块 →(content=code,args 来自 langtag 后缀);XML →(content=内部文本,args 来自属性);原生工具调用 →(kwargs JSON 字典,code/args 为 None)。工具以 system 角色 Message 作为结果 yield;生成器形式支持流式/多消息输出。
- **ToolUse** — 冻结数据类(base.py:838):tool、args、content、kwargs、call_id、start(用于排序的字符偏移)、_format。iter_from_content() 是三种格式共用的唯一解析器;execute() 是运行时包装(钩子 TOOL_EXECUTE_PRE/POST、遥测 trace + 带时长/成败的 record_tool_call、_current_tool_use ContextVar、call_id 只盖在最后一条 yield 的消息上,使 Responses-API 的 function_call_output 配对保持 1:1);_to_params() 把位置参数映射到 Parameter 槽位用于展示/序列化;to_output() 把调用渲染回任意格式的提示词示例。
- **ToolFormat** — Literal['markdown','xml','tool'](base.py:58),模块级全局默认 'markdown' 与 set_tool_format()。同一个 ToolSpec 在三种格式下都渲染文档并接受调用;LLM 层按模型选择。原生 'tool' 解析与 markdown 解析(impersonate/user 块)共存,并跳过围栏代码块内的匹配。
- **注册表(ContextVar 工具状态)** — gptme/tools/__init__.py 把已加载工具、可用性缓存、初始化标志、会话允许列表保存在 ContextVar 中,使每个线程/asyncio 上下文(服务器会话、子代理线程)拥有独立工具集;init_tools() 是线程安全的加载器(允许列表展开含预设/通配/hint: 模式、文件路径工具、requires_tools 不动点);load_tool/unload_tool 在会话中途变更并注册/注销钩子。
- **确认钩子链** — TOOL_CONFIRM 钩子按优先级顺序(最高优先)返回 ConfirmationResult|None(None 则继续下传)。工具自有的自动批准器(shell 允许列表,prio 10)先于 CLI/服务器提示钩子运行;ConfirmAction.EDIT 返回 edited_content,在执行前替换命令。read_only 工具绕过该链,但直接咨询护栏钩子。
- **ShellSession** — 持久 bash 进程,采用哨兵分隔协议(每命令唯一的 START/END 标记 + ReturnCode/PWDHEX 尾部)、经十六进制编码的 `pwd -P` 带外跟踪 cwd、用于崩溃恢复的 env/cwd 快照文件、stdin 加固(经 tree-sitter 注入 < /dev/null)、超时阶梯(杀子进程 → 宽限 → killpg → 重启)、32MiB 字节上限,以及把整个会话软超时提升为 BackgroundJob。
- **BackgroundJob** — shell_background.py:91 —— 已注册的进程(自有 pgid),带读线程、带锁输出缓冲、会话作用域、kill/close/output 回调;既表示显式 `background:true` 任务也表示被提升的前台命令的统一表示;完成结果由 step.pre/loop.continue 钩子投递进会话。
- **子代理编排** — 仅函数 ToolSpec;subagent(agent_id, prompt, ...) 立即返回 None(发后即忘(fire-and-forget))。后端:线程(以隔离的 ContextVar 工具集和 profile 强制的允许列表重入 chat())、子进程(`python -m gptme -n`,提示词走 stdin,进度经 logdir/progress.jsonl)、ACP(外部 harness)。结果先写者胜缓存;完成入队并由钩子投递;经 logdir control.jsonl + STEP_PRE 检查点实现 cancel/steer;SubagentBudget + BoundedSemaphore 限制机群成本/并发;元数据持久化在子代理 logdir 中以便重启重建。
- **MCP 适配器** — create_mcp_tools(config) 把每个远程 MCP 工具转换成一等 ToolSpec,命名 'server.tool',Parameter 从 inputSchema 提升,execute 为闭包,负责把 JSON 内容编组 → client.call_tool;ToolAnnotations 变成 hints,使既有的允许列表/护栏机制不加改动地适用于远程工具。

## 设计亮点(Design Highlights)
- 一个 ToolSpec 驱动一切:模型文档(markdown/xml/原生)、执行分发、确认策略(hints、read_only)、斜杠命令、钩子、IPython 函数 —— 新增工具永不触碰聊天循环。
- 单个数据类实现三格式调用解析:ToolUse.iter_from_content 处理 markdown langtag、XML(两种方言,lxml 带标准库回退)、以及带花括号计数 + json_repair 与围栏代码块排除的原生 `@name(call_id): {json}` —— 使同一 agent 核心既适配弱模型(markdown)、偏好 XML 的模型,也适配 OpenAI/Anthropic 原生工具调用。
- instructions_format['tool'] 覆盖的存在专门因为 OpenAI 把函数描述限制在 1024 字符(#1697):工具提供紧凑的原生模式摘要,同时保留丰富的 markdown 文档。
- 确认实现为按优先级排序、返回 ConfirmationResult|None 的钩子链(首个非 None 者胜):工具专属的自动批准器(shell 允许列表,prio 10)先于 CLI/服务器提示运行,ConfirmAction.EDIT 允许人类在命令运行前改写它。
- 用许可标志白名单而非禁止标志黑名单(shell_flags.py):每个允许列表内的二进制声明可自动批准的标志;未知标志落入确认而非阻止。既失效安全(fail closed)又不烦人。
- 持久 shell 哨兵协议:每命令纳秒级唯一标记加上十六进制 ReturnCode/PWDHEX 尾部,使输出伪造与 stdout 合并均不可能,并让 gptme 无需 chdir 即可跟踪 cwd/env;快照文件(cd + export -p)在 shell 死亡后恢复状态,且明确告知模型丢失了什么。
- 前台转后台提升:不杀慢命令,软超时后 gptme 把仍在运行的 shell 会话注册为 BackgroundJob(带通向活跃会话的 kill/close/output 回调)并交给模型一个新的 —— 结果完成时由 step.pre 钩子注入。
- call_id 纪律:execute_msg 与 ToolUse.execute 保证每个结构化 tool_use 恰好得到一个成对结果(不可运行工具给错误结果、中断时清空排干),防止 Anthropic/OpenAI 400;工具的真实输出被盖为 function_call_output,更早的警告成为上下文。
- 处处 ContextVar:工具注册表、已加载工具、shell 会话、工作区 cwd、钩子注册都是上下文本地的,这正是服务器多会话隔离与进程内子代理线程无需热路径锁即可安全的原因。
- 仅函数工具(subagent、browser):完全没有 execute —— 函数由 python.py 的 init() 注入 IPython 命名空间,使模型在代码中组合它们(循环、预算、管道)而非一次性 JSON 调用;as_function_subtoolspecs/from_function 提供把单个函数暴露为独立工具的逃生口。
- 子代理完成经钩子(loop.continue/step.pre)而非阻塞等待:发后即忘 + 自动 '✅ completed' 注入、经 logdir control.jsonl + STEP_PRE 检查点跨进程 cancel/steer、元数据持久化在子代理 logdir 中可重启恢复。
- requires_tools 伴生闭包:工具可声明依赖(hashline_edit 需要 read),随其一起加载但绝不绕过操作者允许列表 —— 既保留能力边界又保住便利。
- 工具文档中的 {% if tools: a,b %} 模板:instructions 只在其他工具确实加载时才有条件地提及它们,保持每个会话的提示词真实。
- MCP 工具是一等 ToolSpec(server.tool 命名、hints 来自 ToolAnnotations),因此允许列表、护栏、提示词、确认全部零特殊处理地适用于远程工具。

## MVP 指引(MVP Guidance)
- 阶段 1 —— 核心:照搬 ToolSpec/Parameter/ToolUse 三件套,只保留 name、desc、instructions、examples、execute、block_types、parameters、read_only、hints。实现 execute(code,args,kwargs)->Generator[Message]、只支持 markdown 的 ToolUse.iter_from_content(围栏代码块 + langtag→工具查找)、带基础错误处理的 execute_msg、模块扫描式注册表(或显式列表 —— 用 dir() 做发现是锦上添花)。初期跳过 ContextVar(单会话),加并发时再引入。
- 阶段 2 —— 原生工具调用:加 parameters2dict(很简单)和每个提供商一个 _spec2tool;同时保持 markdown 解析活跃。尽早加 call_id 盖章规则(每个 call_id 恰好一个结果、不可运行调用给错误结果)—— 事后补很痛苦。
- 阶段 3 —— 确认:实现带钩子列表的 get_confirmation 与 ConfirmAction(confirm/skip/edit);先做一个 CLI 提示钩子加一个自动批准钩子。然后按此顺序搭建 shell 安全阶梯:带引号感知的拒绝正则 → 简单允许列表(管道命令 + 无重定向 + 无命令替换)→ shellcheck 集成 → 按二进制的标志表(仅当前三者稳定后)。
- Shell MVP:持久 bash + 哨兵标记 + ReturnCode 尾部 + select/poll 循环 + 硬超时(先杀后代再杀 bash)+ 头/尾 token 截断并把完整输出存入 logdir。推迟:tree-sitter 拆分、stdin < /dev/null AST 改写、字节上限核算、状态快照/恢复、前台提升 —— 每一项都是独立的加固层。
- Python 工具:进程内 IPython + TeeIO 捕获约 100 行,还免费获得函数注册模式;先跳过沙箱与产物检测。
- 文件工具:read(带行号 + 可选行区间)与经确认包装器的 save/append 就够了;编辑选其一 —— 简单 search/replace 块,或 hashline 式 read-打标签→edit-验证循环 —— hashline 巧妙但标签/快照/三路合并机制本身就是一个项目。只有做了快照循环才加 requires_tools。
- 子代理:先实现子进程模式(`python -m youragent -n --no-confirm`,提示词走 stdin)—— 进程隔离、进度走 jsonl 文件、完成靠轮询或钩子,外加 wait/list 函数。线程模式的重入性(隔离 ContextVar 工具集 + 重入 chat())是难点;仅当需要共享进程的速度才做。Profile(按子代理的工具允许列表)和预算最后来。
- MCP:若想要生态工具就尽早采用 —— ToolSpec 一旦存在,适配器约 150 行(inputSchema.properties → Parameter 列表、调用客户端的闭包 execute、server.tool 命名)。
- 从第一天保持"system 角色 Message 作为工具结果"的约定与按工具的 yield 消息流式输出;缓冲末条消息盖 call_id 的行为可在引入原生工具调用时再加。
