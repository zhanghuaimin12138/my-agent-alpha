# 扩展性与配置(commands、hooks、plugins、config、MCP、sandbox、credentials、profiles)

## 目的
本子系统是 gptme 的整个扩展面(extensibility surface)与运行时配置脊柱。它提供四种面向用户的扩展机制——斜杠命令(slash-commands)、生命周期钩子(lifecycle hooks)、目录/入口点插件(folder/entry-point plugins,捆绑 工具+钩子+命令+LLM 提供方)以及 MCP 服务器(既作为消费外部工具的客户端,也作为对外暴露 gptme 工具的服务端)——所有这些都构建在一个分层配置(layered config)的 TOML 模型之上(每会话 config.toml > 项目 gptme.toml > 用户 config.local.toml > config.toml > 运维方 config.runtime.toml > 内置默认值),并通过一个 ContextVar 作用域的 `Config` 对象解析。它还掌管围绕这一切可扩展性的安全封套(security envelope):针对项目声明的 shell 钩子的首次使用信任(TOFU)信任门、基于钩子的工具确认/权限系统(CLI 提示 / 服务器 SSE / 自动确认 / 确定性护栏 guardrails)、对持久 bash shell 的可选加入(opt-in)的操作系统级沙箱(firejail/bwrap/docker/wasmtime)、一个从子进程环境剥离提供方 API 密钥的环境变量白名单(allowlist),以及一个 0600 权限模式的 credentials.toml 凭据存储。启动编排位于 gptme/init.py,它排定插件发现、模型初始化、工具加载、钩子注册、信任检查、脚本钩子注册与命令注册的先后顺序。

## 关键抽象
- **command(name, aliases=None, completer=None, auto_undo=True) 装饰器 + register_command(name, handler, aliases, completer, owner_tool=None)** —— 添加斜杠命令的两种方式。装饰器(commands/base.py:54)用于内建命令:它包装处理器,使 `ctx.manager.undo(1, quiet=True)` 在执行前把命令消息从转录中移除,把名字+别名注册进进程全局的 `_command_registry`,并可选地把一个 tab 补全器 `Callable[[partial_arg, previous_args], list[(completion, desc)]]` 注册进 `_command_completers`。`register_command`(line 102)是动态路径,被 ToolSpec.register_commands() 与插件使用;设置 `owner_tool` 会在 `_command_owners` 中记录所有权,此后派发与列表都要求当前会话中 `has_tool(owner)`——进程全局注册表、会话本地强制。
- **CommandContext(args: list[str], full_args: str, manager: LogManager)** —— 传给每个命令处理器的单一上下文对象;处理器是产出 Messages 的生成器(或返回 None)。单一 dataclass 的形态意味着新增字段永远不会破坏现有处理器。
- **HookType(字符串枚举)+ HookFunc 协议** —— 以点分记法表示的约 24 个生命周期点位(hooks/types.py:66)。标准钩子是生成器 `(*event_args, **kwargs) -> Generator[Message | StopPropagation]`;签名是 Protocol 类(SessionStartHook、ToolExecutePreHook(data: ToolExecutePreData)、GenerationChunkHook、FilePreSaveHook 等),`register_hook` 使用 typing.overload,使 Literal HookType 在静态层面绑定正确的 Protocol。
- **Hook dataclass(name、hook_type、func、priority=0、enabled=True、async_mode=False)** —— 注册表单元(hooks/types.py:382)。优先级高者先运行;同名重注册即替换;async_mode=True 时钩子以复制的上下文在守护线程中运行(即发即忘的遥测/通知)。`__lt__` 按 (priority, name) 降序排序。
- **StopPropagation** —— 钩子产出它以中止该事件所有较低优先级钩子的空哨兵类(hooks/types.py:54)。在异步模式下它只被记录并忽略。
- **ToolConfirmHook -> ConfirmationResult** —— 钩子系统内权限模型的例外(hooks/confirm.py:135):确认钩子返回 `ConfirmationResult(action=confirm|skip|edit, edited_content, message)` 而非产出;按优先级顺序尝试,第一个非 None 者胜出,None = 继续下落。`get_confirmation()` 是每个工具都调用的唯一入口;没有任何已注册钩子时自动确认(自主模式)。实现:cli_confirm(0)、server_confirm(100)、auto_confirm(0)、guardrails(200)。
- **GptmePlugin(统一插件清单)** —— 把每种发现机制归一化的 dataclass(plugins/plugin.py:22):provider(自定义 LLM 提供方的 ProviderPlugin)、tool_modules(扫描 ToolSpec 的模块名)、tools(直接给出的 ToolSpec 实例)、register_hooks / register_commands(由 init_hooks/init_commands 调用的可调用对象)、init(Config)(发现时执行一次、读取 `[plugin.<name>]` 配置的生命周期钩子)。目录插件经 `_folder_plugin_to_gptme_plugin` 适配,其钩子/命令模块列表被包进 import 并调用 register() 的闭包。
- **ToolSpec.hooks / ToolSpec.commands** —— 声明式的按工具扩展:一个 ToolSpec 可以携带 `hooks={name: (hook_type_str, func, priority)}` 与 `commands={name: handler}`(tools/base.py:518-519);工具加载时 `_init_single_tool` 调用 `tool.register_hooks()`(命名空间化为 `<tool>.<hookname>`)与 `tool.register_commands()`(owner_tool=self.name),unload_tool 则注销这些钩子——因此加载一个工具就原子地接通它全部的扩展面。
- **Config(user: UserConfig、project: ProjectConfig|None、chat: ChatConfig|None、_model_source)** —— 存于 ContextVar 的解析后聚合对象(config/core.py:44)。关键方法:`get_env`(env>chat>project>user 的回落链,用于 MODEL、TOOL_MODULES、HOOK_ALLOWLIST、API 密钥)、`mcp` 属性(chat 优先的服务器并集)、`get_script_hooks()`(user+project,按优先级降序)、`get_plugin_config()`(paths + 并集白名单)。文档明确把它定位为解析对象,而不是到处传递的上帝对象。
- **MCPServerConfig(name, enabled, command, args, env, url, headers) + MCPConfig(enabled, auto_start, servers)** —— MCP 的 TOML 模式(schema):`[[mcp.servers]]` 条目;`is_http` 属性选择 streamable-HTTP 还是 stdio 传输;stdio 服务器继承完整父环境,其 env 合并覆盖其上(mcp/client.py:297-298)。跨配置层合并按服务器名进行,env 字典亦合并(config/user.py:906-967)。
- **MCPClient** —— 异步 MCP SDK 之上的同步门面(facade)(mcp/client.py:60):持有私有 asyncio 事件循环、装着 transport+ClientSession 的 AsyncExitStack、每服务器一个 CircuitBreaker、roots 列表、诱导回调。`connect(name)` -> (ListToolsResult, ClientSession);`call_tool(name, args)` -> str;`close()` 带取消与 5 秒上界。
- **create_mcp_tools(config) -> list[ToolSpec]** —— 让每个远程 MCP 工具成为一等 gptme ToolSpec(名为 `<server>.<tool>`)的桥(tools/mcp_adapter.py:200),包括 JSON Schema->Parameter 转换、注解->提示映射、确认集成,以及带客户端重启的连接错误重试。由 get_available_tools 调用,因此 MCP 工具流经与原生工具相同的白名单机制。
- **SandboxConfig + wrap_shell_cmd/build_env** —— 环境变量驱动的沙箱策略(sandbox.py:91):后端取值于 {firejail, bwrap, docker, wasmtime, none};shell 工具在 Popen 时按 `apply_memory_limit`(内)再 `wrap_shell_cmd`(外)再 `build_env` 的顺序组合;机密永远不会进入子进程环境,因为白名单在设计上就排除了提供方密钥。
- **Profile / ProfileBehavior** —— agent 能力捆绑(profiles.py:56):system_prompt + 工具白名单 + 软行为开关(read_only、no_network、confirm_writes)。硬性强制来自只加载列出的工具;内建覆盖 explorer/researcher/verifier/isolated 等;用户档案放在 ~/.config/gptme/profiles/,格式为 TOML 或 markdown+YAML frontmatter。
- **TOFU 信任:compute_shell_hash / check_project_shell_trust** —— 安全门(config/trust.py):对规范化后的 {context_cmd, sorted hook commands]} 做 sha256,按解析后的 workspace 划定作用域,持久化在 project-trust.toml,非交互时默认拒绝,经 GPTME_TRUST_PROJECT_SHELL=1 旁路。防范克隆仓库携带恶意 gptme.toml。
- **credentials.toml 存储** —— 位于 ~/.config/gptme/credentials.toml 的 `[providers.<name>] = key` 文件,以 0600 权限写入(credentials.py:52-69);是进程环境变量与配置 [env] 表之后的最后一道 API 密钥来源;被 doctor、/account 以及 openai/anthropic 提供方客户端读取。

## 设计亮点
- 万物皆钩子的对称性:连权限提示也是一个钩子(TOOL_CONFIRM),有三个可互换的实现(CLI tty 提示、服务器 SSE 往返、自动确认),纯粹由 init 模式选择——一个注册表、两种契约(生成器产出 Messages vs 返回带 None 下落的 ConfirmationResult)。
- 基于生成器的钩子直接把 Messages 产出到会话日志:一个扩展可以注入上下文(time_awareness)、改写消息(message.transform)或否决执行(StopPropagation 哨兵),而核心代码里没有任何回调管线。
- 工具自有命令、作用域分离:命令注册表是进程全局的(由兄弟服务器会话共享),但派发检查会话本地的已加载工具集(_command_owners + has_tool),避免了某个会话卸载工具后的经典多会话串扰。
- ContextVar 无处不在:配置、钩子注册表、已加载工具、自动确认状态以及当前 ToolUse 都是上下文本地的,这正是单进程多会话服务器与子代理线程在无锁读路径上安全的原因。
- GptmePlugin 作为归一化边界:目录插件、pip 入口点插件、遗留提供方入口点、甚至裸 ToolSpec 导出,都归约为一个清单 dataclass,并有可编辑安装去重(目录遮蔽入口点)以及在 ep.load() 之前检查的白名单,因此被禁用的重型插件零导入开销。
- 带名字感知合并的分层 TOML:用户层 config.runtime.toml(运维方默认值,只读,严格失败)-> config.toml -> config.local.toml(机密);项目层 gptme.toml -> gptme.local.toml;会话层每会话 config.toml——MCP 服务器与 [[providers]] 按名字合并(env 字典亦合并)而非替换,项目配置用 mtime 为键的 lru_cache。
- 带来源追踪的模型解析:resolve_model_source 不仅返回模型,还返回它来自 7 层中的哪一层(cli/chat_config/environment/project/models.default/MODEL),记录进 ModelSelectionTrace——对“为什么我在用这个模型?”的调试是极好的体验。
- 针对项目 shell 钩子的 TOFU 信任门:按 workspace 限定作用域的规范命令集 sha256,非交互上下文默认拒绝,任何猜测编码的重写之前做字节级 .orig 备份——用低成本做好克隆仓库供应链防御。
- 沙箱环境白名单刻意排除提供方 API 密钥(LLM 调用发生在父进程),把“沙箱被突破”从“凭据泄露”降级为“仅逃出工作区”;ulimit 前先 unset BASH_ENV,使启动脚本无法在内存上限之外预先分配。
- MCP 客户端是私有 asyncio 循环之上的同步门面:每服务器断路器、透明重启服务器进程的连接错误重试、容纳交互式 OAuth 的 60 秒初始化超时,以及桥接到与原生 UI 同一 elicit 钩子的 MCP 诱导(elicitation)——服务端的用户输入请求因此免费获得 CLI/WebUI。
- MCP 从一个工具抽象向两个方向工作:gptme 把外部 MCP 服务器作为 `<server>.<tool>` ToolSpec 消费,同时把自己的工具作为 MCP 服务器(GptmeMCPServer)暴露,经 ContextVar 预置把持久 shell 状态注入执行器线程。
- 无处不在的优雅退化纪律:格式错误的用户配置 MCP/provider 条目跳过并告警而不是让 --help 崩溃;未知顶层配置键在单次告警后自动从磁盘清除;插件 init/注册失败被记录并按插件隔离。

## MVP 指引
- 按此顺序构建:(1) ToolSpec + 模块扫描发现(导入模块,收集 ToolSpec 实例——约 30 行);(2) 钩子注册表:带 priority 的 Hook dataclass、一个 dict[HookType, list[Hook]]、带 StopPropagation 的生成器 trigger、ContextVar 存储;(3) 命令注册表:@command 装饰器 + 带工具回落的 handle_cmd;(4) 分层配置:用户 config.toml + 项目 gptme.toml + 每会话 config.toml,配一个统一的 get_env() 优先链——这四件套占 gptme 扩展性价值的 80%。
- 从小的 HookType 集开始:session.start/end、step.pre/post、tool.execute.pre/post、tool.confirm、turn.post。gptme 的 file.patch.*、generation.chunk、cache.invalidated、cwd.changed 是等相应功能存在后再加的精化。
- 从第一天起就把权限提示做成 TOOL_CONFIRM 式钩子(返回结果带 None 下落、优先级顺序),而不是硬编码的 input()——它日后免费送你 --no-confirm、服务器模式和确定性护栏。
