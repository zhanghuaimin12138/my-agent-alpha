# context-engine

## 目的(Purpose)
context-engine 子系统是 gptme 用来让模型的上下文窗口(context window)保持精简、相关且可恢复,同时让 agent 能连续运行数百个回合(turn)的一整套机制。它有三个循环:(1)收缩循环(shrink loop)——基于规则的自动压缩(autocompaction)(剥离旧推理内容、截断最大的工具结果、对长篇 assistant 散文做抽取式压缩(extractive compression)),LLM 摘要化作为兜底,另在捕获时对单个工具输出做主动的 LLM 剪枝;(2)记忆循环(remember loop)——分层的 markdown 长期记忆(与 Claude Code 兼容)、一个由"问题/解决方案"条目构成的 JSONL 知识库(knowledge base),以及一个按关键字/混合匹配、在 token 预算(token budget)内逐回合自动注入的"经验与技能"(lessons & skills)库;(3)守任务循环(stay-on-task loop)——一个临时的内存内待办清单(todo list),其未完成项会阻断 agent 的"我做完了"自动回复。另有一个反套话(anti-slop)质量门(quality gate,基于正则的套话特征打分)作为输出质量检查为整套机制收尾,而非上下文管理。统一的设计思想是:一份只增不改(append-only)的主日志(master log,conversation.jsonl)永不销毁;模型看到的一切都是它之上一个有损、字节可寻址(byte-addressable)的*视图*(view)。

- **gptme/anti_slop.py** — LLM 套话检测器/质量门:约 50 条带权重的正则特征,覆盖含糊其辞/词汇/排比/热情/总结/过渡/开场白/空泛等类别(anti_slop.py:37-129)、超出容忍度的破折号(em-dash)滥用、断奏句群检测(>=3 个连续 <=8 词的句子,anti_slop.py:163-174)。`detect_smells()` 返回每千词的加权命中(anti_slop.py:177);`evaluate_gate(text, mode)` -> pass/warn/fail/skip,带校准过的 relaxed/balanced/strict 预设(anti_slop.py:147-151)和短文本守卫(<20 词时仅当精选特征的加性证据权重 >=3 才判失败,anti_slop.py:313-332)。CLI:`python -m gptme.anti_slop FILE` 与 gptme/cli/cmd_slop.py。

## 关键抽象(Key Abstractions)
- **上下文预算(Context budget,get_context_budget)** — `get_context_budget(model_context, *, max_output=8192, headroom=1000) -> int` = min(0.9*window, window-max_output-headroom)。刻意与 provider 窗口分离,使压缩在"该开始压缩了"处触发而非"API 在此拒绝"处;环境变量/配置覆盖接受比例(<=1)或绝对 token 数。
- **CompactAction / should_auto_compact** — `should_auto_compact(log, limit=None) -> Literal['none','rule_based','summarize']`。单一触发条件(tokens >= budget),随后做一次"值不值"检查:模拟节省量 / 总量 >= MIN_SAVINGS_RATIO(0.10)则选择确定性的规则式裁剪,否则走更激进的 LLM 摘要器。理由:压缩会使 provider 提示缓存(prompt cache)失效,微小节省是净负收益。
- **auto_compact_log(三阶段生成器)** — `auto_compact_log(log, limit=None, max_tool_result_tokens=2000, reasoning_strip_age_threshold=5, logdir=None, keep_head=0) -> Generator[Message]`。产出一份位置 1:1 对应的日志重构:剥离推理(距末尾 >=5)、从最大开始截断工具结果(仅在仍超预算时进行)、对又旧又长的 assistant 消息做抽取式压缩(target_ratio 0.7)。消息位置被保持,因此指向 conversation.jsonl 的字节区间引用依然有效——这是一条文档化的不变量('Phases 1-3 preserve message positions')。
- **主上下文与视图(master context / views)** — conversation.jsonl 是一份永不压缩的只增不改主日志。压缩输出写到新的*视图分支*(manager.create_view/switch_view);用户发起的 '/compact' 则直接替换日志。每条被截断的消息内嵌一个由逐消息字节索引构造的 `[Content truncated - N tokens] / Master context: <path> (bytes a-b) / Preview / To recover: grep...` 块,模型因此能自行恢复被裁掉的原文。
- **ContextProvider / CompactionResult** — 抽象基类,含 `name`、`should_compress(messages, config)`、`compress(...) -> CompactionResult(messages, source_digest: role+content 流的 sha256, covered_through: int, limitations: list[str])`。带 entry-point 组 `gptme.context_providers` 的注册表允许插件替换默认策略;digest/coverage 元数据让调用方能对照已变更的源日志校验摘要。
- **PrunePlan(以查询为条件的输出剪枝)** — `plan_tool_output_prune(tool_name, output, *, context_label) -> PrunePlan | None`;`PrunePlan(ranges: tuple[(start,end)], total_lines, kept_lines, original_tokens, kept_tokens, model)`,带 `.apply(lines)`。一个便宜的 LLM(配置的摘要模型,静默输出)挑选*当前用户请求*所需的最小 1 起始闭区间行号范围;除非 token 严格减少,否则丢弃方案。完整输出总是先落盘,因此剪枝在上下文中有损、在磁盘上无损。
- **MemoryEntry + 分层 MemoryRoots** — `MemoryEntry(name, description, type, body, status, supersedes/superseded_by, keywords, ...)` 是 CC 兼容的 frontmatter markdown。根解析顺序 explicit > project > cc > agent > user;读取合并所有层、同名由最近层遮蔽,写入目标为 explicit/project/cc。生命周期:living -> superseded 通过双向链接;audit() 检查链接对称性。MEMORY.md 是常开的指针索引(pointer index);`.memory-index.json` 可选地把它变成按字节预算约束的选择视图。
- **recall() / match_memories()(两种召回模式)** — `recall(store, query, limit, backend)` = 拉模式(pull)排序检索(gptme-rag 的 TF-IDF,token 重叠兜底,结果中带显式 backend)。`match_memories(store, text, limit)` = 推模式(push)触发式投递,把 LessonMatcher 的通配符关键字语义用于条目 `keywords:`。render_recall/render_matches 产出有界的注入块。
- **Lesson / LessonIndex / LessonMatcher** — `Lesson(path, metadata: LessonMetadata, title, description, category, body, is_stub)`——gptme lessons、Anthropic skills、Cursor 规则共用一个模式。LessonIndex = 多目录扫描 + mtime 缓存 + 三级去重 + 先存根后物化。LessonMatcher.match 依据 MatchContext(message, tools_used) 为关键字(+1)/模式(+1)/技能名(+1.5)/工具(+2)打分;HybridLessonMatcher 增加语义(嵌入或 z 门控 BM25)、有效性(bandit 后验)、新近度,权重合计约 1.0。
- **有效性 bandit 状态** — `~/.local/state/gptme/lessons/bandit-state.json` = {"arms": {lesson: {alpha,beta} | {helpful,harmful,false_positive,noop} | both}}。_score_from_ts_arm = alpha/(alpha+beta);_score_from_judge_arm = (helpful+1)/(total+2) 拉普拉斯平滑;combined = 平均。lesson 可按 metadata.id、完整路径、文件名或父目录/文件名查找。这就是 lessons 的"学习"方式——帮不上忙的注入会逐渐退出排名。
- **KnowledgeEntry 存储** — `KnowledgeEntry(id, problem, resolution, tags, keywords, created_at, memory_type='knowledge_entry', entry_type)` 在单个 JSONL 中。检索 = 对 problem+resolution+tags 的整数 token 重叠计数;select_knowledge_for_session 要求 >=2 个查询关键字,每会话经行前缀哨兵注入一次 top-3、每字段裁剪至 240 字符。
- **_current_todos + 重放(replay)** — 进程局部的 {id, text, state, created, updated} 字典;ID 为递增整数。持久性是以*逻辑*方式达成的:todo 工具调用是普通消息,因此 SESSION_START 重放只重演 'write' 操作即可重建完全相同的状态——没有单独的持久化文件,而日志被压缩才是唯一会丢失它的途径(所以它们是普通消息,受同一套恢复机制保护)。
- **evaluate_gate(反套话)** — `evaluate_gate(text, *, mode=None, warn_threshold, fail_threshold, em_dash_tolerance) -> dict`,状态 pass/warn/fail/skip。分数 = 每千词的加权特征命中;MODES = relaxed/balanced/strict,在 1,098 篇帖子的语料上校准;MIN_WORDS_FOR_GATE=20,低于该值时采用加性证据 >=3 规则。

## 数据流(Data Flow)
上下文收缩循环(每回合):1) 每个回合后,TURN_POST 触发 autocompact_hook(hook.py:106),除非被 60 秒/日志未变的冷却拦下(hook.py:127-144)。2) should_auto_compact 计算 total tokens 与 get_context_budget 的关系(decision.py:110-132)。低于预算 -> 'none',返回。3a) 'rule_based':DefaultContextProvider.compress 运行 auto_compact_log。阶段 1 从距末尾 >=5 的消息剥离 <think> 块(engine.py:132-152)。阶段 2 收集 >2000 token 的超尺寸(system 角色)工具结果,按从大到小排序,只要 current_tokens >= limit 就把每个替换为 create_tool_result_summary(完整输出经 save_large_output 存到 logdir/tool-outputs/<tool>/<ts>-<hash>.txt),外加来自 build_master_context_index(conversation.jsonl) 的主上下文字节区间引用(engine.py:197-223)。阶段 3 用 compress_content 对又旧又长的 assistant 散文做保留 top-70% 句子的抽取,同样带字节引用(engine.py:227-269)。结果写入一个全新的视图分支;触发 CACHE_INVALIDATED 钩子;一条压缩事件落入 compaction.jsonl(hook.py:179-221)。3b) 'summarize':_resume_via_llm 让模型产出结构化的 RESUME.md,保存,解析其 '## Context Files' 列表,加载这些文件(工作区沙箱,每个 2000 token),并构造 new_log = 前导 system 消息 + 文件上下文消息 + 引言 + 以 assistant 消息呈现的恢复摘要,写入视图分支(resume.py:193-346)。4) 若 provider 仍以上下文长度错误硬失败,chat.py:833-851 调用 compact_for_overflow 并重试一次,在事件中记录 retry_success。手动:'/compact [trim|summarize]' 按需做同样的事,但原地替换日志而非分叉视图(handlers.py:58-152)。
主动剪枝(工具执行时):当 PRUNE_TOOL_OUTPUT 启用时,read/shell 携带输出文本与最新用户查询调用 plan_tool_output_prune;摘要模型返回 JSON 行区间;PrunePlan 过滤展示的结果,并告知模型完整输出文件的位置(read.py:233-259, shell.py:2690-2725)。
记忆(跨会话,会话开始时拉取):resolve_roots 合并 project/cc/agent/user 目录;prompts/workspace.py:419-556 在共享 64KB 预算下把每个根的 MEMORY.md(或策略视图)渲染成 '## Persistent Memory' system 消息。写入经 `memory` 工具(模型提议,用户确认)-> MemoryStore.save -> 条目 .md + MEMORY.md 索引 upsert;相互冲突的知识用 supersede() 而非删除。按需召回(gptme-util memory recall / match)按 TF-IDF 或重叠对 living 条目排序,或经 LessonMatcher 触发带关键字的条目。
LESSONS/技能(每 step):STEP_PRE -> auto_include_lessons_hook(tools/lessons.py:244)提取近期 user+assistant 文本与所用工具,LessonIndex 扫描约 12 个目录(缓存、去重、status=active),LessonMatcher 或 HybridLessonMatcher 打分,top-5 命中(可选地经 dropout 采样以做因果分析)在 50k token 预算内格式化(第一条 lesson 强制纳入)为插在 system prompt 之后的隐藏 '# Relevant Lessons' system 消息。技能另外可作为 /skill:<name> 斜杠命令调用,把 SKILL.md 正文(做 $ARGUMENTS 替换)作为 user prompt 入队,并向 skill-events.jsonl 写生命周期事件,后者最终喂养 hybrid 匹配器读取的 bandit-state 有效性分数。
知识库(会话开始/首回合):hooks/knowledge_inject.py 从最后一条用户消息推导查询,select_knowledge_for_session 要求 >=2 个关键字,top-3 条目裁剪到 240 字符,经哨兵注释守护,作为隐藏的 '<knowledge-entries>' 块一次性注入。
TODO(会话内):模型经 `todo write` 写待办(状态存于 _current_todos);SESSION_START 重放从已记录的工具调用重建状态(todo.py:150-197)。当回合结束而无任何工具调用时,complete.py 的自动回复钩子检查 has_incomplete_todos(),若为真则注入 'You have incomplete todos: ... Please continue working...' 取代结束提示;连续两次无工具回复即结束会话。
反套话(输出质检,按需):detect_smells/evaluate_gate 用加权套话正则扫描生成文本并返回 pass/warn/fail;接到 /slop CLI,未接入实时循环。

## 设计亮点(Design Highlights)
- 主上下文架构:永不销毁历史——压缩成只增不改 conversation.jsonl 之上的*视图*,并在每条被截断的消息里内嵌字节区间恢复指针,模型可以通过读自己的日志文件自行找回被裁掉的内容(util/master_context.py)。便宜、精确、无需额外索引基础设施。
- 从最大开始截断("oh-my-opencode 策略"):截断单个最大的工具结果,相比裁剪许多小结果,单位信息损失换来的节省更多;阶段 2 一旦低于预算立即停(engine.py:154-223)。
- 压缩前的节省比门(MIN_SAVINGS_RATIO=0.10):压缩会使 provider 提示缓存失效,因此由一次干跑估算器(estimate_compaction_savings)决定走规则式、LLM 摘要式还是不动——决策函数里显式的缓存经济学(decision.py)。
- 上下文预算 != 上下文窗口:一个独立旋钮(0.9 倍窗口,减去输出+余量预留,为小模型设下限),让压缩在 1M 窗口模型上有意义地触发,配置可以在不虚报模型窗口的前提下调节"从哪里开始压缩"(util/context_budget.py)。
- keep_head=2 + Message.pinned 传递:原始任务(system prompt + 第一条用户消息)在 engine 里受保护,并且在输出上重新 pin,下游 reduce_log/limit_log 也丢不掉它——保护在多层收缩后仍然存活(engine.py:308-341)。
- 位置保持的压缩:所有阶段 1:1 替换消息,因此指向 conversation.jsonl 的索引对字节区间引用仍然有效——这条明示的不变量是主上下文方案成立的基础。
- 处处可见的重入与并发纪律:以 (logdir, branch) 为键的 60 秒冷却,消息数增长即可逃逸(hook.py:37-60);围绕不加锁的 LLM 调用用文件大小/mtime 快照做过期摘要检测(resume.py:247-292);flock 保护的只增不改事件日志;原子的 0600 临时文件 + os.replace 写入并保留目标权限(memory/store.py:47-70)。
- Pruner 先存后剪:完整输出总是先落盘(tool-outputs/<hash>.txt),LLM 选出的行区间再缩小上下文中的副本——上下文有损、磁盘无损,并且被剪的块里告知模型恢复路径。
- 对摘要器输出的安全意识:LLM resume 建议的文件路径会被解析,除非位于工作区内否则拒绝——模型生成的文本被当作不受信任的文件读取输入(resume.py:85-164)。
- 双轨记忆召回对应两种认知模式:常开的指针索引(MEMORY.md,按字节限额)vs 拉式检索(recall)vs 推式触发(match_memories 仅用显式关键字——描述匹配因曾导致 100% 触发率而被移除)。
- lessons 作为统一的规则格式:gptme lessons、Anthropic SKILL.md、Cursor .mdc 都解析进同一个 Lesson dataclass(globs 翻译为关键字),三个生态共享一个匹配器与注入器(lessons/parser.py)。
- 证据驱动的 lesson 排名:skill-events.jsonl 的终局证据 + Thompson 采样/LLM 裁决臂给出每个 lesson 的有效性后验,用于给未来匹配重新加权;带 exempt/validated_core/holdout 类别的随机 dropout 甚至支持对上下文注入做因果 leave-one-out 评估(lessons/hybrid_matcher.py, lessons/auto_include.py)。
- lesson 注入中的预算不对称:唯一最优的 lesson 无论多大都强制纳入,而第 2..N 条才计入 50k 预算——一个超大的赢家不会饿死其余条目(auto_include.py:656-705)。
- 存根优先的技能索引:清单提供轻量存根,数百个技能在启动时只花一次 JSON 读取;正文只为真实命中物化(lessons/index.py:508-683)。
- 待办的持久性靠重放而非存储:todo 只活在内存里,但工具调用是被记录的消息,重放其中的 'write' 子集就能在恢复时重建精确状态——持久化免费地从只增不改日志中自然产生(todo.py:150-197)。
- 待办接进完成门(completion gate):agent 字面上无法带着未完成项随随便便结束一次自主运行——无工具调用的自动回复变成待办提醒,并有对无限唠叨的 2 次熔断(complete.py:513-548)。
- 反套话短文本守卫:每千词外推在 <20 词时会说谎,因此该门要求加性精选特征证据 >=3 且分数超阈值,并且特征性痕迹(em-dash/断奏)不计入佐证(anti_slop.py:291-332)。

## MVP 指引(MVP Guidance)
- 按此顺序构建:(1) token 计数 + 上下文预算;(2) 规则式 autocompact 三阶段引擎;(3) TURN_POST 钩子 + 冷却;(4) LLM 摘要兜底 + /compact 命令;(5) 主日志字节引用;然后才是 memory/lessons/knowledge,它们是相互独立的附加件。
- autocompact 的 MVP 必备核心:从距末尾 >5 的消息剥离推理标签;先截断最大的工具结果,并放一个 '[removed N tokens, full output at <path>]' 占位符;对又旧又长的 assistant 消息做抽取式句子打分。正则打分表(决策/结论/承诺/文件路径/错误,scoring.py:15-142)可以直接抄,无需模型调用。
- 初期跳过:ContextProvider 插件注册表与 entry points、compaction.jsonl 可观测性、视图分支机制(v1 用原地日志替换即可)、溢出重试路径、dropout 实验、bandit 状态、混合嵌入(关键字匹配本来就是文档化的默认)、技能安装器/依赖图、Cursor .mdc 翻译。
- 第一天就保留:节省比门(不要为 <10% 压缩——你会白烧提示缓存)、keep_head=2 任务保护、位置保持的替换消息、先存后剪(绝不截断而不把完整输出落盘并告知模型位置)。
- Pruner 是极好的廉价第二阶段:围绕一次返回 JSON 行区间的摘要模型调用约 80 行;用环境变量、500 token 阈值和"完整输出"提示检测做门控,使它永不违背用户显式意图。
- 长期记忆 MVP:一个放 frontmatter markdown 的目录 + 会话开始时在固定字节上限下注入的 MEMORY.md 指针索引;保存经一次带确认的工具调用。只有当跨 harness/类 CRDT 需求出现时,才加 cc 目录兼容、分层、取代与锁。
- 知识库 MVP:单个 JSONL、问题/解决方案对、token 重叠检索、top-3 经哨兵在会话开始注入一次。库变大之前跳过标签/条目类型/原子删除。
- Todo MVP:内存字典、add/update/remove 类 CLI 操作、会话开始重放 write 操作,以及——真正的要点——把 has_incomplete_todos() 接进自动回复/完成门。没有这道门,todo 工具只是装饰。
- 反套话是零依赖的独立模块——想要输出质检门的话可以逐字抄那张模式表;它不属于上下文循环。
