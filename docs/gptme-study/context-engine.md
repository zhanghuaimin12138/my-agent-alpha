# context-engine

## Purpose
The context-engine subsystem is gptme's machinery for keeping the model's context window small, relevant, and recoverable while letting the agent run for hundreds of turns. It has three loops: (1) a shrink loop — rule-based autocompaction (strip old reasoning, truncate largest tool results, extractively compress long assistant prose) with an LLM-summarization fallback, plus proactive LLM pruning of individual tool outputs at capture time; (2) a remember loop — layered markdown long-term memory (Claude Code-compatible), a JSONL knowledge base of problem/resolution entries, and a keyword/hybrid-matched "lessons & skills" library that gets auto-injected per turn under a token budget; (3) a stay-on-task loop — an ephemeral in-memory todo list whose incomplete items block the agent's "I'm done" auto-reply. An anti-slop quality gate (regex slop-tell scoring) rounds it out as an output-quality check rather than context management. The unifying design idea: an append-only master log (conversation.jsonl) is never destroyed; everything the model sees is a lossy, byte-addressable *view* over it.

## Key Abstractions
- **Context budget (get_context_budget)** — `get_context_budget(model_context, *, max_output=8192, headroom=1000) -> int` = min(0.9*window, window-max_output-headroom). Deliberately separate from the provider window so compaction triggers at 'start compacting here' rather than 'API rejects here'; env/config override accepts a fraction (<=1) or absolute token count.
- **CompactAction / should_auto_compact** — `should_auto_compact(log, limit=None) -> Literal['none','rule_based','summarize']`. Single trigger (tokens >= budget), then a worth-it check: simulated savings / total >= MIN_SAVINGS_RATIO (0.10) picks deterministic rule-based trimming, otherwise the more aggressive LLM summarizer. Rationale: compaction invalidates the provider prompt cache, so tiny savings are net-negative.
- **auto_compact_log (3-phase generator)** — `auto_compact_log(log, limit=None, max_tool_result_tokens=2000, reasoning_strip_age_threshold=5, logdir=None, keep_head=0) -> Generator[Message]`. Yields a 1:1-position reformation of the log: strip reasoning (age>=5), largest-first tool-result truncation (only while over budget), extractive compression of old long assistant messages (target_ratio 0.7). Message positions are preserved so byte-range references into conversation.jsonl stay valid — a documented invariant ('Phases 1-3 preserve message positions').
- **Master context + views** — conversation.jsonl is an append-only master log that is never compacted. Compaction output is written to a new *view branch* (manager.create_view/switch_view); '/compact' from the user replaces the log directly instead. Every truncated message embeds a `[Content truncated - N tokens] / Master context: <path> (bytes a-b) / Preview / To recover: grep...` block built from a per-message byte index, so the model itself can recover the exact original text.
- **ContextProvider / CompactionResult** — ABC with `name`, `should_compress(messages, config)`, `compress(...) -> CompactionResult(messages, source_digest: sha256 of role+content stream, covered_through: int, limitations: list[str])`. Registry with entry-point group `gptme.context_providers` lets a plugin replace the default strategy; the digest/coverage metadata lets callers validate a summary against a mutated source log.
- **PrunePlan (query-conditioned output pruning)** — `plan_tool_output_prune(tool_name, output, *, context_label) -> PrunePlan | None`; `PrunePlan(ranges: tuple[(start,end)], total_lines, kept_lines, original_tokens, kept_tokens, model)` with `.apply(lines)`. A cheap LLM (the configured summary model, quiet output) picks minimal 1-indexed inclusive line ranges needed for the *current user request*; plan is discarded unless it strictly shrinks tokens. Full output is always saved to disk first, so pruning is lossy-in-context but lossless-on-disk.
- **MemoryEntry + layered MemoryRoots** — `MemoryEntry(name, description, type, body, status, supersedes/superseded_by, keywords, ...)` as CC-compatible frontmatter markdown. Roots resolve explicit > project > cc > agent > user; reads union with nearest-layer shadowing by name, writes target explicit/project/cc. Lifecycle: living -> superseded via bidirectional links; audit() checks link symmetry. MEMORY.md is the always-on pointer index; `.memory-index.json` optionally turns it into a byte-budgeted selected view.
- **recall() / match_memories() (two recall modes)** — `recall(store, query, limit, backend)` = pull-mode ranked retrieval (TF-IDF via gptme-rag, token-overlap fallback, explicit backend in result). `match_memories(store, text, limit)` = push-mode triggered delivery reusing LessonMatcher wildcard keyword semantics over entry `keywords:`. render_recall/render_matches produce bounded injection blocks.
- **Lesson / LessonIndex / LessonMatcher** — `Lesson(path, metadata: LessonMetadata, title, description, category, body, is_stub)` — one schema for gptme lessons, Anthropic skills, and Cursor rules. LessonIndex = multi-dir scan + mtime cache + 3-level dedup + stub-then-materialize. LessonMatcher.match scores keyword(+1)/pattern(+1)/skill-name(+1.5)/tool(+2) against MatchContext(message, tools_used); HybridLessonMatcher adds semantic (embeddings or z-gated BM25), effectiveness (bandit posterior), recency, with weights summing to ~1.0.
- **Effectiveness bandit state** — `~/.local/state/gptme/lessons/bandit-state.json` = {"arms": {lesson: {alpha,beta} | {helpful,harmful,false_positive,noop} | both}}. _score_from_ts_arm = alpha/(alpha+beta); _score_from_judge_arm = (helpful+1)/(total+2) Laplace; combined = average. Lesson lookup by metadata.id, full path, filename, or parent/file. This is how lessons 'learn' — injections that don't help decay out of the ranking.
- **KnowledgeEntry store** — `KnowledgeEntry(id, problem, resolution, tags, keywords, created_at, memory_type='knowledge_entry', entry_type)` in a single JSONL. Search = integer token-overlap count over problem+resolution+tags; select_knowledge_for_session gates on >=2 query keywords and injects top-3, 240-char-clipped, once per conversation via a line-prefix sentinel.
- **_current_todos + replay** — Process-local dict of {id, text, state, created, updated}; IDs are incremental ints. Durability is achieved *logically*: the todo tool-calls are ordinary messages, so SESSION_START replay re-executes only 'write' ops to rebuild identical state — no separate persistence file, and compaction of the log is what would lose it (hence they're normal messages subject to the same recovery).
- **evaluate_gate (anti-slop)** — `evaluate_gate(text, *, mode=None, warn_threshold, fail_threshold, em_dash_tolerance) -> dict` with status pass/warn/fail/skip. Score = weighted tell hits per 1k words; MODES = relaxed/balanced/strict calibrated on a 1,098-post corpus; MIN_WORDS_FOR_GATE=20 with additive-evidence>=3 rule below it.

## Data Flow
CONTEXT SHRINK LOOP (per turn): 1) After each turn, TURN_POST fires autocompact_hook (hook.py:106) unless the 60s/unchanged-log cooldown blocks it (hook.py:127-144). 2) should_auto_compact computes total tokens vs get_context_budget (decision.py:110-132). Under budget -> 'none', return. 3a) 'rule_based': DefaultContextProvider.compress runs auto_compact_log. Phase 1 strips <think> blocks from messages >=5 from the end (engine.py:132-152). Phase 2 collects oversized (system-role) tool results >2000 tokens, sorts largest-first, and while current_tokens >= limit replaces each with create_tool_result_summary (full output saved to logdir/tool-outputs/<tool>/<ts>-<hash>.txt by save_large_output) plus a master-context byte-range reference from build_master_context_index(conversation.jsonl) (engine.py:197-223). Phase 3 compress_content top-70%-sentence extraction on old long assistant prose, also byte-referenced (engine.py:227-269). Result is written to a fresh view branch; CACHE_INVALIDATED hook fires; a compaction event lands in compaction.jsonl (hook.py:179-221). 3b) 'summarize': _resume_via_llm asks the model for a structured RESUME.md, saves it, parses its '## Context Files' list, loads those files (workspace-sandboxed, 2000 tokens each), and builds new_log = leading system msgs + file-context msgs + intro + resume as an assistant message, into a view branch (resume.py:193-346). 4) If the provider still hard-fails with a context-length error, chat.py:833-851 calls compact_for_overflow and retries once, logging retry_success in the event. MANUAL: '/compact [trim|summarize]' does the same on demand, replacing the log in place rather than forking a view (handlers.py:58-152).
PROACTIVE PRUNING (at tool execution): when PRUNE_TOOL_OUTPUT is enabled, read/shell call plan_tool_output_prune with the output text and the latest user query; the summary model returns JSON line-ranges; PrunePlan filters the displayed result and the model is told where the full output file lives (read.py:233-259, shell.py:2690-2725).
MEMORY (cross-session, pull at session start): resolve_roots unions project/cc/agent/user dirs; prompts/workspace.py:419-556 renders each root's MEMORY.md (or policy view) under a shared 64KB budget into a '## Persistent Memory' system message. Writes go through the `memory` tool (model proposes, user confirms) -> MemoryStore.save -> entry .md + MEMORY.md index upsert; conflicting knowledge uses supersede() instead of delete. On-demand recall (gptme-util memory recall / match) ranks living entries by TF-IDF or overlap, or triggers keyworded entries via LessonMatcher.
LESSONS/SKILLS (per step): STEP_PRE -> auto_include_lessons_hook (tools/lessons.py:244) extracts recent user+assistant text and tools used, LessonIndex scans ~12 dirs (cached, deduped, status=active), LessonMatcher or HybridLessonMatcher scores, top-5 matches (optionally dropout-sampled for causal analysis) are formatted under a 50k-token budget (first lesson force-included) into a hidden '# Relevant Lessons' system message inserted after the system prompt. Skills are additionally invocable as /skill:<name> slash commands which queue the SKILL.md body (with $ARGUMENTS substitution) as a user prompt and write lifecycle events to skill-events.jsonl, which eventually feed the bandit-state effectiveness scores the hybrid matcher reads.
KNOWLEDGE (session start / first turn): hooks/knowledge_inject.py derives the query from the last user message, select_knowledge_for_session requires >=2 keywords, top-3 entries are clipped to 240 chars and injected once as a hidden '<knowledge-entries>' block guarded by a sentinel comment.
TODO (intra-session): the model writes todos via `todo write` (state held in _current_todos); SESSION_START replay rebuilds state from logged tool calls (todo.py:150-197). When a turn ends with no tool calls, complete.py's auto-reply hook checks has_incomplete_todos() and, if true, injects 'You have incomplete todos: ... Please continue working...' instead of the finish prompt; two consecutive tool-less replies end the session.
ANTI-SLOP (output QA, on demand): detect_smells/evaluate_gate scan generated text for weighted slop regexes and return pass/warn/fail; wired to the /slop CLI, not into the live loop.

## Design Highlights
- Master-context architecture: never destroy history — compact into a *view* over an append-only conversation.jsonl, and embed byte-range recovery pointers in every truncated message so the model can self-recover dropped content by reading its own log file (util/master_context.py). Cheap, exact, and no extra index infrastructure.
- Largest-first truncation ('oh-my-opencode strategy'): truncating the single biggest tool result saves more per information-lost than trimming many small ones; Phase 2 stops as soon as it's under budget (engine.py:154-223).
- Savings-ratio gate before compacting (MIN_SAVINGS_RATIO=0.10): compaction invalidates the provider prompt cache, so a dry-run estimator (estimate_compaction_savings) decides rule-based vs LLM-summarize vs nothing — explicit cache economics in the decision function (decision.py).
- Context budget != context window: a separate knob (0.9x window, minus output+headroom reserves, floored for tiny models) so compaction triggers meaningfully on 1M-window models and config can tune 'start compacting here' without lying about the model's window (util/context_budget.py).
- keep_head=2 + Message.pinned propagation: the original task (system prompt + first user msg) is protected in the engine AND re-pinned on output so downstream reduce_log/limit_log can't drop it either — protection survives multiple layers of shrinking (engine.py:308-341).
- Position-preserving compaction: all phases replace messages 1:1 so indices into conversation.jsonl stay valid for byte-range references — a stated invariant that makes the master-context scheme sound.
- Reentrancy + concurrency discipline everywhere: 60s cooldown keyed by (logdir, branch) with message-count growth escape (hook.py:37-60); stale-summary detection via file size/mtime snapshots around the unlocked LLM call (resume.py:247-292); flock-guarded append-only event logs; atomic 0600-temp + os.replace writes that preserve destination permissions (memory/store.py:47-70).
- Pruner saves-then-prunes: full output always hits disk (tool-outputs/<hash>.txt) before the LLM-selected line ranges shrink the in-context copy — lossy context, lossless disk, and the model is told the recovery path in the pruned block.
- Security-conscious summarizer output: file paths suggested by the LLM resume are resolved and rejected unless inside the workspace — model-generated text is treated as untrusted input to file reads (resume.py:85-164).
- Two-tier memory recall matching two cognitive modes: always-on pointer index (MEMORY.md, byte-budgeted) vs pull retrieval (recall) vs push triggering (match_memories with explicit keywords only — description matching removed after causing 100% trigger rates).
- Lessons as one universal rule format: gptme lessons, Anthropic SKILL.md, and Cursor .mdc all parse into the same Lesson dataclass (globs translated to keywords), so three ecosystems share one matcher and injector (lessons/parser.py).
- Evidence-driven lesson ranking: skill-events.jsonl terminal evidence + Thompson-sampling/LLM-judge arms give per-lesson effectiveness posteriors that reweight future matching; randomized dropout with exempt/validated_core/holdout classes even supports causal leave-one-out evaluation of context injection (lessons/hybrid_matcher.py, lessons/auto_include.py).
- Budget asymmetry in lesson injection: the single best lesson is force-included regardless of size while only lessons 2..N count against the 50k budget — an oversized winner can't starve the rest (auto_include.py:656-705).
- Stub-first skill indexing: manifests provide lightweight stubs so hundreds of skills cost one JSON read at startup; bodies are materialized only for actual matches (lessons/index.py:508-683).
- Todo durability via replay, not storage: todos live only in memory, but because tool calls are logged messages, replaying the 'write' subset reconstructs exact state on resume — persistence falls out of the append-only log for free (todo.py:150-197).
- Todos wired into the completion gate: the agent literally cannot casually end an autonomous run with pending items — the no-tool-call auto-reply becomes a todo reminder, with a 2-strike circuit breaker against infinite nagging (complete.py:513-548).
- Anti-slop short-text guard: per-1k-word extrapolation lies on <20 words, so the gate requires additive curated-tell evidence >=3 AND score over threshold, and artifacts (em-dash/staccato) are excluded from corroboration (anti_slop.py:291-332).

## MVP Guidance
- Build in this order: (1) token counting + context budget; (2) rule-based autocompact 3-phase engine; (3) TURN_POST hook + cooldown; (4) LLM-summarize fallback + /compact command; (5) master-log byte references; only then memory/lessons/knowledge, which are independent add-ons.
- MVP must-have core of autocompact: strip reasoning tags from messages >5 from end; truncate largest tool results first with a '[removed N tokens, full output at <path>]' placeholder; extractive sentence scoring for old long assistant messages. The regex scoring table (decisions/conclusions/commitments/file-paths/errors, scoring.py:15-142) is directly copyable and needs no model calls.
- Skip initially: ContextProvider plugin registry and entry points, compaction.jsonl observability, view-branch machinery (in-place log replacement is fine for v1), overflow-retry path, dropout experiments, bandit state, hybrid embeddings (keyword-only matching is the documented default anyway), skill installer/dependency graphs, Cursor .mdc translation.
- Keep from day one: the savings-ratio gate (don't compact for <10% — you'll burn the prompt cache for nothing), keep_head=2 task protection, position-preserving replacement messages, and saves-then-prunes (never truncate without writing the full output to disk and telling the model where).
- Pruner is a great cheap second phase: ~80 lines around one summary-model call returning JSON line ranges; gate on an env flag, a 500-token threshold, and 'full output' hint detection so it never fights explicit user intent.
- Long-term memory MVP: one directory of frontmatter markdown + a MEMORY.md pointer index injected at session start under a fixed byte cap; save via a confirmed tool call. Add the cc-dir compatibility, layering, supersession and locking only if cross-harness/CRDT-like needs appear.
- Knowledge base MVP: single JSONL, problem/resolution pairs, token-overlap search, top-3 injected once at session start behind a sentinel. Skip tags/entry types/atomic deletes until the store grows.
- Todo MVP: dict-in-memory, add/update/remove CLI-ish ops, replay write-ops at session start, and — the actual point — wire has_incomplete_todos() into the auto-reply/complete gate. Without that gate the todo tool is decoration.
- Anti-slop is standalone with zero dependencies — copy the pattern table verbatim if you want an output QA gate; it is not part of the context loop.

## Open Questions
- Memory extraction is not automatic: entries are written only when the model calls the `memory` tool (with user confirmation) or via CLI — there is no post-session distillation pipeline writing memories from transcripts; is one planned or deliberately rejected?
- The effectiveness bandit (bandit-state.json) is read by hybrid matching but I found no in-repo writer updating arms from skill-events.jsonl — the judge/TS update loop appears to live in external tooling (gptme-contrib / workspace pipelines); where is arm state actually updated?
- Todo state is process-local and replayed from the log — after an auto-compaction or /compact summarize rewrite of the log, do earlier `todo write` tool calls survive in the new view? Phase 2 targets system-role messages (tool results), and the resume path keeps only leading system messages, so replayability across a summarize compaction looks fragile.
- Phase 2 of auto_compact_log treats tool results as role=='system' messages — an encoding convention of gptme's log format that is implicit in the code; worth confirming against message.py how tool output roles are assigned in structured tool formats.
- Pruner runs the summary model synchronously inside tool execution (read/shell) — latency and cost per large output are unbounded by anything except the 500-token threshold; no caching or budget cap is visible.
- anti_slop.py is wired only to a CLI (/slop), not into the generation loop — is a gate-on-generate integration planned, or is it intentionally an offline audit tool?
- memory/recall.py and knowledge.py overlap conceptually (both are keyword-ranked personal stores injected at session start); the boundary is 'CC-compatible markdown + index' vs 'typed JSONL + sentinel injection' — whether they converge is unclear.
