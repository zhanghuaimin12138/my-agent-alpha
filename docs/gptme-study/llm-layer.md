# llm-layer

## Purpose
The LLM client layer of gptme (gptme/llm/, ~10k lines) is the single seam between the agent core (messages, tools, chat loop) and every LLM backend. It exposes one entry point `reply()` that returns a finished `Message`, hides provider routing (Anthropic SDK path vs one shared OpenAI-compatible path for ~14 providers plus custom/plugin providers), converts gptme's canonical text format (`<think>` blocks and `@tool(call_id): {args}` tool calls) to and from each provider's wire format, streams tokens with live terminal rendering and early tool-call interruption, tracks usage/cost per request, resolves model names to rich metadata (context window, prices, capabilities), and owns retry/backoff policy independent of the SDKs.

## Key Abstractions
- **reply(messages, model, stream, tools, ...) -> Message** — gptme/llm/__init__.py:362. The only function the rest of the codebase calls. Fires GENERATION_PRE hooks, copies messages, tags provider exceptions with mark_llm_reply_origin, then delegates to _reply_after_hooks which picks _chat_complete (returns (str, MessageMetadata)) or _reply_stream (returns Message). Validates max_tokens>0.
- **Provider / BuiltinProvider / CustomProvider** — models/types.py:51-100. Provider = BuiltinProvider | CustomProvider where BuiltinProvider is a Literal of 16 names ('openai','openai-subscription','anthropic','azure','openrouter','requesty','gptme','gemini','groq','xai','grok-subscription','deepseek','moonshot','nvidia','local','mock') and CustomProvider is a str subclass for user-config or entry-point providers. get_provider_from_model (llm/__init__.py:483) splits 'provider/model' and wraps unknown-but-configured names in CustomProvider. The critical routing split: PROVIDERS_OPENAI (types.py:103, 14 providers) all share llm_openai; only 'anthropic', 'openai-subscription' have their own wire formats; 'mock' is in-process.
- **ModelMeta (frozen dataclass)** — models/types.py:134. Fields: provider, model, context, max_output, supports_streaming/vision/reasoning/responses_api/parallel_tool_calls/strict_tools/mid_system, price_input/price_output (USD per 1M), knowledge_cutoff, deprecated, default_tool_format, preferred_edit_format ('diff'|'whole'), pricing_type ('per_token'|'subscription'). Property `.full` = 'provider/model'. This one object drives routing decisions, cost math, tool-format choice, and capability gating throughout the layer.
- **get_model(model: str) -> ModelMeta** — models/resolution.py:176 -> _resolve_model (183). Never raises for unknown models; falls back through: exact static MODELS hit -> dynamic API fetch (openrouter/gptme) -> alias table -> date-suffix strip (-20250929) -> same-family closest match by knowledge_cutoff -> recommended model -> generic 128k. Applies infer_supports_mid_system (Qwen3.5 detection) at 178. This 'always resolve' design means new provider models work before the static dict is updated.
- **_StreamWithMetadata** — llm/__init__.py:648. Wraps Generator[str, None, MessageMetadata|None]; __iter__ captures the generator's return value from StopIteration.value as .metadata, falling back to a shared _partial dict (Anthropic message_start usage) or {'model': model}. This is the trick that lets provider stream() functions be plain generators that return metadata.
- **Provider stream()/chat() generator contract** — Every provider module exports chat(messages, model, tools, output_schema, max_tokens, temperature, top_p) -> tuple[str, MessageMetadata|None] and stream(...) -> Generator[str, None, MessageMetadata|None] yielding plain-text chunks in gptme's canonical format. Canonical format: reasoning wrapped in <think>...</think>, tool calls as '@name(call_id): {json-args}'. All downstream parsing (ToolUse.iter_from_content) works on this single format regardless of provider.
- **@retry_on_openai_error / @retry_generator_on_overloaded decorators** — llm_openai.py:939/971 and llm_anthropic.py:521/553. Wrap chat and stream. Generator variant only retries if nothing has been yielded yet (has_yielded flag, llm_openai.py:1003) to avoid duplicate output. Backoff via retry_delay_for_error honoring Retry-After; abortable via retry_abort.backoff_wait.
- **_record_usage(usage, model, ...) -> MessageMetadata** — llm_openai.py:224 and llm_anthropic.py:140. Normalizes usage (via _extract_usage_token_counts for OpenAI shapes), detects true provider for openrouter/gptme-prefixed models (llm_openai.py:258-265), calls telemetry record_llm_request (which computes cost and feeds CostTracker), and builds the MessageMetadata dict {'model', 'resolved_model', 'reasoning_effort', 'usage': UsageData, 'cost'} attached to the final Message.
- **UsageTokenCounts** — openai_responses.py:61. Normalized token counts (input/output/cache_read/cache_creation/total/reasoning). _extract_usage_token_counts (433) handles OpenAI Chat Completions (prompt_tokens/completion_tokens + prompt_tokens_details.cached_tokens), Responses API (input_tokens/output_tokens + input_tokens_details), OpenRouter (cache_write_tokens), and computes uncached input = prompt - cache_read - cache_create.
- **ProviderPlugin** — models/types.py:193. Entry-point-declared third-party provider: name, api_key_env (optional), base_url, models list, optional init(config). Discovered via importlib.metadata group 'gptme.providers' (provider_plugins.py:69); auto-initialized as an OpenAI-compatible client in llm_openai.init (llm_openai.py:673-698).
- **_LazyClient** — llm_openai.py:71. Records constructor kwargs, imports openai and materializes the real client on first attribute access — keeps the ~1s SDK import off CLI startup while init() still fails fast on missing keys.

## Data Flow
STREAMING PATH (the main one): chat loop calls `reply(messages, model, stream=True, tools, ...)` (llm/__init__.py:362). (1) GENERATION_PRE hooks may append context messages (380-393). (2) `_reply_after_hooks` (420) calls `init_llm(provider)` (433) and computes break_on_tooluse: GPTME_BREAK_ON_TOOLUSE env override, else `not model_meta.supports_parallel_tool_calls` (439-447). (3) `_reply_stream` (815) prints 'Thinking...', builds a combined chunk emitter (`_emit_chunk` fusing on_token callback and GENERATION_CHUNK hooks, 845-853), then calls `_stream` (889). (4) `_stream` (697) resolves max_tokens defaults (`_resolve_max_tokens` 227: OpenRouter 16k default / gptme max_output to avoid credit-reservation 402s), picks the provider generator: anthropic-backed gptme models -> llm_anthropic.stream with via_gptme=True and a shared `_partial` dict (713-728); grok-subscription re-registers a fresh OpenAI client if the OAuth token rotated (734-747); PROVIDERS_OPENAI/custom/plugin -> llm_openai.stream (750-766); anthropic -> llm_anthropic.stream (767-784); openai-subscription -> llm_openai_subscription.stream (785-791); mock -> llm_mock.stream. The generator is wrapped in `_StreamWithMetadata`. (5) Inside llm_openai.stream (llm_openai.py:1562): `_prepare_messages_for_api` (2471) runs the model-specific message transforms, image embedding, @tool -> tool_calls conversion, tool-result merging, and (for openrouter/anthropic models) apply_cache_control; `_should_use_responses_api` (357) dispatches GPT-5-class to `_stream_responses` (1482) which yields from the shared `_stream_responses_events` SSE loop; otherwise Chat Completions with stream_options={'include_usage': True} (1636). Deltas: reasoning (delta.reasoning_content/reasoning) is wrapped live in <think>...</think> (1709-1719, 1743); tool-call deltas emit '\\n@name(id): ' on func.name then stream func.arguments incrementally (1726-1734). Usage arrives in the final chunk -> `_record_usage` (1691-1697); metadata returned as generator value (1754). (6) Back in `_reply_stream`, the char loop (907-1072) does terminal rendering with three buffers (line_buffer for on_token, think_display_buffer for dim thinking, normal_display_buffer flushed once per chunk), suppresses think-sig comments (959-974), fires on_token per non-thinking line (1013-1041), and — when break_on_tooluse — checks `ToolUse.iter_from_content(output, streaming=True)` at format-specific break chars (`_tooluse_break_check_char` line 49: '\\n' for markdown, '}'/'>' for tool/xml) and if a runnable tool call is complete, drains the remaining generator to capture message_delta usage (`_drain_toolbreak_stream` line 61) and breaks so the executor can run the tool (1056-1072). (7) finally-block closes the generator, logs ttft/gen/tok-s and attaches MessageTimings to metadata (1124-1158); returns Message('assistant', output, metadata=stream.metadata).\n\nNON-STREAMING: `_chat_complete` (543) follows the same routing to provider chat() functions which return (text, metadata); `_reply_after_hooks` pretty-prints via ToolCallDisplay (461-480).\n\nNEXT-TURN ROUND-TRIP: the stored assistant text (with <think> + @tool syntax) is re-converted to provider wire format on the next request — OpenAI: `_handle_tools` (llm_openai.py:1790) re-derives tool_calls, system+call_id becomes role=tool, orphan tool results are demoted to user messages (1803-1823); Anthropic: `_handle_tools` (llm_anthropic.py:1097) rebuilds thinking blocks (with signatures), text parts, and tool_use blocks, tool results become tool_result content; Responses API: function_call / function_call_output items (openai_responses.py:199).\n\nMODEL RESOLUTION happens at every entry: get_provider_from_model + get_model hit the static MODELS dict or dynamic fetch, and their flags steer everything downstream (tool format, temperature forcing for gpt-5/moonshot at llm_openai.py:136-171, reasoning effort at 1304, thinking budget at llm_anthropic.py:205, message transforms at 2486-2511).

## Design Highlights
- One canonical internal format: providers yield plain text where reasoning is <think>...</think> and tool calls are '@name(call_id): {json}'. Every provider's stream() produces this, the terminal/executor/parser only consumes this, and _handle_tools converts it back to each API's native shape on the next turn. This single decision keeps N providers x M consumers from becoming N*M converters.
- Generator-return-value metadata protocol: provider stream() generators `return` the MessageMetadata dict; _StreamWithMetadata captures it from StopIteration.value; _drain_toolbreak_stream re-consumes the generator after an early tool break specifically to harvest the final usage event, with a shared _partial dict (Anthropic message_start) as fallback — usage/cost survive even interrupted streams.
- break_on_tooluse: char-level scanning with format-aware break characters (_tooluse_break_check_char) lets the agent stop generating as soon as one runnable tool call is complete and execute it, instead of waiting for the full response; models that support parallel tool calls opt out via ModelMeta.supports_parallel_tool_calls.
- 'Always resolve' model lookup: get_model never fails — alias tables, date-suffix stripping, family-prefix closest-match by knowledge_cutoff, dynamic API fetch, then a generic 128k fallback. New provider models work day one with approximate metadata.
- Retry ownership: SDK_MAX_RETRIES=0 on every client so gptme's decorators own backoff exclusively (prevents retry multiplication), ~5min cumulative budget, Retry-After header respected, generators only retried before first yield, and backoff sleeps are abortable per-thread for test teardown (retry_abort.py generation counter + Events).
- Lazy everything: PEP 562 module __getattr__ for provider functions, _LazyClient deferring the openai SDK import, per-provider init only for the active provider — CLI startup stays fast.
- Static metadata dict with construction-time stamping: MODELS is built once through _stamp_provider which stamps default_tool_format='tool' on OpenAI-compat providers and supports_parallel_tool_calls on documented providers, so the flags cannot drift from the raw per-model tables.
- Anthropic thinking-signature round-trip: signatures are embedded as <!-- think-sig: ... --> comments inside the <think> block in stored message text, then re-extracted into signed thinking blocks on the next request — satisfies Anthropic's 400-on-missing-signature rule without changing the Message schema.
- Usage normalization across 4 wire shapes (Chat Completions, Responses API, OpenRouter accounting, raw Codex SSE dicts) in one function via duck-typed _obj_get, with uncached input computed as prompt - cache_read - cache_create so cost math is provider-consistent.
- Cost as metadata + telemetry side-effect: _record_usage both stamps MessageMetadata (persisted to conversation.jsonl) and feeds record_llm_request -> CostTracker + cache-hit-rate heuristics; subscription models keep token counts but cost 0 via pricing_type.
- Prompt caching is explicit: apply_cache_control places ephemeral breakpoints on system prompt, the stable boundary before ephemeral messages, and the last two user messages — including for Anthropic models served through OpenRouter.
- The OpenAI path is the universal adapter: 14 built-ins + custom config providers + entry-point plugins all reuse one client registry keyed by Provider, differing only in api_key/base_url resolved at init().

## MVP Guidance
- Replicate first: the two-function provider contract (chat -> (str, metadata), stream -> Generator[str, None, metadata]) plus one router (get_provider_from_model + if provider == 'anthropic' elif openai-compatible). That's the load-bearing 20%.
- Copy the canonical text format immediately: <think> blocks and '@tool(call_id): {args}'. Design your Message and tool parser around it from day one; retrofitting native tool-call objects everywhere is expensive.
- Copy _StreamWithMetadata + returning metadata as the generator's return value. It's ~40 lines and makes streaming usage tracking trivial.
- Start with exactly two providers: anthropic (native SDK) and one OpenAI-compatible (openai or openrouter). Add custom-provider-by-base_url support early since it's nearly free (just another entry in the clients dict).
- Model metadata: begin with a small static dict {name: {context, price_in, price_out, supports_reasoning, max_output}} and get_model() with a lenient fallback chain; add dynamic /models fetching only when you support openrouter/local.
- Implement the retry decorator pair (function + generator-with-has_yielded-guard) with SDK retries disabled; defer Retry-After parsing and abortable backoff.
- Streaming tool-call extraction: for native tool deltas, emit the header on func.name and stream arguments incrementally — don't buffer the whole call. The ToolUse.iter_from_content streaming parse for early break is a v2 feature; v1 can wait for stream end.
- Skip initially: message transforms for strict providers (_fold_mid_system, deepseek reasoning_content restoration), the three subscription/OAuth providers (openai-subscription, grok-subscription, gptme cloud), provider plugins via entry points, validate.py, local_discovery.py, thinking-signature preservation (needed only for Anthropic extended thinking multi-turn), fast mode, think-sig display suppression.
- Add early but small: apply_cache_control for Anthropic (4 cache breakpoints is a hard API constraint worth getting right), _record_usage with per-token cost from the metadata table, and ModelMeta.supports_parallel_tool_calls to gate break_on_tooluse.
- Add the mock provider early (30 lines) — it makes tests of everything above the LLM layer deterministic and network-free.

## Open Questions
- No embeddings support exists anywhere in gptme/llm/ — retrieval/embedding features (if any) live outside this layer (e.g. gptme/knowledge/), so a re-implementation needing embeddings would add a separate client path rather than extending these provider modules.
- The `reply()` signature accepts workspace/output_schema/on_token/on_thinking, and output_schema (structured output) is implemented three different ways: OpenAI json_schema response_format, Responses API text.format, and an Anthropic fake-tool trick (_make_schema_tool + _inject_schema_instruction) — a unified abstraction was deliberately not attempted.
- Rate limiting is handled only reactively (429 retry with Retry-After); there is no client-side rate limiter or request queue in this layer.
- gptme-cloud routing (_gptme_backend) inspects the resolved ModelMeta.model prefix to decide anthropic-SDK vs OpenAI-SDK for gateway models; this is string-convention-based coupling between llm_gptme.py model listings and the router that would need redesign if the gateway adds backends.
- The tool-format story is dual: models may use native 'tool' format (tool_calls) or markdown/xml tool blocks in plain text; ModelMeta.default_tool_format and get_tool_format() choose per model, and both the stream break-check and _handle_tools must handle both — a re-implementation could pick native-only to simplify.
- llm_openai.py retains parallel streaming loops (Chat Completions at 1679-1754 and Responses at 1482-1558 + shared openai_responses._stream_responses_events); the file's own comment (1493-1501) notes a possible future merge — pick the Responses loop if consolidating for a new build.
