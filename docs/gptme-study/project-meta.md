# project-meta

## Purpose
The metadata, testing, and distribution layer of gptme: a Poetry-packaged Python project (v0.34.0) that ships a terminal AI agent as 26 console entry-points to PyPI, as 7 Docker images (including a self-host server and a VNC computer-use sandbox), and as a Tauri desktop app bundling a PyInstaller-frozen gptme-server sidecar. This layer defines dependencies (minimal hard core + 16 optional extras), a 401-file pytest suite with a three-lane CI strategy (no-API, minimal-install, real-API matrix) built around offline mock providers and heavy teardown hygiene, a Makefile-driven dev workflow (test/lint/typecheck/docs/site/release), Sphinx docs with enforced per-page audience metadata, an assembled static site for gptme.org, and AGENTS.md conventions for AI coding agents working on the repo itself.

## Key Abstractions
- **Console entry-point fan-out ([project.scripts])** — One Python package exposes 26 CLIs (pyproject.toml:36-62), each mapping name -> module:main (e.g. gptme = gptme.cli.main:main, gptme-server = gptme.server.cli:main). Sub-capabilities (server, eval, agent, doctor, auth, mcp-server) get their own binary so users can pipx-install only what they need and systemd/docker can invoke narrow surfaces.
- **Extras-based dependency lattice ([tool.poetry.extras])** — Hard deps stay tiny (CLI + 2 provider SDKs + config/parsing); everything heavy is opt-in: server (flask+pydantic), browser (playwright), tui (textual), acp, telemetry (9 opentelemetry packages), eval (dspy/swebench/terminal-bench), datascience, sandbox (wasmtime), minimal (empty — for ARM/musl/Termux), all. Lets `pipx install gptme` stay light while `poetry install -E all` powers CI.
- **Plugin entry-point group (gptme.plugins)** — pyproject.toml:32-34 registers gptme.hooks.auto_snapshots:plugin and aw_watcher_agent:plugin under the namespaced entry-point group 'gptme.plugins', so even first-party hooks load through the same discovery mechanism third-party plugins use.
- **Offline model strategy: local/test + mock/* providers** — Two layers of LLM fakes. (1) `local/` provider = any OpenAI-compatible base URL; conftest sets MODEL=local/test with OPENAI_BASE_URL=http://localhost:666 (port 666 chosen to never answer) so the full init path runs and accidental network calls fail instantly. (2) A real in-process provider `mock` with scripted models mock/echo and mock/static (gptme/llm/llm_mock.py:33-79) registered in the normal provider table, exercising reply/stream/dispatcher plumbing deterministically with zero cost.
- **requires_api marker + quota-skip machinery** — Marker declared in pyproject (line 412) and conftest (154-158). Collection-time: if no API key, all requires_api tests get skip markers (conftest.py:254-269); session-start probe makes a 1-token claude-haiku call to detect exhausted quota/invalid key (104-142); run-time: pytest_runtest_makereport rewrites failed requires_api tests whose error matches _QUOTA_ERROR_PATTERNS into skips (188-215). CI runs this lane as a cheap-model matrix only when API-related paths change (test.yml:259-335).
- **Scripted-sequence reply mocking with origin tagging** — Loop tests replace gptme.chat.reply (or _process_message_conversation) with a closure over `iter([exception, Message(...)])` that raises or returns each element (test_chat.py:1237-1245); provider errors are real httpx/openai exception instances tagged via mark_llm_reply_origin(err, output_emitted=..., visible_output_emitted=...) so the loop's is_provider_error() and retry-once-after-compaction logic is tested against genuine exception types (1231-1236, 1418).
- **sys.modules module-handle trick** — Because gptme/__init__.py does `from .chat import chat`, patch("gptme.chat.X") resolves the package attribute (the function) and fails; tests use `_chat_mod = sys.modules["gptme.chat"]` then patch.object on the true module (test_chat.py:539-547). Documented inline as a gotcha for anyone writing loop tests.
- **Autouse teardown-hygiene fixture stack** — conftest defines ~10 autouse fixtures forming a defensive cleanup chain: restore_cwd, detect_leaked_threads (snapshot/diff + ranked terminal summary + strict mode env var), clear_tools_before (resets tool registry, _init_done, chat config), cleanup_shell_after (ContextVar shell + workspace cwd), cleanup_acp_health_monitor, cleanup_subagents_after (interrupts retry-backoff sleeps, joins threads 5s cap, terminates subprocesses, resets semaphores in try/finally), cleanup_logged_warnings, _clear_proactive_summarize_cache. Ordering comments explain which fixture must tear down last.
- **Thread-leak detection** — tests/thread_leak.py helpers (snapshot_threads/diff_threads/format_leaks/is_dict_iteration_race) wired into an autouse fixture (conftest.py:344-390) plus pytest_exception_interact dumping all live thread stacks when the dict-iteration race fires (166-185). Reports by default; GPTME_STRICT_THREAD_LEAKS=1 fails the offending test — a pinning workflow for an agent that starts threads from ~27 sites.
- **In-thread real-server fixtures** — server_thread (conftest.py:663-705) builds the actual Flask create_app(), monkeypatches a known GPTME_SERVER_TOKEN, binds socket to port 0 for an OS-assigned free port, and runs app.run in a daemon thread; setup_conversation/event_listener then exercise real HTTP PUT + SSE streaming. Complementary `client` fixture uses app.test_client() with GPTME_DISABLE_AUTH for the bulk of endpoint tests.
- **Lazy, frozen-aware __version__** — gptme/__version__.py computes version on first attribute access via module __getattr__ with caching and a never-raise guard; distinguishes wheel installs (importlib.metadata), pip-from-git (direct_url.json commit), editable (git describe + dirty suffix), and PyInstaller frozen (no git at all).
- **Marker vocabulary as test policy** — pyproject [tool.pytest.ini_options] markers (407-418): slow, eval, serial, timeout, requires_api, flaky, no_retry, integration, x11, xdist_group. Combined with Makefile toggles (`make test` excludes slow+eval by default, SLOW=1 adds them with --timeout 60 --retries 2) this is the API by which CI lanes and local runs select slices.
- **Scheduled auto-release pipeline** — release.yml cron Mon/Thu creates .devYYYYMMDD pre-releases after verifying green CI; version bump + generated changelog + amended tag via scripts shared with manual `make release-*`; PyPI publish ordered last as the only non-idempotent step; downstream build.yml/tauri.yml dispatched with registration verification.
- **Docs audience contract** — docs/conf.py check_audience fails the Sphinx build unless every page declares :audience: user|power-user|developer (84-126); AGENTS.md instructs contributors to keep content at the declared level. A structural guard against documentation drift.

## Data Flow
Packaging/install flow: a contributor runs `make build` (Makefile:17) -> poetry install resolves pyproject + poetry.lock; the wheel built by `poetry build` embeds gptme/, gptme/server/webui-dist (populated by `make bundle-webui` from webui/dist, Makefile:48-52 and release.yml:298-307), export templates, and media per [tool.poetry.include] (pyproject.toml:68-79). A user installing gets 26 console scripts from [project.scripts] (pyproject.toml:36-62); on startup any of them can read gptme.__version__, which resolves lazily through __getattr__ -> _compute_version -> importlib.metadata -> direct_url.json -> (editable only) git tags (gptme/__version__.py:60-133). First-party hooks register through the gptme.plugins entry-point group (pyproject.toml:32-34). Docker path: scripts/Dockerfile.selfhost builds webui in a node stage, pip-installs '.[server]' into python:3.12-slim, and docker-compose.yml wires env keys, token, and persistent named volumes (docker-compose.yml:17-41); the computer-use profile adds an Xvfb desktop streamed over noVNC (43-82). Desktop path: `make tauri-build` builds webui, then Tauri bundles the PyInstaller sidecar from tauri/scripts/build-sidecar.sh into platform installers (Makefile:386-393). Test flow: `make test` (Makefile:57-64) invokes pytest -n 16 with coverage and marker filters; conftest.py runs first — pytest_configure sets GPTME_CHECK=false/GPTME_CHAT_HISTORY=false (160-163), pytest_sessionstart pre-downloads the embedding model and probes Anthropic quota (283-293), pytest_collection_modifyitems installs the local/test fallback model and skips requires_api when keyless (254-269). Per test, the autouse stack resets tools/config (clear_tools_before, 420-436) and re-inits via init_ (600-613); the test body either calls real subsystems (ShellSession actually executes commands), spins the real Flask server in-thread (server_thread, 663-705), or patches gptme.chat internals obtained through sys.modules (test_chat.py:543-547) with scripted iter([exc, msg]) reply sequences (1237-1245); teardown walks the cleanup chain and diffs thread snapshots (344-374). CI flow: test.yml's paths-filter gates lanes; the no-api lane runs with emptied keys and MODEL=local/test including slow tests under Xvfb (test.yml:60-128); the minimal lane proves the no-extras install on Python 3.10 (138-199); the api lane runs -m requires_api on a cheap-model matrix (259-335). Release flow: cron/dispatch -> preflight green-CI check -> bump_version.sh -> changelog generation -> amended tag -> GH release -> publish job (webui bundle, poetry build, validate-release-package, PyPI, acp shim via OIDC, artifact upload, trigger build.yml + tauri.yml with verification) (release.yml:23-403); build.yml pushes Docker images to ghcr.io with latest/dev tagging heuristics (build.yml:33-56). Docs/site flow: `make docs` builds Sphinx with -W, fetching the eval-results branch for leaderboard data (Makefile:128-137) while conf.py enforces per-page audience (docs/conf.py:90-126); `make site` assembles site/next (Next.js) + docs HTML + downloads + media into site/dist and site-check asserts required files (Makefile:146-184).

## Design Highlights
- Two-layer offline LLM strategy: an unreachable local/test endpoint (fails fast on accidental network use) plus a first-class mock provider with scripted echo/static models registered in the real provider table — the agent loop, streaming, and dispatch are all testable deterministically without any mocking library.
- requires_api as a first-class contract with three enforcement points (collection-time skip, session-start quota probe, makereport failure->skip rewrite) so flaky paid APIs never redden CI, while a paths-filter + cheap-model matrix + OpenRouter routing + GPTME_MAX_TOKENS cap keeps API spend bounded (~$30/day mentioned as the motivation).
- The conftest is treated as production code for teardown hygiene: cwd restore, thread-leak snapshot/diff with a strict-mode env var for pinning leakers, ContextVar resets, subagent interrupt-then-join with caps, and a vendored retry_compat plugin so the pytest-retry workaround itself is regression-tested (tests/retry_compat.py loaded via -p).
- Entry-point fan-out (26 scripts) turns one package into a toolkit of narrow binaries — essential for systemd units, docker ENTRYPOINTs, editor integrations (gptme-acp, gptme-mcp-server), and least-privilege automation.
- Extras lattice with an explicitly empty 'minimal' extra for constrained platforms, and a CI lane that tests the no-extras install on the oldest supported Python — packaging regressions for the common user are caught, not assumed.
- The webui is bundled into the wheel via an explicit Poetry include with a validate-release-package make target and a CI check, because generated+gitignored assets are otherwise silently dropped from release artifacts (comment at pyproject.toml:71-73).
- Lazy __version__ that distinguishes wheel/git/editable/frozen installs and never raises, because the server exposes it in API metadata.
- Release engineering as code: scheduled dev pre-releases, changelog generated from the tag range and committed into the bump commit, PyPI ordered last as the only non-idempotent step, and dispatch verification polling because gh workflow run is fire-and-forget (release.yml:357-403).
- AGENTS.md gives the project's own AI agents a git discipline (never push master, conventional commits, never git add .), a core-vs-contrib boundary rule ('when in doubt, start in contrib'), a six-term glossary (Tool/ToolUse/Message/LogManager/Step/Turn), and a memory protocol (recall at start, save durable learnings) — plus recipes like 'adding a tool is 3 steps because discovery is automatic'.
- Docs quality enforced by the build: every page must declare :audience: and the Sphinx env-check-consistency hook fails otherwise; `make docs-structure` prints the rendered sidebar for review.
- 'Are we tiny' as a tracked metric: cloc/radon/jscpd make targets, a startup-time hyperfine benchmark, and CI benchmark thresholds — size and startup are treated as features (AGENTS.md:66-70).
- Makefile as the single dev vocabulary shared by humans, CI, and AGENTS.md (make test / test SLOW=1 / typecheck / lint), with toggles (EVAL, SLOW, PROFILE, TYPE) instead of duplicated flag soup.

## MVP Guidance
- Replicate first (cheap, high leverage): a flat pyproject with a tiny hard-dependency set (click + rich + one provider SDK + tomllib/platformdirs), ONE console script, and ruff+mypy+pytest configured in the same file; an AGENTS.md/CLAUDE.md with the git discipline, glossary, and 'adding a tool' recipe from day one; a README with a positioning paragraph and a tool table.
- Replicate the offline-first test design early: a scripted mock provider (echo/static) registered like a real provider, a MODEL=local/test + unreachable-base-url fallback when no API key, and a requires_api marker with collection-time skip. This is what makes the agent loop testable in CI for free.
- Copy the conftest patterns selectively: start with restore_cwd, clear-tools/init reset, and a shell-session closer; add thread-leak detection only once you have background threads (you will).
- Adopt the Makefile trio (make test / typecheck / lint) and 2-3 pytest markers (slow, requires_api) rather than the full 10-marker vocabulary; add markers when a real lane needs one.
- Adopt the CI lane split as soon as you have CI: a no-API lane (fast, every PR) and an API lane behind a paths-filter; skip the minimal-install and Windows lanes until you have users.
- Ship one distribution channel first: PyPI via pipx/uv with an 'all' extra. Docker (single selfhost image + compose file with named volumes for config/data) is the second. Defer Tauri/PyInstaller, mobile configs, and the 7-Dockerfile matrix until the core is stable.
- Defer entirely for an MVP: eval harnesses (swebench/terminal-bench/dspy), OpenTelemetry extras, the Sphinx site + Next.js landing + CNAME assembly, scheduled dev releases with generated changelogs, plugin registry ecosystem, sounds, and the GitHub bot.
- For the version string, copy the simple parts: static version in pyproject plus importlib.metadata fallback; only add git-direct_url handling when you care about editable-install provenance.
- Release cadence worth stealing late: tag-driven releases where the changelog is generated from the tag range and CI refuses to release on non-green HEAD.

## Open Questions
