# project-meta

## 目的(Purpose)
gptme 的元数据、测试与分发层:一个用 Poetry 打包的 Python 项目(v0.34.0),把一个终端 AI agent 以多种形态发布——以 26 个控制台入口点(console entry-points)发布到 PyPI,以 7 个 Docker 镜像发布(包括一个自托管服务器和一个 VNC computer-use 沙箱),以及一个捆绑了 PyInstaller 冻结的 gptme-server sidecar 的 Tauri 桌面应用。该层定义了:依赖(极小的硬核依赖 + 16 个可选依赖分组(extras))、一个 401 个文件的 pytest 测试套件——配套围绕离线 mock provider 与重度 teardown 卫生(teardown hygiene)建立的三车道 CI 策略(no-API、最小安装、真实 API 矩阵)、一套 Makefile 驱动的开发工作流(test/lint/typecheck/docs/site/release)、带强制逐页受众(audience)元数据的 Sphinx 文档、为 gptme.org 组装的静态站点,以及面向在本仓库上工作的 AI 编码代理的 AGENTS.md 约定。

## 关键抽象(Key Abstractions)
- **控制台入口点扇出(Console entry-point fan-out,[project.scripts])** — 一个 Python 包暴露 26 个 CLI(pyproject.toml:36-62),每个映射 name -> module:main(例如 gptme = gptme.cli.main:main、gptme-server = gptme.server.cli:main)。子能力(server、eval、agent、doctor、auth、mcp-server)各有自己的二进制,用户可以只用 pipx 安装所需,systemd/docker 也能调用窄接口。
- **基于 extras 的依赖格(extras-based dependency lattice,[tool.poetry.extras])** — 硬依赖保持极小(CLI + 2 个 provider SDK + 配置/解析);一切重量级皆可选:server(flask+pydantic)、browser(playwright)、tui(textual)、acp、telemetry(9 个 opentelemetry 包)、eval(dspy/swebench/terminal-bench)、datascience、sandbox(wasmtime)、minimal(空——面向 ARM/musl/Termux)、all。这让 `pipx install gptme` 保持轻量,而 `poetry install -E all` 为 CI 供能。
- **插件入口点组(Plugin entry-point group,gptme.plugins)** — pyproject.toml:32-34 在命名空间化的入口点组 'gptme.plugins' 下注册 gptme.hooks.auto_snapshots:plugin 与 aw_watcher_agent:plugin,因此连第一方 hook 也经由第三方插件所用的同一发现机制加载。
- **离线模型策略:local/test + mock/* provider** — 两层 LLM 替身。(1)`local/` provider = 任意 OpenAI 兼容 base URL;conftest 设置 MODEL=local/test 与 OPENAI_BASE_URL=http://localhost:666(选端口 666 正因其永不应答),使完整 init 路径照常运行,而意外的网络调用立刻失败。(2)一个真实的进程内 provider `mock`,带脚本化模型 mock/echo 与 mock/static(gptme/llm/llm_mock.py:33-79),注册在正常 provider 表中,零成本、确定性地演练 reply/stream/分发器管道。
- **requires_api 标记 + 配额跳过机制(quota-skip machinery)** — 标记在 pyproject(412 行)与 conftest(154-158)中声明。收集期:若无 API key,所有 requires_api 测试被打上跳过标记(conftest.py:254-269);会话开始的探测发起一次 1-token 的 claude-haiku 调用,检测配额耗尽/key 无效(104-142);运行期:pytest_runtest_makereport 把错误匹配 _QUOTA_ERROR_PATTERNS 的失败 requires_api 测试改写为跳过(188-215)。CI 仅在 API 相关路径变更时以廉价模型矩阵运行该车道(test.yml:259-335)。
- **带来源标记的脚本化序列回复 mock(Scripted-sequence reply mocking with origin tagging)** — 循环测试用一个闭包替换 gptme.chat.reply(或 _process_message_conversation),闭包内是 `iter([exception, Message(...)])`,对每个元素或抛出或返回(test_chat.py:1237-1245);provider 错误是真实的 httpx/openai 异常实例,经 mark_llm_reply_origin(err, output_emitted=..., visible_output_emitted=...) 打标,使循环的 is_provider_error() 与"压缩后重试一次"逻辑面对真实异常类型得到测试(1231-1236、1418)。
- **sys.modules 模块句柄技巧(sys.modules module-handle trick)** — 由于 gptme/__init__.py 里 `from .chat import chat`,patch("gptme.chat.X") 解析到的是包属性(那个函数)从而失效;测试改用 `_chat_mod = sys.modules["gptme.chat"]`,再对真正的模块做 patch.object(test_chat.py:539-547)。坑已写成行内注释,留给所有要写循环测试的人。
- **Autouse teardown 卫生 fixture 栈(Autouse teardown-hygiene fixture stack)** — conftest 定义约 10 个 autouse fixture,构成一条防御性清理链:restore_cwd、detect_leaked_threads(快照/对比 + 排序的终端摘要 + 严格模式环境变量)、clear_tools_before(重置工具注册表、_init_done、chat 配置)、cleanup_shell_after(ContextVar shell + 工作区 cwd)、cleanup_acp_health_monitor、cleanup_subagents_after(打断重试退避休眠、join 线程上限 5 秒、终止子进程、try/finally 中复位信号量)、cleanup_logged_warnings、_clear_proactive_summarize_cache。顺序注释解释哪个 fixture 必须最后 teardown。
- **线程泄漏检测(Thread-leak detection)** — tests/thread_leak.py 的辅助函数(snapshot_threads/diff_threads/format_leaks/is_dict_iteration_race)接入一个 autouse fixture(conftest.py:344-390),加上 pytest_exception_interact 在字典遍历竞态触发时转储全部存活线程栈(166-185)。默认只报告;GPTME_STRICT_THREAD_LEAKS=1 则让肇事测试失败——对一个从约 27 处启动线程的 agent,这是钉住泄漏者的流程。
- **线程内真实服务器 fixture(In-thread real-server fixtures)** — server_thread(conftest.py:663-705)构建真实的 Flask create_app(),monkeypatch 一个已知的 GPTME_SERVER_TOKEN,把 socket 绑到端口 0 由 OS 分配空闲端口,并在守护线程中运行 app.run;setup_conversation/event_listener 随后演练真实 HTTP PUT + SSE 流。互补的 `client` fixture 用 app.test_client() 配 GPTME_DISABLE_AUTH,承担大部分端点测试。
- **惰性、感知 frozen 的 __version__(Lazy, frozen-aware __version__)** — gptme/__version__.py 在首次属性访问时经模块 __getattr__ 计算版本,带缓存与永不抛异常的护栏;区分 wheel 安装(importlib.metadata)、pip-from-git(direct_url.json 的 commit)、可编辑安装(git describe + dirty 后缀)与 PyInstaller frozen(完全不碰 git)。
- **标记词表即测试策略(Marker vocabulary as test policy)** — pyproject [tool.pytest.ini_options] 的 markers(407-418):slow、eval、serial、timeout、requires_api、flaky、no_retry、integration、x11、xdist_group。配合 Makefile 开关(`make test` 默认排除 slow+eval,SLOW=1 时以 --timeout 60 --retries 2 加入),这就是各 CI 车道与本地运行挑选切片的 API。
- **定时自动发布流水线(Scheduled auto-release pipeline)** — release.yml 的 cron(周一/周四)在确认 CI 全绿后创建 .devYYYYMMDD 预发布;版本号提升 + 生成 changelog + amend 的 tag 经由与手动 `make release-*` 共享的脚本完成;PyPI 发布作为唯一非幂等步骤排在最后;下游 build.yml/tauri.yml 的触发带注册验证。
- **文档受众契约(Docs audience contract)** — docs/conf.py 的 check_audience:任何页面未声明 :audience: user|power-user|developer 就让 Sphinx 构建失败(84-126);AGENTS.md 要求贡献者把内容保持在所声明的层级。这是抵御文档漂移的结构性守卫。

## 设计亮点(Design Highlights)
- 两层离线 LLM 策略:一个不可达的 local/test 端点(意外联网时快速失败),加一个一等公民的 mock provider,其脚本化的 echo/static 模型注册在真实 provider 表中——agent 循环、流式与分发全部无需任何 mock 库即可确定性测试。
- requires_api 作为一等契约,配三个执行点(收集期跳过、会话开始配额探测、makereport 失败->跳过改写),让不稳定的付费 API 永远不会把 CI 染红;同时 paths-filter + 廉价模型矩阵 + OpenRouter 路由 + GPTME_MAX_TOKENS 上限把 API 开销框在预算内(动机处提到约 $30/天)。
- conftest 被当作生产代码来对待 teardown 卫生:cwd 恢复、带严格模式环境变量以钉住泄漏者的线程泄漏快照/对比、ContextVar 复位、带上限的子 agent 先打断后 join,还有一个 vendored 的 retry_compat 插件,使 pytest-retry 规避方案本身也有回归测试(tests/retry_compat.py 经 -p 加载)。
- 入口点扇出(26 个脚本)把一个包变成一组窄面二进制的工具箱——对 systemd unit、docker ENTRYPOINT、编辑器集成(gptme-acp、gptme-mcp-server)和最小权限自动化必不可少。
- extras 格阵里有一个显式为空的 'minimal' extra 面向受限平台,且有 CI 车道在最老的支持版 Python 上验证无 extras 安装——普通用户会撞上的打包回归是被抓住的,不是被想当然的。
- webui 经显式 Poetry include 打进 wheel,并配 validate-release-package make 目标与 CI 检查,因为生成且被 gitignore 的资产否则会从发布产物中被悄悄丢掉(pyproject.toml:71-73 的注释)。
- 惰性 __version__ 区分 wheel/git/editable/frozen 安装且永不抛异常,因为服务器会在 API 元数据里暴露它。
- 发布工程即代码:定时 dev 预发布、从 tag 区间生成 changelog 并提交进 bump 提交、PyPI 作为唯一非幂等步骤排在最后,以及因 gh workflow run 即发即忘而设的触发验证轮询(release.yml:357-403)。
- AGENTS.md 给项目自己的 AI 代理立下 git 纪律(永不 push master、Conventional Commits、永不 git add .)、core 与 contrib 的边界规则("拿不准就先放 contrib")、六词术语表(Tool/ToolUse/Message/LogManager/Step/Turn)与记忆协议(开始时 recall、持久经验用 save)——外加"加一个工具只需 3 步,因为发现是自动的"这类配方。
- 文档质量由构建强制:每页必须声明 :audience:,否则 Sphinx env-check-consistency hook 让构建失败;`make docs-structure` 打印渲染后的侧边栏供审阅。
- "我们够小吗(are we tiny)"作为被跟踪的指标:cloc/radon/jscpd 的 make 目标、启动时间 hyperfine 基准、CI 基准阈值——体积与启动被当作功能对待(AGENTS.md:66-70)。
- Makefile 是人类、CI 与 AGENTS.md 共享的唯一开发词汇表(make test / test SLOW=1 / typecheck / lint),以开关(EVAL、SLOW、PROFILE、TYPE)取代重复的旗标汤。

## MVP 指南(MVP Guidance)
- 优先复刻(便宜、杠杆高):一个扁平的 pyproject,硬依赖极小(click + rich + 一个 provider SDK + tomllib/platformdirs)、只有一个控制台脚本,ruff+mypy+pytest 配在同一文件;第一天就带上含 git 纪律、术语表与"加一个工具"配方的 AGENTS.md/CLAUDE.md;一个带定位段落与工具表格的 README。
- 尽早复刻离线优先的测试设计:一个像真实 provider 一样注册的脚本化 mock provider(echo/static)、无 API key 时 MODEL=local/test + 不可达 base URL 的兜底、以及带收集期跳过的 requires_api 标记。正是这些让 agent 循环在 CI 里免费可测。
- 有选择地照搬 conftest 模式:先从 restore_cwd、clear-tools/init 重置和 shell 会话关闭器开始;等真有后台线程了再加线程泄漏检测(你迟早会有)。
- 采用 Makefile 三件套(make test / typecheck / lint)与 2-3 个 pytest 标记(slow、requires_api),而非完整的 10 标记词表;哪条真实车道需要了再加标记。
- 一有 CI 就采用车道拆分:no-API 车道(快、每个 PR)加 paths-filter 门后的 API 车道;minimal-install 与 Windows 车道等有用户再说。
- 先只发一个分发渠道:经 pipx/uv 的 PyPI,带一个 'all' extra。Docker(单个 selfhost 镜像 + 带配置/数据命名卷的 compose 文件)是第二个。Tauri/PyInstaller、移动端配置与 7 个 Dockerfile 矩阵推迟到核心稳定之后。
- MVP 阶段完全推迟:评测 harness(swebench/terminal-bench/dspy)、OpenTelemetry extras、Sphinx 站点 + Next.js 落地页 + CNAME 组装、带生成 changelog 的定时 dev 发布、插件注册表生态、音效与 GitHub bot。
- 版本字符串只抄简单部分:pyproject 里的静态版本加 importlib.metadata 兜底;只有在意可编辑安装的出处时才加 git-direct_url 处理。
- 发布节奏值得后期再学:tag 驱动发布,changelog 从 tag 区间生成,CI 拒绝在非绿的 HEAD 上发布。

## 开放问题(Open Questions)
- 对 2026 年的全新重实现,选 Poetry(poetry-core 后端 + poetry.lock)还是更现代的 uv/hatch——gptme 的动态依赖 + extras 用任一后端都能干净映射到 PEP 621,但基于 lockfile 的 CI 缓存(test.yml 里的 .cache-id 技巧)是 Poetry 特有的。
- 配额跳过机制(会话开始的 haiku 探测 + makereport 改写)有多少值得复刻,还是干脆用一个手动开关把 API 测试挡在后面——它存在是因为他们在每个相关 PR 上跑付费 API 测试,学习者未必如此。
- `local/` provider 的 localhost:666 约定依赖该端口永不应答;对学习者更简单的循环,单靠一个 mock provider(mock/echo)能否完全替代它,还是 OpenAI 兼容端点这条路也需要测试。
- vendored 的 scripts/build_changelog.py 区间语义的准确契约(dev 与 stable 各自的前一 tag 选择,Makefile:223-234)——此处仅略读;只有在复刻其发布自动化时才需要。
- 每个子命令一个入口点的扇出(26 个二进制)对小项目是否值得付出命名面成本,还是单个二进制加子命令(gptme server/eval/doctor)就够——gptme 自己也在 `gptme` 下嵌套子命令(README:534-536),两种方式并存。
- tauri.android.conf.json / tauri.ios.conf.json 确实存在,但移动构建车道的实际成熟度未经验证(README 声称可下载 Android 桌面应用)。
