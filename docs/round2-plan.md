# 第二轮路线图:从"功能完成"到"日常可用"

> 第一轮(阶段 0-8):照着 gptme 把骨架搭完,验收标准是"功能实现、测试全绿"。
> 第二轮:让它真的能干活,验收标准换成"**独立完成三个真实任务**"。
> 日期:2026-10-05 定稿;执行方式与第一轮相同:每轮开发 + 测试全绿 + 中文开发记录 + 提交。

## 背景:为什么第一轮结束时"感觉做不了什么事"

1. **模型适配差**:kimi-k3 光说不做、思考泄漏,单步成功率低,多步指数衰减;
2. **没有编辑工具**:agent 只会整文件重写(save),改代码必丢内容;
3. **没有任务推进机制**:多步任务做到一半没人推,模型一句"完成"就溜了;
4. **没干过真事**:验收从没以"完成真实任务"为目标过。

## 各任务要点

### R1 edit 工具(对照 gptme 的 patch / Claude Code 的 Edit)
- 用法:`​```edit path/to/file` + 旧文本 + 分隔行 + 新文本;
- 匹配规则:旧文本必须在文件中**恰好出现一次**;多处出现报错(要求带更多上下文);
- 找不到 → 报错并打印最接近的行号区间(配合 read 的行号输出);
- 写回走确认链(非只读工具);原子写(先写临时文件再替换)。

### R2 todo 工具 + 完成门控(对照 gptme tools/todo.py,研究报告 §7)
- 状态存内存 + 会话恢复时从日志回放(todo write 是普通消息,回放即恢复);
- 门控:回合无工具调用且有未完成 todo 时,自动注入"你还有未完成事项"的
  user 消息逼它继续;连续 2 次仍无工具调用 → 熔断结束(防死循环);
- 用 LOOP_CONTINUE hook 实现,不改核心循环。

### R3 grep 工具
- 包装系统 rg/grep,固定输出格式:相对路径:行号:内容;
- 参数:正则 + 可选 glob + 可选目录;无命中时明确说"没有匹配"。

### R4 会话自动命名
- 时机:第一个回合结束时(第一轮用户输入 + 模型回复已存在);
- 方式:用便宜模型(或当前模型)对首轮对话生成 ≤20 字标题,写入会话目录名旁的 meta;
- /log 与会话列表显示标题。

### R5 模型适配收尾
- 实测 glm-5.3 / deepseek-chat / kimi-k3 三家的围栏服从率,固化默认配置建议;
- ALPHA_TOOL_FORMAT 默认值评估(kimi 走原生通道);
- 行动纪律提示词效果记录进 devlog。

### R6-R8 真实任务考试(第二轮的期末)
- 每个任务:独立完成 = 无人工干预(确认链的 y 除外);
- 过程全程记录:失败在哪一步、为什么、需要修什么 —— 这份清单就是下一轮的输入;
- 考试通过 = 第二轮毕业。

## 纪律(延续第一轮)

- 每轮:开发 → 测试全绿 → ruff/mypy 干净 → 中文开发记录(devlog 续编号 013 起)→ 显式文件列表提交,用户推送;
- 注释规范照旧(每函数简注、示例、禁黑话;用户学习注释保留);
- 信息量控制:每轮结束的汇报宁短勿长。
