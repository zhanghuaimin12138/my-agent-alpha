# 037 · chat.py 主链路拆分(2026-10-30)

## 目标

chat.py 从 712 行瘦身到 319 行,只留主链路四个函数:
`chat` / `_run_chat_loop` / `_process_message_conversation` / `step`。
其余附属功能全部搬去"各自的主业模块",逻辑一行不改,纯搬家。

## 决策及理由

**为什么拆**:chat.py 是整个程序的"地图"——新人(和三个月后的自己)
打开它应该一眼看懂三层循环。但补发提醒、流式打印、确认链、会话切换
等功能逐版往里塞,主链路被淹没在附属代码里,成了屎山苗头。

**搬去哪、为什么**(每件东西去它概念上的家):

| 原函数/类 | 去向 | 理由 |
|---|---|---|
| `_StreamPrinter`、`_print_message`、`_get_user_input`、`_replay` | 新包 `tui/`(stream.py + io.py) | 终端显示和循环无关;拆两个文件是因为流式渲染(小状态机)和逐条打印/读输入不是一类事;留包结构,将来接 Web 前端只动这里 |
| `missed_tooluse_reason`、`_make_nudge`、`NUDGE_PREFIX`、`MAX_TOOL_NUDGES` 等 | 新模块 `nudge.py` | 一个完整独立的功能(检测+提醒),内聚成一个文件 |
| `_preview`、`cli_confirm_hook`、`_setup_confirm_hooks` | `confirm.py` | "确认"概念全家一个文件;装配函数改名 `setup_confirm_chain` |
| `prepare_messages` | `compaction.py` | 压缩本来就是它的主业,视图组装放一起 |
| `has_runnable_tooluse` | `tools/base.py` | 靠 ToolUse 解析判定;还顺手复用了现成的 `tooluses_in_messages`(原来 chat 里手写了一遍同样的倒序找回复) |
| `_dispatch_hooks` | `hooks/__init__.py`(改名 `dispatch_hooks`) | 它是钩子和日志的接合点,跟钩子系统放一起,契约两边对得上 |
| `_switch_session` | `logmanager/sessions.py`(改名 `switch_session`) | 会话的事归会话模块 |
| chat() 里的 MCP 接入块 | `mcp_client.connect_mcp_tools()` | chat() 只剩流程编排 |
| chat() 里的开场消息块(提示词+记忆索引) | `prompts.session_opening_messages()` | 同上 |

**循环导入的两处处理**(动手前逐条验证过依赖方向):

1. `shell_safety` 引用 `confirm`(钩子要返回 ConfirmationResult),
   所以 `setup_confirm_chain` 里的护栏/只读钩子用**函数内延迟导入**;
2. `hooks/__init__` 和 `tui/io.py` 对 LogManager 只做
   `TYPE_CHECKING` 导入,运行时不依赖,logmanager ↔ hooks/tui 不成环。

**兼容点(刻意不动)**:测试的打桩点 `chat_mod.reply`、`chat_mod.MAX_STEPS`
名字位置不变(step/中层还在 chat.py,继续引用它们)。

```

+ tui/             __init__(导出 4 名) + stream.py(StreamPrinter) + io.py(读/打/回放)
```

搬家时去下划线前缀(模块间调用了就是公开的);`_blank_fences`、
`_resembles_known_tool` 只被 nudge 内部用,保持私有。

## 两处微小行为差异(如实记录)

1. 记忆索引那条消息原来 `append(sync=False)`,现在随开场消息统一
   `sync=True` —— 只多一次强制刷盘,落盘时机更早,无语义差别;
2. `has_runnable_tooluse` 从"手写倒序找回复"改为调用
   `tooluses_in_messages`(同一逻辑),行为等价。
