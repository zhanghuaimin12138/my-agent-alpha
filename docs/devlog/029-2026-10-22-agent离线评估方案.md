# 029 · agent 离线评估方案(纯文档)

## 目标

基于项目现状,给出一份可落地的离线评估可行性方案:不引入框架、不加依赖,
回答"评什么、拿什么评、怎么判分、分几步做、花多少钱"。

## 决策及理由

1. **两层评估,不混**:A 层 mock 驱动评"骨架代码正确性"(已有 tests/ 即是,
   继续维护);B 层真模型驱动评"端到端能力"(本方案新建)。
   理由:B 层失败时需要先排除代码层问题,两层分开才能定位。
2. **自研,不接 LangSmith/AgentEvals**:零新依赖、jsonl 格式天然配套、
   学习项目自研本身就是目的之一。
3. **任务集用 Python dataclass 定义而非 YAML**:不引 pyyaml;类型检查能兜笔误;
   中文 prompt 不用转义。
4. **判分两级制**:确定性断言(文件状态/回复内容/步数上限/禁用工具)优先,
   LLM 裁判只用于开放式任务(E3)且需人工校准。
5. **失败二分**:任务失败与基础设施失败(限流/超时)分开统计,不互相污染。
6. **唯一核心文件改动**:E3 计划加 `ALPHA_CONTEXT_BUDGET` 环境变量
   (照 `ALPHA_MAX_STEPS` 先例),其余全部外围实现。
