# 024 — M3:写路径补全(scope 层级、覆盖提示、删除)

## 目标

实施《长期记忆改进方案》M3:解除 memory 工具"永远写项目层"的硬编码、
让覆盖更新对模型可见、补上删除被证伪记忆的通道。

## 决策及理由

1. **层级判定放在 save_memory 内部,优先级三级**:
   显式 project_level > 内容 frontmatter 的 scope > 按类型推断
   (user/feedback → 用户层,project/reference → 项目层)。
   理由:类型解析本来就在 save_memory 里(参数 > frontmatter > 默认),
   推断要用解析后的最终类型,放在工具层会复制一遍解析逻辑;
   markdown 通道没有参数位,frontmatter 带 scope: 让两条通道对称(沿用 M1 的做法)。
2. **save_memory 的 project_level 从 bool 改为 bool | None**:None = 交给推断。
   语义变化:裸调用(不传类型也不传层级)从"用户层"变为"项目层"——
   与工具协议的默认(project)对齐,测试全走显式参数不受影响。
3. **覆盖提示在工具层做,不在 store 层**:save_memory 返回值契约不变(返回 Path),
   工具先 find_memory 拍下旧标题快照、保存后比对路径——同路径 = 覆盖(提示旧标题),
   不同层 = 盖住(提示旧路径)。让模型看见"已有近似条目",它才能判断合并还是替换。
4. **删除做成 action=delete 而不是新工具**:与 save 共用确认链(read_only=False
   天然过审)、共用 name 参数;围栏形式 "```memory delete 名字"。
   delete_memory 删"看得见的那个"(近层)——近层盖远层,删除语义应与所见一致。
5. **删不存在的记忆给明确反馈不报错**:模型可能基于过期索引行动,
   "没有叫 X 的记忆"比异常栈更有用。

## 改动结构

- `src/my_agent_alpha/memory_store.py`:
  - `save_memory` 的 project_level 参数改 `bool | None` + 三级层级判定;
  - `_parse_frontmatter` 认识第五个键 `scope`(只在保存输入里出现,不落盘);
  - 新增 `find_memory`(按名查,slug 规则与落盘一致)和
    `delete_memory`(按名删近层 + 重建索引)。
- `src/my_agent_alpha/tools/memory.py`:
  - 删除分支(action=delete / 围栏头 delete);
  - 保存分支加 scope 参数 + 覆盖/盖住提示;
  - `_PROTOCOL` 补两段:记在哪层(user/feedback → 用户层)、更新与删除纪律;
  - 参数表加 action / scope,content 改非必填(delete 不需要)。
- `tests/test_phase8.py`:新增 5 个用例(类型推断、显式覆盖、工具 scope、
  覆盖提示、删除全家桶)。

## 已知限制

1. 围栏头 "delete" 是保留词——真有一条记忆名叫 "delete" 时只能走原生通道删;
2. 覆盖提示只报旧标题,不展示旧正文全文(消息体量考虑,模型可自己 read);
3. 删除只删近层,若两层同名想全删要删两次(先删近层,远层浮上来再删)——
   行为与"所见即所删"一致,但模型未必第一次就懂,协议里未展开。
