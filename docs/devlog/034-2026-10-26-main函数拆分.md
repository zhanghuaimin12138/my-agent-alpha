# 034 重构:main 函数拆分(嵌套函数,行为零变化)

- 日期:2026-10-26
- 性质:refactor(只动 `src/my_agent_alpha/__init__.py` 的 main 函数体,无行为变化)
- 背景:main 塞了参数定义、配置解析、会话目录、装配编排一大坨;用户要求拆开、优雅一点

## 一、目标

main 主干只留"流程编排",细节收进嵌套函数;命令行行为一字不变。

## 二、决策及理由

| 决策 | 理由 |
|---|---|
| 用**嵌套函数**而不是模块级函数 | 这些步骤只有 main 用,不配占公共命名空间;对外 API(包的 `__all__`)零变化,测试零改动 |
| 三个函数:`build_parser` / `load_settings` / `make_logdir` | 命名统一"动词_名词",跟着 build_parser 的风格走;一眼可读"建解析器→载配置→定会话目录" |
| **config / model / tool_format 收在同一个函数** | 它们是同一件事的三个结果:同一条优先级链(命令行 > 环境变量 > 配置文件)、同一批 `effective_*` 函数、同时解析同时使用——拆开反而做作。max_steps 同族,一并收进(副作用:改 chat 模块全局上限,注释写明) |
| `load_settings` 只返回 (model, tool_format),config 不外抛 | 主干用不到 config;它只是解析的中间产物 |
| 局部导入保持原样(收进各自函数) | 原有设计:`import my_agent_alpha` 保持轻量(mock 测试不加载真实 LLM 库),不因拆分而破坏 |
| `-` 读 stdin、工具白名单留在主干 | 各 5 行以内,再拆就是为拆而拆 |

## 三、改动结构

```
main(argv)
├── build_parser()      全部 argparse 定义(想知道支持哪些参数,只读它)
├── load_settings(args) Config.load + effective_model/tool_format/max_steps
├── make_logdir(args)   会话根/<会话名> 计算 + --name 写标题
└── 主干                prompts/-stdin、白名单、调 load_settings/make_logdir、chat()、Ctrl-C→130
```
