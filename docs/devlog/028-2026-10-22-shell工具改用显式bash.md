# 028 — shell 工具改用显式 bash

## 目标

修复 shell 工具"文档说 bash、实际跑 dash"的偏差:把命令的执行者从系统默认的
`/bin/sh` 换成明确指定的 bash。

## 问题背景与决策理由

改动前 [shell.py](../../src/my_agent_alpha/tools/shell.py) 用的是:

```python
subprocess.run(command, shell=True, ...)
```

`shell=True` 在 Linux 上的实际行为是启动 `/bin/sh -c "命令"`。而 `/bin/sh`
只是个软链接,指向谁因系统而异——在本机(Ubuntu/WSL)上验证指向 dash:

```
$ ls -l /bin/sh
/bin/sh -> dash
```

dash 只支持基础语法,不认 bash 的扩展写法(`[[ ]]`、数组、进程替换等)。
但工具描述和注释都告诉模型"这是 bash",模型按 bash 语法写命令就可能莫名失败。

**决策:显式写 `["bash", "-c", command]`,与 gptme 原实现一致**
(gptme 源码 `gptme/tools/shell.py:582` 就是 `["bash", "-c", command]`)。
bash 在 Ubuntu 上是 essential 包,必装,不用担心缺失。

## 改动结构

只改一处调用(`execute_shell` 内),其余逻辑(超时、截断、存盘)不动:

```python
# 显式点名 bash,而不是 shell=True:后者会走 /bin/sh,
# 而 Ubuntu 上 /bin/sh 其实是 dash,不认 [[ ]]、数组这些 bash 语法
proc = subprocess.run(
    ["bash", "-c", command],
    cwd=get_workspace(),
    ...
)
```

## 验证结果

- `uv run pytest`:318 passed
- `uv run ruff check .`:All checks passed
- `uv run mypy src`:no issues in 36 files
- 真机验证:通过工具实际执行 bash 独有语法
  `arr=(a b c); echo ${arr[1]}; [[ -f pyproject.toml ]] && echo 双括号OK`,
  输出 `b` 和 `双括号OK`,ReturnCode: 0(改前这种命令在 dash 下会报语法错误)
