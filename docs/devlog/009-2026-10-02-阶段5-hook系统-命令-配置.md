# 009 · 阶段 5:hook 系统、命令框架与分层配置

- **日期**:2026-10-02
- **阶段**:5 / 通用 hook 系统 + slash 命令 + 分层 TOML 配置
- **验收标准**:新功能挂钩子/加命令即可,不改核心循环 —— ✅ 达成(支柱三完全成型)

## 一、目标

让"加功能"不再动 chat.py:横切功能做成钩子、交互做成命令、偏好做成配置。

## 二、设计(全部仿 gptme,简化版)

### 1. 钩子系统(hooks/,支柱三的主体)

- 生命周期点 7 个:session.start / session.end / turn.pre / turn.post /
  step.pre / generation.post / loop.continue;
- 钩子 = 产出(yield)若干 Message 的函数;消息由循环统一落盘显示
  (于是自然进入模型上下文);纯打印钩子产出空即可;
- register_hook(同名替换)/ unregister_hook / trigger_hook;
  优先级大的先跑;**StopPropagation** 制止后续;钩子抛异常被隔离
  (记警告,继续跑别的 —— 一个坏钩子不许拖垮会话);
- 接线:_dispatch_hooks 统一"触发+落盘+显示";step() 内
  yield from trigger(GENERATION_POST)(消息排在模型回复后、工具输出前);
- **与确认链的分工**(同 gptme):钩子产出消息;确认链返回
  放行/拒绝/改写的**返回值** —— 契约不同,保持两个体系;
- 内置钩子两个:usage(generation.post,每次回复后记一条
  `[用量] 输入 X / 输出 Y tokens` 进日志 —— gptme 的"token 感知")、
  session_info(会话开始打印会话目录)。

### 2. 命令框架(commands/)

- @command(名字, *别名) 装饰器注册;CommandContext(args/full/manager/model);
- execute_cmd:是已注册命令 → 执行返回 True;否则 False(按普通对话处理);
  命令输入不进日志;
- 内置命令:/help /?、/exit /quit /q、/tools、/log、/model、/hooks(学习调试用)。

### 3. 分层配置(config.py)

- 用户层 ~/.config/my_agent_alpha/config.toml → 项目层 <工作区>/alpha.toml
  → 环境变量 ALPHA_* → 命令行参数(最高);
- 支持键:model / tool_format / max_steps;
- 坏 TOML 文件告警忽略,不许配置拖垮程序;
- dirs.get_config_dir()(XDG_CONFIG_HOME)。

## 五、过程中的坑与修

1. **批量补丁静默失败**:一次脚本里 6 个替换,其中 2 个因目标文本被
   ruff/用户注释改动而没命中,且 s.replace 不报错 —— 测试大多仍绿,
   差点带着"没接线"的 chat() 过关。教训:改完必须 grep 验证关键符号
   (GENERATION_POST/builtin)真的在文件里;
2. **chat() 清空钩子的设计错误**:最初 chat() 开头 clear_hooks(),
   把调用方在会话前注册的自定义钩子也抹了(测试当场抓住)。
   改为"只确保内置已注册(同名替换),不清别人的";清理职责归调用方
   (conftest 显式清);
3. **环境变量污染测试**:本机 .bashrc 的 ALPHA_MODEL 让优先级测试
   不自洽 —— 测试先 delenv 再测。

## 六、已知限制(按计划推迟)

- 钩子/命令注册表是模块级(单会话);多会话(server)时升级 ContextVar;
- 钩子无 per-hook 配置与启停开关(gptme 的 HOOK_ALLOWLIST);
- 配置无监听热更新(改文件要重启会话);无工具允许列表键(阶段 8 前按需);
- loop.continue 目前只产出消息,未实现"队列接力提示词"语义(gptme 用于
  自动回复/subagent 完成通知,等阶段 8 需要时扩展)。
