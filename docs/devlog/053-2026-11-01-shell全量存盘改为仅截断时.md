# 053 · shell 全量存盘改为只在截断发生时做

## 目标

用户审查 `tools/shell.py` 时提出质疑:每次 shell 调用都无条件把完整输出
写进 `tool-outputs/shell/*.txt`,但指向这个文件的提示行只在输出被截断时
才进入消息 —— 那没截断时写的文件是给谁看的?要求评估后修正。

## 评估结论(为什么无条件写不合理)

逐个排查"谁可能消费未截断时的存档文件":

1. **模型**:知道文件的唯一渠道是消息里那行"完整输出: <路径>"提示,
   而提示只在截断时附加。未截断的文件路径从不进上下文,模型不知道它存在;
2. **人(事后翻会话目录)**:未截断时,消息内容与文件内容一字不差,
   而消息本来就永久躺在主日志 `conversation.jsonl` 里(主日志永不销毁),
   文件是零信息增量的纯复制;
3. **压缩层**:核对 `compaction.py` 后确认,压缩在截断工具结果前会**自己**
   把完整内容存到 `tool-outputs/compacted/` 再截(先存盘再截断)。
   "短到躲过 shell 截断、但大到撞上压缩阈值"的中间地带输出已被独立兜住,
   不依赖 shell 的存档。

三条路都走不通 → 存档的唯一正当目的是**截断发生时给模型留恢复路径**
(消息里那份被砍了,文件里有全文)。这正是蓝图里 gptme 的"先存盘再截断"
(saves-then-prunes)原则:存盘是截断的前置动作,不是独立动作。原实现把
"全量存盘"做成了无条件,比原则多走一步,还附送两个代价:每条 `ls`、
每个 `(无输出)` 都落一个文件,长会话目录全是噪音;`tool-outputs/shell/`
本该有的含义("日志装不下的输出")被稀释成"每次调用"。

## 决策及理由

- **存盘与截断绑定**:先算截断版 `shown`,只有 `shown != output`(真的砍了)
  才调 `_save_full_output`。对模型的可见行为零变化(提示行本来就是条件拼的),
  微秒+pid 防覆盖文件名、超时分支、"没有会话目录返回 None"分支全部原样。
- **不动的部分**:截断算法本身(砍中间留两头)不动;压缩层的独立存档不动
  (它有自己的目录和按内容哈希去重,职责清晰)。

## 改动结构

- `src/my_agent_alpha/tools/shell.py`:
  - 模块 docstring:"输出截断 + 全量存盘"改为"输出截断(截断发生才把
    全量存盘,给模型留恢复路径)";
  - `_save_full_output` docstring 补"只在截断时才调用,没截断不存"及理由;
  - `execute_shell` 收尾:先 `shown = _truncate(...)`,`full_path` 改为
    条件调用,删掉原来的独立 `truncated` 变量,note 只看 `full_path`。
- `tests/test_review_fixes.py`:
  - `test_shell_full_output_files_never_collide`:原来靠 `echo x`(不截断)
    验证三个文件不互相覆盖 —— 行为改了它就失效。改为压低
    `_MAX_OUTPUT_CHARS=200` + `seq 1 500`,逼三次调用都走"截断+存盘"路径;
  - 新增 `test_shell_short_output_not_archived`:短输出执行后
    `tool-outputs/shell/` 目录根本不存在(未截断不落盘的回归)。
