# 030 · 上下文压缩重构(M0–M6):gptme autocompact 移植 · 压缩核心

- **日期**:2026-10-22
- **阶段**:压缩重构 · 前半(压缩功能);后半(视图分支 + 双写 + 接线)见下一篇
- **依据**:[autocompact-dev.md](../autocompact-dev.md)(所有接口、算法、阈值以该文档为唯一标准)

## 目标

把 gptme 的 autocompact 机制移植过来,替换现有的"每次请求现算"压缩
(compaction.py)。本篇交付开发任务分解里的 **M0–M6**(契约骨架、纯函数、
决策层、三阶段引擎、兜底压缩器、Provider 层、LLM 摘要);
**M7(触发器 + ViewBranchStore 双写 + 对话循环接线)在下一篇交付**。

## 开发前确认(文档 §11 的八个问题,全部从代码现状落实)

| # | 问题 | 结论(依据) |
|---|---|---|
| 1 | 语言/框架 | Python 3.12+、同步(pyproject `requires-python >=3.12`) |
| 2 | 消息模型 | 复用现有 `Message`(frozen、自带 pinned);工具输出 = role="system"(和 gptme 同款)。集中定义 `is_tool_result()` = `role=="system" and not hide` —— 多排除一层 hide,防止系统提示词/记忆索引这类"说明书"被当成工具输出截断 |
| 3 | tokenizer | 不引入 tiktoken,用项目现成的字符启发式估算(ascii 4 字符/token、中文 1.5 字符/token);确定性,满足"同一输入稳定同一值"的契约 |
| 4 | 主力模型 | glm/glm-5.3(config 默认);兜底 `FALLBACK_MODEL_INFO = ModelInfo("glm-5.3", 128_000)`(与 ModelMeta 默认窗口一致) |
| 5 | LLM 客户端 | `ReplyLLMClient` 包装现有 `llm.reply`(非流式、无工具);测试用 Fake |
| 6 | 落地策略 | ✅ 视图分支 + 双写(文档已确认)→ M7 实现 |
| 7 | entry-points 插件 | 砍掉,仅编程式注册(`register_provider`) |
| 8 | 环境变量前缀 | `ALPHA_AUTOCOMPACT_KEEP_HEAD`(沿用项目 ALPHA_ 前缀,M7 用上) |

## 决策及理由

1. **新代码放独立包 `src/my_agent_alpha/autocompact/`**,不动老 `compaction.py`
   —— 老模块还在被 chat.py 用,等 M7 接线完成后再退役,避免半成品状态。
2. **文档歧义的处理**(gptme 源码副本 /tmp/gptme 已不在磁盘,以文档为准;
   有冲突时按"边界条件表 + 不变量清单 > 伪代码字面"):
   - 伪代码的 needs_p1/needs_p3 存在性检查没写 ¬pinned,但边界表说"全部
     pinned → needs_* 全 False → 早退"→ 存在性检查镜像各阶段循环的过滤
     条件(pinned / keep_head / 年龄 / 角色 / 工具调用);
   - 长度打分三行(−1.0 / +0.3 / −0.2)按表格字面实现为三个独立 if
     (极短句净得 −0.7,不是 elif 链);
   - P3 的"压完反而更大则跳过"与不变量 6"引用文本引入也算不降"都满足:
     先查压缩结果、再附字节引用、附完再查一次,两次都小于原文才替换;
   - 切句后过滤空白段(文档未提,re.split 尾部会产生空串)。
3. **estimate_tokens 在 adapters.py 放了一份副本**而不是 import 老模块:
   新包只依赖 message + 标准库,老 compaction.py 退役删除时不牵连。
4. **DefaultContextProvider 的适配器可注入**(counter/models/tool_use),
   默认实现延迟导入 —— 不用压缩就不拖起模型客户端/工具表的依赖链。
5. **注册表加了 `reset_registry()`**:模块级全局状态,测试之间必须能重置
   (和 hooks.clear_hooks 同一个角色,非文档规格、纯测试卫生)。
6. **resume 失败不抛异常**:返回一条带 `[resume-failed]` 前缀的 system
   消息(对应文档边界 8"返回错误提示消息,不破坏原日志"),
   触发器(下篇)看到前缀就不落地。

## 已知限制(留给 M7 及以后)

- **summarize 视图会打破"视图与 master 等长"不变量**(LLM 摘要重建的日志
  长度 ≠ 原日志):之后再次规则压缩时字节引用会失准。M7 的 ViewBranchStore
  需要给视图记一个"是否索引对齐"的标志,不对齐的视图压缩时不附字节引用。
- 触发器、60s 节流、`ALPHA_AUTOCOMPACT_KEEP_HEAD` 环境变量、`/compact`
  手动命令:全部属于 M7。
- entry-points 插件发现:按确认结论砍掉。
