# 042 —— 压缩视图 V1:单 View 存储骨架

## 目标

按 [docs/plan/my-agent-alpha-view-development-plan.md](../plan/my-agent-alpha-view-development-plan.md)
§8 V1 落地"压缩视图"的存储层骨架:一个会话 = 完整 Master 日志 + 最多一个激活的
压缩 View,View 能创建、能激活、重启能恢复;Master 一个字节都不动。
本阶段不引入双写与崩溃修复(那是 V2),也不接压缩算法(那是 V4)。

## 决策及理由

- **views.py 单独成文件,不塞进 manager.py**:视图编号生成、active.json 读写校验
  是一组独立概念(方案 §7),单独放方便测试;manager.py 只保留"编排"职责
  (什么时候创建、什么时候激活)。
- **views.py 不导入 manager(单向依赖)**:两个模块都需要"目录 fsync"这个 6 行小工具,
  若 views 反向导入 manager 会形成循环导入。选择在 views.py 里再放一份
  `_fsync_directory` 并注明来历 —— 重复 6 行比循环导入干净。
- **active.json 里同时存两个计数(master/view_committed_count)**,而不是像 gptme
  只存视图名(方案 §4.1):Master 和 View 是两个文件,双写没有跨文件原子性,
  崩溃可能停在"一边写完另一边没写"的中间;这两个计数就是 V2 恢复时裁齐的依据。
  V1 先把格式定下来并写入,避免 V2 再改文件格式。
- **read_active_state 对一切可疑输入(损坏 JSON/未知版本/非法视图名/坏计数)
  统一"告警 + 返回 None"**:调用方回退 Master 即可,不用为每种坏法写分支。
  非法视图名特别重要 —— ID 会被拼进文件路径,放行 `../` 就能越出 views/ 目录。
- **create_compacted_view 的顺序**:Master 先落盘 → 写新 View 文件 → 写 active.json
  → 最后内存激活(方案 §4.3)。任何一步失败,读取来源都不变(旧 View 或 Master),
  最坏多一个没被激活的孤立快照文件,无害。
- **V1 的已知限制(有意留给 V2)**:激活 View 后 `append()` 仍只写 Master,
  View 会停在创建时刻。所以 V1 验收不含"追加后两边一致"的用例;V2 做双写后补。
- **View ID 定长 3 位起步(`compacted-\d{3,}`)**:超过 999 自然变 4 位仍合法;
  编号靠扫描现有文件取最大 +1(不维护计数状态),手动删文件也不会撞号。
- 不新增 Message 字段、不动 Log 类、不建 branches/ —— 方案 §0/§3 的纪律。

## 改动结构

- `src/my_agent_alpha/logmanager/views.py`(新增):
  `ViewState` 冻结 dataclass(视图名 + 双写计数);`views_dir`/`view_path`/
  `is_valid_view_id`/`next_view_id`;`read_active_state`(校验一切,坏了返回 None)、
  `write_active_state`(临时文件 → fsync → os.replace → 目录 fsync)、
  `remove_active_state`。
- `src/my_agent_alpha/logmanager/manager.py`:只改 `LogManager`(`Log` 一行未动):
  - `_log` → `_master_log`,新增 `_active_view_log`/`_active_view_id`;
  - 读取口分层:`master_log`/`master_messages`(完整历史)与
    `log`/`messages`/`len`/`iter`(当前有效历史,有视图读视图);
  - `create_compacted_view(messages) -> str`:校验非空 → 按安全顺序落盘激活;
  - `switch_to_master()`:只删 active.json 指针,视图文件保留;
  - `load()` 末尾调 `_restore_active_view()`:active.json 合法且文件存在 →
    激活;否则告警回退 Master(不删任何文件)。
- `src/my_agent_alpha/logmanager/__init__.py`:导出 `ViewState`。
- `tests/test_views.py`(新增,17 个用例):逐条对照方案 §8 V1 验收清单 +
  views.py 单元(编号扫描、ID 校验、坏状态拒绝)+ switch_to_master。
