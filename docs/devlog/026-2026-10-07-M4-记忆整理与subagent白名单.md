# 026 — M4:限制帮手进程的工具 + /memory consolidate 记忆整理命令

## 目标

完成《长期记忆改进方案》的最后一期 M4,分两步:

1. 前置:让"派出去干活的帮手"只能使用指定的一小部分工具(防止它干超出范围的事);
2. 主体:新增斜杠命令 `/memory consolidate`(整理记忆:合并重复、修正矛盾、删除已被证伪的)。

## 先把几个词说清楚(写给自己,复习用)

- **子代理(帮手进程)**:主助手另外启动的一个独立的 my-agent-alpha 程序进程,
  替主助手单独干一件事,干完把结论带回来。它有自己的对话记录,看不到主对话。
  这是阶段 8 做好的功能,本项目文档里一直叫它 subagent。
- **工具注册表**:程序里保存"当前有哪些工具可用"的一张清单
  (代码在 tools/__init__.py)。模型写的每一次工具调用,都要先查这张清单。
- **白名单**:把清单缩小——只保留指定的几个工具名,其余全部移除。
  移除之后,模型再怎么写调用这些工具的指令,程序都当作没看见,不会执行。
- **mock 模型**:测试用的假模型,不联网、不花钱。可以事先给它几句话(剧本),
  它就按顺序一句一句回——这样测试就能精确"导演"出一次多步操作。
- **一个往返(一轮)**:主循环的一次完整配合——模型输出文字(可能带工具调用)
  → 程序执行工具 → 把结果发回给模型。多步任务就是多个往返。

## 决策及理由

### 1. 把"派帮手进程"的代码写成一个独立函数,工具和命令共用

原来这段代码写在 subagent 工具的执行函数里面,只有这个工具能用。
这次把它搬出来,做成独立函数 `run_subagent`(在 tools/subagent.py):
subagent 工具调用它,`/memory consolidate` 命令也调用它——
同一份"派活"逻辑,不用写两遍。

`run_subagent` 用了 Python 的**生成器**写法(函数里用 `yield`,每调用一步
就交出一条结果)。原因:派帮手的过程会产生好几条消息——开始时的
"已派出,等待完成…",结束时的"结论是:…"。生成器一条一条交出,
两边各取所需:工具把这些消息转成 system 消息发给模型看;
命令把它们直接打印到终端给你看。**同一份过程,两种展示方式。**

### 2. 白名单:新增 restrict_tools 函数 + 命令行参数 --tools

- 调用 `restrict_tools(["read", "grep", "memory"])` 之后,注册表里就只剩
  这三个工具。想留但注册表里不存在的名字会原样返回,方便提示"名字写错了";
- 命令行加 `--tools read,grep,memory`(逗号分隔),给帮手进程启动时用;
- 模型调用工具有两条路(在回复里写代码块,或走接口的原生函数调用),
  两条路都要查同一张注册表——所以只要把清单缩小一次,两条路同时被拦住,
  不会出现"漏拦一条路"。

### 3. 堵一个自查发现的漏洞:晚连接的 MCP 工具会绕过白名单

`--tools` 在程序启动时就生效了;但 MCP 的外部工具是进入对话环节之后
才连上服务器、才加进注册表的——加的时候没检查白名单,外部工具就
混进"受限帮手"里了(你的 /tmp/mcp-test 工作区就配置着 MCP)。
修法:把白名单单独记住,以后每次往注册表加新工具,都先对照白名单,
不在名单里的不许进。这条有专门的回归测试。

### 4. mock 模型的剧本可以放进环境变量

测试里的剧本原本只能设在"当前这个进程"里;但帮手是另一个进程,
看不到当前进程里设置的剧本。解决办法:剧本(一个 JSON 数组)放进
**环境变量** `ALPHA_MOCK_REPLIES`(环境变量:操作系统传给子进程的
文字设置,子进程能读到)。这样测试就能指挥帮手进程按剧本干活。
取用顺序:当前进程的剧本 > 环境变量里的剧本 > 普通回声模式;
环境变量内容不是合法 JSON 时,当作没有剧本,不报错。

### 5. 整理记忆的任务说明里,直接附上现有记忆的清单

`build_consolidate_prompt`(在 memory_store.py)拼任务说明时,把每条记忆
的"文件路径 + 描述 + 类型"直接列进去。这样帮手一读任务就知道已有什么,
不用先花一个往返去执行列目录命令。内容层面的"哪两条算重复"没有程序
能判断的办法,只能靠把清单给它、让它自己对照——这是诚实的技术边界。

### 6. 整理帮手只能用 read / grep / edit / memory 四个工具,没有 shell

它要改记忆、删记忆,所以给写的能力;但不给它执行任意命令的 shell 工具
(Claude Code 的"做梦"整理代理也是同样的限制)。帮手进程带自动确认参数
运行,不再逐条问你——**你敲 `/memory consolidate` 这个动作本身就是审批**。

## 改动结构

| 文件 | 改了什么 |
|---|---|
| tools/\_\_init\_\_.py | 新增 restrict_tools(缩小清单+记住白名单);往清单加新工具时先对照白名单 |
| \_\_init\_\_.py(main 函数) | 新增命令行参数 --tools |
| tools/subagent.py | 独立函数 run_subagent;subagent 工具新增 tools 参数 |
| llm/mock.py | 支持从环境变量 ALPHA_MOCK_REPLIES 读剧本 |
| memory_store.py | 新增 build_consolidate_prompt(四阶段任务说明+记忆清单) |
| commands/builtin.py | /memory consolidate 命令入口 |
| 测试(5 个新增) | 白名单缩小、晚加的工具被拦、环境变量剧本、任务说明含清单、整理全流程 |

## 已知限制

1. **整理效果还没用真模型验证过**:mock 只能证明管道通(命令→帮手→改文件→
   报告返回),四阶段任务说明对真模型(kimi/glm)的执行效果,要等记忆
   攒到十几条后真跑一次 `/memory consolidate` 才知道;
2. `-n` 模式不会去读管道传入的标准输入(初验时发现,不算错误):
   命令要作为启动参数传,如 `my-agent-alpha "/memory consolidate"`;
3. 白名单按工具名精确匹配;将来若要"允许用 shell 但只许只读命令"这种
   更细的限制,需要另外做参数级别的检查。
