# 007 · 阶段 3:原生工具调用

- **日期**:2026-09-30
- **阶段**:3 / 原生工具调用(function calling)
- **验收标准**:同一份 ToolSpec 声明,markdown 和原生两种通道都能调,执行端零改动 —— ✅ 达成

## 一、目标

给 agent 加上第二种工具调用通道(见学习文档 §2.4/§3.3/§5.2):
模型走接口内置的 function calling,而不是只靠"围栏代码块"的文本约定。

## 二、核心设计(照搬 gptme 的"支柱二")

日志仍是纯文本 —— 原生调用在文本里记成一行:

```
@save(call_abc123): {"path": "a.txt", "content": "你好"}
```

三个方向各有一个转换点:

1. **收(响应方向)**:接口的 tool_calls 流式分片(name 先到、arguments 逐字符到)
   在 `_stream_once` 里按 index 拼装,参数 JSON 一凑齐(大括号配对 + 可解析)
   立刻产出上面那种行 —— 断点检测无需特判就能提前触发;
2. **发(请求方向)**:`msgs2dicts` 把 assistant 消息里的 @行 转回接口的
   `tool_calls` 字段;带 call_id 的 system 消息(工具结果)转成 `tool` 角色;
   编号找不到主的结果("孤儿")降级为 user 消息(接口要求每个 tool 消息必须有主);
3. **解析(执行方向)**:`ToolUse.iter_from_content` 新增第三种识别 ——
   `@名字(编号): {JSON}`,大括号配对计数(引号内不算),没闭合先不要
   (天然流式安全);围栏代码块里的 @xxx 只是示例,fenced_regions 跳过;
   markdown 块和 @行混排时按出现位置统一排序。

## 三、改动结构

| 文件 | 变化 |
|---|---|
| tools/base.py | `Parameter` 参数表;`parameters_to_schema`/`spec_to_openai_tool`(描述截断 1000,OpenAI 1024 上限);`ToolUse.kwargs` + `display_command`;@行解析 + `find_json_end` |
| codeblock.py | `fenced_regions`:围栏的字符区间(给 @行解析排除示例用) |
| tools/__init__.py | execute_msg 给原生调用的**最后一条**结果盖 call_id(接口要求一调用一结果) |
| tools/{shell,read,save}.py | 声明参数表;execute 支持 kwargs 通道(和 code/args 通道并存) |
| llm/openai_compat.py | 流式分片拼装;非流式 tool_calls → @行;msgs2dicts 双向转换 + 孤儿降级 |
| llm/__init__.py | reply(tools=, tool_format=) |
| chat.py / prompts / CLI | tool_format 全链路透传;原生版系统提示词;`--tool-format` 参数(默认 markdown,`ALPHA_TOOL_FORMAT` 可设) |
