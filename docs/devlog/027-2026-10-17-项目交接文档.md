# 027 · 2026-10-17 · 项目交接文档

## 目标

写一篇交接文档(`docs/项目交接文档.md`),让接手的人(或 AI)一篇文章看懂:项目是什么、每个模块完成了什么功能、进度到哪、当前工作区有什么未提交改动、去哪查资料。

## 决策及理由

- **信息来源用源码头注,不用记忆**:每个模块"完成了什么"一律摘自各 `.py` 文件开头的学习型注释和 `docs/devlog/README.md` 索引,保证和代码现状一致,不凭印象写。
- **文档放在 `docs/` 根目录,中文文件名**:和已有的 `踩坑记录.md`、`长期记忆改进方案.md` 同风格。
- **模块按目录分组讲,先架构后清单**:先给"三层循环 + 三条铁律"的一分钟版,再逐模块列表 —— 读者不用读完也能按需查。
- **如实记录暂存分支**:`phase7-server-webui` 上有 Server+WebUI 的 wip 提交(用户未学前端故暂存),交接文档必须写明,否则接手的人会以为界面功能丢了。

## 改动结构

- 新增 `docs/项目交接文档.md`(八个部分:项目简介 / 架构一分钟版 / 模块清单 / 进度 / 工作区状态 / 文档地图 / 硬规则摘要 / 常用命令);
- 新增本 devlog 并更新 `docs/devlog/README.md` 索引。
- 未改任何代码。
