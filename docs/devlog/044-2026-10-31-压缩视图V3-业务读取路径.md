# 044 —— 压缩视图 V3:业务读取路径与端到端验收

## 目标

按开发方案 §8 V3(§6.2/§6.3)把视图接入真实业务读取路径:需要完整历史的
地方(todo 重放、终端回放)显式读 Master;给人看的数字(/log)不被压缩骗;
核对 /resume 与子代理不受影响。核心命题只有一条:**"给状态重放的/给人看的"
读完整历史,"给模型看的"读视图,两条线不能串**。

## 决策及理由

- **改动极小是本阶段的刻意目标**:V1/V2 把读取口(`master_messages` vs
  `messages`)准备好了,V3 只是让三个调用点选对口的 —— tui.replay 与
  replay_todo_hook 各改一行(读 master_messages),/log 补一行视图说明。
  chat.py 主链路一行不动(step(manager.messages) 自动读视图)。
- **replay_todo_hook 必须读 Master(方案 §1 特别点名)**:todo 的 add/update
  可能早已被压缩掉,用视图重放会漏掉状态变更,重启后清单就错了。
  todo_gate_hook 保持读 messages(它判断的是"近期收尾",视图正合适)。
- **tui.replay 读 Master**:回放是给人看的,用户应看到真实完整对话;
  模型上下文才用视图。两个读取源不同是有意设计(方案 §9.8)。
- **/log 的数字不许骗人**:消息条数固定报 Master(压缩不能让会话"看起来
  变短");激活视图后补一行"当前视图:compacted-NNN · N 条(模型读这份压缩后的)",
  让用户看见两个数字不一样时知道为什么。/log list 的统计(sessions.py
  _parse_roles)本来就直读 conversation.jsonl,零改动天然满足。
- **不加 /context 命令**:方案 §6.4 允许"/context 或扩展 /log"二选一,
  选扩展 /log(KISS);token 统计入口等真需要时再补。
- **子代理独立性零改动验证**:视图状态全在各自 logdir 的 views/ 下,
  子代理会话目录里没有 active.json,天然互不影响;用测试钉住这个事实。

## 改动结构

- `src/my_agent_alpha/tui/io.py`:replay() 改读 master_messages(+注释说明为什么)。
- `src/my_agent_alpha/hooks/todo.py`:replay_todo_hook() 改读 master_messages。
- `src/my_agent_alpha/commands/builtin.py`:/log 显示完整历史条数,
  激活视图时补视图行。
- `tests/test_view_integration.py`(新增,7 个用例):
  todo 压缩后重放、回放 vs 模型输入、switch_session(/resume 执行体)
  恢复视图并双写、/log 双份显示、/log list 计数不变、子代理独立、
  chat() 全链路(mock 流式入口包探针,拿模型实际收到的消息列表断言
  "输入来自视图",同时 capsys 断言"回放是完整历史")。
