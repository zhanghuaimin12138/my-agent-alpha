## 三、关键设计点

### 3.1 工作区键:可读编码 + 路径指纹(2026-10-26 修订)

> **修订原因**:CC 的桶名纯靠编码,孪生路径(如 `my_agent_alpha` 与 `my-agent-alpha`)会撞进同一桶,**项目记忆因此串用**——2026-10-25 用户在 CC 中实测确认此缺陷真实存在。本方案不继承它。

**思路一句话:桶名 = 姓名 + 身份证号。** CC 相当于只拿姓名当身份:把路径里非字母数字的字符统统换成 `-`,拿结果当目录名——可这种替换是丢信息的,两个不同目录会换出同一个"姓名"(这就是撞桶)。指纹方案在姓名后面拼一串"身份证号":姓名可以重,身份证号不重。

参考实现(2026-10-26 已在本机跑通,实测见下):

```python
import hashlib, re
from pathlib import Path


def workspace_key(workspace: Path) -> str:
    """工作区桶名:可读前缀(给人看)+ 路径指纹(保证唯一)。"""
    real = str(workspace.expanduser().resolve())  # ① 归一
    readable = re.sub(r"[^A-Za-z0-9]+", "-", real)  # ② 姓名段
    digest = hashlib.sha256(real.encode()).hexdigest()[:8]  # ③ 身份证段
    return f"{readable}-{digest}"
```

三步各自的职责:

| 步骤 | 做什么 | 为什么必须有它 |
|---|---|---|
| ① 归一 `expanduser().resolve()` | 把 `.`、`..`、结尾斜杠、`~`、符号链接全部翻译成唯一的绝对真实路径 | 治**反向 bug**:同一个项目若按"写法"算键,今天 `.`、明天 `../my_agent_alpha`、后天带尾斜杠启动,会被拆成三个桶。规则:**写法千千万,身份只有一个** |
| ② 姓名段(编码) | 真实路径里非字母数字换 `-`(连续合并) | 只给人看,**不承担唯一性**——怎么换都不影响正确性 |
| ③ 指纹 | 真实路径的 UTF-8 字节做 SHA-256,取前 8 位十六进制 | 哈希像"榨汁机":同一输入永远同一输出,差一个字符输出面目全非——孪生路径必然分桶;8 位十六进制 ≈ 43 亿种组合,个人量级撞不上 |

实测输出(2026-10-26,本机真实运行结果):

```
同一个目录的三种写法 → 同一个桶:
  '.'                                  -> -home-yby-projects-my-agent-alpha-d15c78a0
  '../my_agent_alpha'                  -> -home-yby-projects-my-agent-alpha-d15c78a0
  '/home/yby/projects/my_agent_alpha/' -> -home-yby-projects-my-agent-alpha-d15c78a0
孪生命名 → 不同桶:
  my_agent_alpha -> -home-yby-projects-my-agent-alpha-d15c78a0
  my-agent-alpha -> -home-yby-projects-my-agent-alpha-7a3c5ba0
```

上面两组结论就是将来 `test_dirs.py` 的两条硬断言:**同目录不同写法必须同桶;孪生命名必须分桶。**

两个常见疑问:

- **为什么不直接拿完整路径当目录名?** 路径里的 `/` 不能出现在目录名里,必须替换,而替换丢信息、正是撞桶根源;指纹把丢掉的信息用另一种形式补了回来。
- **项目改名/搬家怎么办?** 键随路径变,旧桶视为新工作区(数据不丢,只是不自动续上)——个人工具接受,如实记录。

其余纪律不变:桶名只用来"编码后查询",永不反向解码。

### 3.2 会话目录名:默认 uuid4,`--name` 语义不变

- 默认目录名 = `uuid4().hex`(32 位十六进制,全局唯一,不含日期——日期会撒谎:跨天续聊的会话文件名里的日期就不对了;看时间交给 /log list)
- **`--name` 保持"就是目录名"的原语义,不改**。原因:[subagent.py:63-64](../../src/my_agent_alpha/tools/subagent.py) 用 `--name` 把子会话目录名传给子进程、父进程再按同名找回来,这是内部契约。用户给会话起名 → 目录名可读 + 标题写 meta.json,行为与今天完全一样。

### 3.3 `ALPHA_LOGS_HOME` 环境变量:语义微调

- 现在 = "整个 logs 根目录"
- 改为 = "替代 `projects/` 这一层的位置",即会话根 =
  - 默认:`数据目录/projects/<编码>/logs`
  - 设了变量:`$ALPHA_LOGS_HOME/<编码>/logs`
- 作用不变(测试与真实数据隔离),已 grep 确认仅测试代码在用,无外部脚本依赖

### 3.4 数据目录改连字符的两处牵连

1. 用户级记忆要搬家:`mv ~/.local/share/my_agent_alpha/memory ~/.local/share/my-agent-alpha/`(一条命令,人工执行,不写代码)
2. 配置目录 `~/.config/my_agent_alpha` 是否跟着改连字符 → **待拍板 A**(推荐:改,保持一致;反正现在里面是空的)

### 3.5 明确不变的东西(红线复述)

- `conversation.jsonl` 行格式 = 现有 `Message.to_dict()`,一字段不增不减
- 只追加、永不改写;追加游标 + 原子重写机制原样
- `meta.json` 读写仍只走 naming 那对函数;标题混入 `<think>` 的老 bug **本次不修**(与目录无关,进积压)
