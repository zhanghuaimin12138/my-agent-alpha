# 017 · 坏字符清洗:用户输入坏表情序列不再崩程序

## 目标

修复踩坑记录条目 6:用户输入混入"落单代理字符"(终端坏 UTF-8 序列的解码
残渣),`manager.append()` 写日志时 `UnicodeEncodeError` 直接把整个程序
打死(REPL 崩到系统提示符)。

## 决策及理由

三层防御,各挡一层:

| 层 | 手段 | 挡什么 |
|---|---|---|
| 入口 | `_get_user_input()` 返回前清洗 | 终端传来的坏字符(本次事故的直接来源) |
| 日志层 | `_jsonl_line` 编码前清洗 | 任何别的来源:LLM 回复、MCP 工具结果、subagent 输出 |
| 循环层 | append(user)/TURN_PRE 钩子挪进 try | 未知未来的存储错误:只终结回合,不终结程序 |

清洗函数 `clean_bad_unicode()`(message.py):`encode("utf-8", errors="replace")
.decode("utf-8")` —— 落单代理字符换成 ?,合法字符(含正常表情)原样保留。
取舍:一个字符变 ? 是可接受的损失,丢掉整段会话不可接受(日志是唯一状态)。

## 已知限制

- 清洗是"丢字符换存活":坏字符变成 ?,原字节不可恢复(可接受:反正也
  编不进 utf-8);
- `print()` 到终端的字符串理论上也可能因坏字符抛异常(终端编码差异),
  本次未处理,出现再说。
