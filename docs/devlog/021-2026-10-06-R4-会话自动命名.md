# 021 · R4:会话自动命名

日期:2026-10-06 · 阶段:第二轮 R4 · 状态:代码完成,待用户审查后 commit

## 目标

round2-plan R4:治"会话列表全是时间戳"。第一回合结束后让模型给会话
起一个 ≤20 字的标题,`/log` 与 `/log list` 能看清哪个会话是哪个。

## 决策及理由

| 决策 | 理由 |
|---|---|
| turn.post 钩子触发(不改核心循环) | 架构纪律"横切关注点皆钩子";回合结束正好有首轮对话可用 |
| 标题写会话目录的 meta.json,目录名不动 | 会话进行中改目录名会弄断所有攥着旧路径的句柄;meta 与日志分离 |
| 命名请求**不进对话日志** | 标题是元数据不是消息;日志仍是"唯一事实来源"且不被污染 |
| 当前模型生成(不单独配便宜模型) | KISS;round2-plan 允许;一次调用 ≤600 字输入成本极低 |
| 命名失败不重试硬扛:打印一句,下个回合自然再试 | 命名是锦上添花,任何失败都不许影响会话本身 |
| `--name` 指定的会话直接把名字写成标题 | main 入口写一次 meta,钩子看到已有标题就跳过;列表显示统一走 meta |
| 触发条件 = 无标题 + 已有一对 user/assistant | 不限"第一回合":恢复的旧会话(无标题)在下一个回合后也会补上名字 |
| 总开关 `ALPHA_AUTO_NAME`(默认开) | 测试隔离:命名钩子的额外模型调用会消耗 mock 脚本序列,搅乱 todo 门控/subagent/guardrail 等无关测试;conftest 默认关,测命名的测试显式开 |
| 新增 `/log list` | 会话列表功能此前不存在;扫 logdir 同级目录 + 读各自 meta,排序即时间序 |

## 开发中抓到的真实 bug(测试的功劳)

第一版 main 的 --name 分支在 `chat()` 之前写 meta.json,而 logdir
此时还没被 `LogManager.load(create=True)` 创建 → FileNotFoundError。
**subagent 子进程正是用 --name 起会话的**,phase8 的三个子代理测试
当场全红 —— 生产上任何 `--name` 启动也会炸。修复:`write_session_title`
自己 `mkdir(parents=True, exist_ok=True)`(写标题者保证目录在)。

CLI 冒烟(ALPHA_LOGS_HOME 隔离):
- `--name 冒烟会话`:正常跑完,meta.json = {"title": "冒烟会话"};
- 自动命名路径:`(会话已命名:...)` 打印、meta 写入、目录名不动;
  mock/echo 把提示词原样回显(真模型会给真标题),清洗截断生效。

测试覆盖:标题清洗(引号/多行/超长/空)、meta 往返与损坏容错、
已有标题跳过(--name 场景)、对话未成型不命名、端到端命名
(脚本第 2 条被命名调用消耗,断言标题写入 + 打印 + 日志无命名消息)、
/log 显示标题、/log list 列出命名与未命名会话。

## 已知限制

- 命名调用是同步的:回合结束后阻塞约一次模型往返(交互模式可感知);
  之后有标题就再不触发;
- 标题质量依赖模型;清洗只做"取首行/剥引号/截 30 字"三件事,不纠内容;
- `/log list` 没有分页(mtime 排序也暂未做,按目录名字典序即时间序)。
