# 045 —— 压缩视图 V4:压缩器修复与接入

## 目标

按开发方案 §8 V4(§5.2)做两件事:先修 compact_messages 的四个正确性问题
(三处重建消息丢字段、hard_cap 拆散工具配对、缺激活前安检),再把它接进
视图(compact_current_to_view + /compact 命令)。修好之前,压缩结果
没有资格升级为持久化视图。

## 决策及理由

- **三处 Message(...) 重建全部改为 dataclasses.replace(msg, content=...)**:
  剥思考/截断工具结果/压长回复都只该换 content,call_id/pinned/hide/
  quiet/metadata/时间戳必须原样带到新实例。丢了 call_id 的工具结果在
  压缩后永远配不回它的调用(接口 400),丢 pinned 等于模型失忆。
- **compress_long_replies 的调用判断改用 ToolUse.iter_from_content**
  (两种通道都认),不再靠肉眼猜文本特征:只查 "@" 会漏 markdown 围栏调用,
  只查 "```" 会误伤纯展示代码块。
- **hard_cap 按"交互组"裁剪(新私有函数 _tool_groups)**:一组 = 一条
  assistant + 它后面的全部 system 随从(工具结果/[用量]统计),组是原子的。
  user 消息必须打断分组(它是回合边界,不是随从)——第一版分组把 user
  吸进前一个 assistant 组,自查发现后修掉。装不下 pinned+尾部组时
  尽力而为(pinned+能装的组),不再保证"至少留一条";View 路径的安检
  会拒绝丢了最新 user 意图的结果,请求级路径照旧让接口兜底。
- **validate_compacted_messages 四查**:pinned 系统提示词一条不少、
  最后一条 user 在、原生调用与结果按 call_id 多重集合配对(同编号两条
  结果也算坏)、任一不满足抛 ValueError。匹配用对象同一性(is)而不是
  Message 相等 —— 相等只比 role/content,内容撞车会误判"还在"。
- **is_meaningful_reduction:省不足一成不建视图**(省 5% 白多一个视图
  文件和一次切换)。**compact_current_to_view 的压缩源是 manager.messages**
  (激活过就是上一次视图),第二次压缩不会重读整个 Master 反复压。
- **/compact 命令**:成功打印视图名与两份条数;无收益如实说"保持现状";
  安检不过(比如还有没返回的调用)打原因、不激活。

## 改动结构

- `src/my_agent_alpha/compaction.py`:
  - 三处 replace 修复;compress_long_replies 换 ToolUse 解析器判断;
  - `_tool_groups` + 重写 hard_cap(组原子裁剪);
  - 新区块"压缩视图接入":validate_compacted_messages /
    is_meaningful_reduction / compact_current_to_view;
  - 模块 docstring 更新(压缩结果两个去处:请求级现算 vs 持久化视图)。
- `src/my_agent_alpha/commands/builtin.py`:新增 /compact 命令 + /help 提示。
- `tests/test_compaction.py` +8:字段保留、原生调用不压、组原子性、
  [用量]随组、hard_cap 结果过 msgs2dicts 无孤儿、安检四例。
- `tests/test_view_integration.py` +5:建视图(Master 字节不变)、无收益
  不建、第二次压缩源自视图(探针捕获 compact_messages 的输入)、
  /compact 命令两条路径、压缩后 msgs2dicts 配对 + chat 继续一轮。
