# 039 · 移除补发提醒,回合停止条件回归纯规则(2026-10-30)

## 目标

按用户决定修正 `_process_message_conversation`:**不保留消息提醒**,
turn 停止的条件就是"最后一条模型回复里没有任何可执行的工具调用"。

## 决策及理由

补发提醒(nudge)是历史上为治"模型本想调工具却没写成(只输出思考/
围栏标记写岔/冒号结尾/宣告要干活/原生调用行不合规)"而加的兜底:
回合将结束时检测这些迹象,追加一条 system 提醒再生成一轮,有次数上限。

用户现在选择回归 AGENTS.md 的架构纪律原文 —— "循环的继续判定只看
'最后一条 assistant 是否还有可运行 ToolUse',不引入额外状态":
模型漏写调用就当作它给了最终回答,回合自然结束,不再补救。
代价是那五类"没写成"的坑重新变成静默收尾;收益是中层循环回到
零额外状态、零特判,行为完全可从日志推导。

**连带删除**(功能整体退场,不留死代码):
- `src/my_agent_alpha/nudge.py`(037 刚从 chat.py 搬出的检测+提醒模块);
- `tests/test_tool_nudge.py`(16 个测试);
- 各处注释里对 NUDGE 的引用(hooks/todo.py、test_todo_gate.py、
  test_naming.py)改为自足表述。todo 门控不受影响 —— 它是
  loop.continue 钩子,继续判定之外的独立机制,用户明确保留。

## 改动结构

```
chat.py  _process_message_conversation:
         - 删 nudges 计数、missed_tooluse_reason/make_nudge 分支(约 25 行)
         - 循环尾部只剩:has_runnable_tooluse → continue;否则 return
         - 模块文档串去掉 nudge 段落与去向清单行
删除     nudge.py、test_tool_nudge.py
```

本提交同时收录用户在 chat.py 的两处手改(如实注明):
函数重排为"入口在上、内层在下"的阅读顺序;`chat()` 的 tool_format
默认值由 "markdown" 改为 "tool"(**该默认值是否保留此前已提请用户确认,
尚未答复;如要改回,一行 + 一个回归测试即可**)。
