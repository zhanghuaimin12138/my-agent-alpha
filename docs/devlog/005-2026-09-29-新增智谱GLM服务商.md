# 005 —— 新增智谱 GLM 服务商

## 目标

让 agent 能直接用 `-m glm` / `-m glm-coding` 对接智谱 GLM 大模型,零新增客户端代码。

## 决策及理由

- **不加新模块,只在 `PROVIDERS` 表加两条配置**。智谱开放平台提供 OpenAI 兼容端点
  (`https://open.bigmodel.cn/api/paas/v4/`),现有 `openai_compat.py` 的统一客户端
  (重试/流式/`reasoning_content` → `<think>` 包装)全部直接复用——这正是 gptme
  "OpenAI 路径是万能适配器"设计的第一收益。
- **两个端点都内置**(用户选定):`glm`(标准按量计费)与 `glm-coding`
  (`https://open.bigmodel.cn/api/coding/paas/v4`,GLM Coding Plan 订阅专用)。
  区别只是 base_url,多一行配置即可随时切换。
- **默认模型 `glm-5.3`**(用户选定);**密钥环境变量 `GLM_API_KEY`**(用户选定,
  与 provider 名保持一致,和 `ALPHA_GLM_*` 自定义风格对称)。

## 改动结构

- `src/my_agent_alpha/llm/models.py`:`PROVIDERS` 表新增 `glm`、`glm-coding` 两条
  `ProviderCfg`,共用 `GLM_API_KEY`,默认模型均为 `glm-5.3`。
- `tests/test_llm.py`:新增 3 个离线测试——`glm` 裸名走默认模型、表内两条配置的
  base_url/api_key_env 断言、`glm-coding/glm-4.6` 显式拆分(验证带连字符的服务商名
  能被整名识别)。
- `src/my_agent_alpha/tools/__init__.py`:注释前补一个空格(ruff format 要求,
  与本功能无关的顺手修复)。

```
uv run my-agent-alpha -m glm-coding     # Coding Plan 订阅端点
```

## 已知限制

- 未做真实网络联调(无密钥环境下会话);离线测试只覆盖名字解析与表配置,
  HTTP 层行为由既有 `test_streaming.py` 对 `openai_compat` 的覆盖保证。
- `glm-5.3` 是否在账号开放以实际调用为准;不可用时显式写 `-m glm/glm-4.6` 等模型名即可。
