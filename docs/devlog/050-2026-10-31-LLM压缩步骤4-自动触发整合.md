# 050 —— LLM 语义压缩 步骤 4:自动触发整合与 /context

## 目标

按报告 L5(方案步骤 4)把两种压缩接进现有 turn.post 自动机制:三选一
决策(none/trim/summarize)、同指纹节流(不重复花钱)、自动 LLM 通道
默认关、新增只读 /context 观测命令。不注册第二个钩子,存储层不动。

## 决策及理由

- **decide_compaction 用"软压缩预演"而不是完整机械压缩**:第一版
  直接预演 compact_messages(含 hard_cap 兜底裁剪) —— 超预算时兜底
  必然把历史砍到目标线,"省 10%"永远满足,**summarize 分支永远不可达**
  (自查发现的漏洞)。改为只预演软压缩三阶段(剥思考/截超长输出/压长
  回复,不丢整条消息):有低损收益就用机械;省不动说明剩下全是语义
  密集的干货,丢消息损失大,才轮到请模型写笔记(保留语义)。
- **自动 LLM 默认关**(ALPHA_AUTO_LLM_COMPACT=1 开启):纯花钱的操作,
  质量尚未在真模型上验证(步骤 5 的事);手动 /compact summarize 永远
  可用且不受节流限制。通道关闭时安静跳过(每回合打印会刷屏)。
- **同指纹节流替代回合冷却(LLM 分支)**:压缩失败/花钱没结果时记下
  当时的历史指纹;指纹相同(历史没实质变化)不再自动重试,指纹变了
  自然重试 —— 比"数回合"更精确地表达"同一段历史别反复烧钱"。
  stale(摘要期间历史变了)不节流:指纹已不同,下回合自会再试。
  trim 分支保留原有回合冷却,行为与 V5 完全一致。
- **一个有意的行为变化**:干货型超阈值历史在"自动 LLM 关闭"时,
  现在会安静不动(以前直接丢消息裁剪);超窗兜底仍由 step() 的溢出
  重试负责。保守取向:自动机制宁可不动也不丢语义,想压请手动或开开关。
- **/context 只读命令**:完整历史条数/tokens、当前读哪份(视图 or
  Master)、压缩方式与前后 token、预算占用百分比。笔记 metadata 增记
  tokens_before(压缩前多大)供其显示。

## 改动结构

- `src/my_agent_alpha/hooks/autocompact.py`:decide_compaction(三选一)、
  llm_auto_enabled、_auto_trim(V5 逻辑原样搬入)、_auto_summarize
  (开关+节流+四状态处理)、_failed_llm_digest 模块级状态。
- `src/my_agent_alpha/compaction_llm.py`:extra_meta 增 tokens_before
  (分块诊断用 update 合并,不覆盖)。
- `src/my_agent_alpha/commands/builtin.py`:/context 命令 + /help 更新。
- `tests/test_autocompact.py` +6:决策三例(含垫底消息让 think 可剥)、
  默认关安静跳过、开启后自动生成视图、同指纹节流(spy 计数不重复调)、
  历史变化后重试成功、/context 两种状态输出。
  V5 的两个测试历史改为带思考区(适配"干货不再走机械"的行为变化)。
