# 027 多会话改造方案(架构设计 + 阶段计划)

- 日期:2026-10-24
- 性质:纯文档(方案定稿,未动代码)
- 分支:feat/multi-session
- 上游输入:gptme 源码调研(GitHub master)+ 本项目 S0 现状核对(真实读码)

## 一、目标

把"一个进程 = 一个会话"的终端 agent,改造成:

1. 同时打开多个会话,来回切换(一个终端窗口);
2. 多个会话**同时干活**——A 在后台跑长任务,B 在前台正常对话;
3. 多个终端窗口各自开会话互不干扰(S2 起就达成);
4. 后台会话完成/需要确认时,主动提醒用户。

不做的事:**不做前端、不做 server**(gptme 的浏览器路线),纯 REPL 实现,不引入 TUI 框架。

## 二、关键决策及理由

| 决策 | 理由 |
|---|---|
| 并发模型用**线程**,不用 asyncio | gptme 同款:agent 循环代码一行不改,只是"搬进后台线程跑"。asyncio 化要重写全部 IO,违背 KISS |
| 不上 server | 用户明确"先不开发前端";且 S3/S4 的注册表将来若做 server 可直接复用,不算白做 |
| 切换用斜杠命令(`/switch`) | 不引入 TUI 框架,工作量最小,学习曲线平缓 |
| 主线程只当"输入泵" | 终端只有一个输入流,但 N 个会话 + N 个确认请求都想问话 → 规定:只有主线程读输入,worker 线程一律登记"待确认"然后等待,由主线程路由答复 |

### gptme 调研结论(源码实读,三层)

1. **磁盘层**:每会话一目录(`conversation.jsonl` + 配置);跨进程互斥靠目录里 `.lock` 文件(flock 非阻塞排他 + 写 PID + 死进程检测);稳态追加写、改历史走临时文件原子替换 —— 我们的 Log 已经同构,只缺 `.lock`。
2. **内存层**:`SessionRegistry` 就是 `dict[会话ID, Session]`;Session = LogManager + 运行状态(正在生成/待确认/自己的锁);注册表不持久化,重启即失。
3. **执行层**:每步一个后台**线程**(不是 asyncio);同一会话两级锁 + "正在生成"标志 + 代际号(step_seq 递增,中断后旧排队任务全部作废)。
4. gptme 的 TUI 是**一窗口一会话**,多会话体验靠 server+浏览器 —— 我们走的"单进程内多会话"是它没做的路线,但零件(注册表/线程/锁)全部可借鉴。

## 三、现状核对结果(S0,已按真实代码逐项核实)

| # | 项 | 结论 |
|---|---|---|
| 1 | REPL 入口 | `src/my_agent_alpha/chat.py` 三层循环完全同步;一个进程一个会话;恢复旧会话只能靠 `--name` 撞目录名 |
| 2 | LogManager | `logmanager/manager.py` 与 gptme 同构(追加游标+原子重写);**没有文件锁**(devlog 001 刻意推迟) |
| 3 | 会话列表 | `/log list`(`commands/builtin.py`)直接扫目录读标题,已有雏形,但没有独立函数层、信息少 |
| 4 | 工具执行 | `tools/shell.py` 用 `subprocess.run(cwd=get_workspace())`;全项目 **0 处 os.chdir** —— "工作目录互踩"的雷不存在 |
| 5 | 确认机制 | `confirm.py` 的 `_hooks` 和 `_auto_confirm` 是**模块级全局**,`cli_confirm_hook` 直接 `input()` 抢终端 —— 多会话最大的雷 |
| 6 | 全局状态 | `context.py`(workspace/logdir/model)和 `tools/__init__.py`(工具表/白名单)**已经是 ContextVar**,注释明言为多线程预留;`hooks/__init__.py` 注册表是普通 dict(但现有钩子全部无状态,暂不致命);llm 层无可变全局 |

两个额外发现:

- **好消息**:多线程伏笔早就埋好(context/tools 两处注释原话就是"将来开多线程跑多个会话时,各线程各有一份,互不干扰")。
- **新雷**:Python 新线程**不继承** ContextVar 当前值(拿到的是默认值)→ worker 线程启动时必须显式设置自己的上下文(这反而保证了会话间隔离)。

## 四、目标架构图

```
┌──────────────────────────────────────────────────────────┐
│ 主线程:输入泵 + 显示路由(唯一读终端输入的人)             │
│   REPL:读一行 → /命令?确认答复?普通输入? → 路由          │
└─────────┬────────────────────────────────────────────────┘
          │ 唤醒/答复(Event)         ▲ 状态与缓冲
┌─────────▼────────────────────────────────────────────────┐
│ SessionManager(内存注册表,新文件 session_manager.py)     │
│   会话名 → LiveSession                                     │
│     ├─ LogManager(现有,不改)                            │
│     ├─ worker 线程:跑 _process_message_conversation      │
│     │    (核心循环 chat.py 逻辑不动,只换地方跑)           │
│     ├─ 运行状态:锁 / 正在生成 / 中断代际号 / 待确认      │
│     ├─ 输出缓冲(后台会话)                                │
│     └─ 专属 ContextVar:workspace/logdir/model/工具表      │
├──────────────────────────────────────────────────────────┤
│ 横切(纪律:不进核心循环):                                 │
│   确认链 confirm.py(ContextVar 化,S3)                    │
│   通知 → 挂 TURN_POST 等现有 hook 点(S5)                 │
└─────────┬────────────────────────────────────────────────┘
          │ 每会话独立目录,append-only
┌─────────▼────────────────────────────────────────────────┐
│ 磁盘层(现有 + S2 一把锁)                                  │
│ ~/.local/share/my_agent_alpha/logs/<会话ID>/               │
│   conversation.jsonl  ← 只追加,永不改写(现有纪律)        │
│   meta.json           ← 会话标题(现有,R4 自动命名)       │
│   .lock               ← 跨进程互斥(S2 新增,仿 gptme)    │
└──────────────────────────────────────────────────────────┘
```

一句话:**磁盘层只加一把锁,核心循环一行不改,新增"注册表 + worker 线程 + 输入泵"三样,横切全走现有 hook。**

## 五、阶段计划(S1–S5,含文件改动预判)

**做什么**:把"扫目录列会话"从 `/log list` 命令里抽出来,变成正式函数层,补齐时间、排序。

| 文件 | 动作 | 说明 |

| `src/my_agent_alpha/logmanager/sessions.py` | 新建 | `SessionMeta`(目录名/标题/修改时间)+ `list_sessions(根目录)`;只读元数据,**不读正文**(个人使用量级,先不做 gptme 的"只读尾部 8KB"优化) |
| `src/my_agent_alpha/commands/builtin.py` | 修改 | `/log list` 改调 `list_sessions()`,按时间倒序显示 |
| `src/my_agent_alpha/logmanager/__init__.py` | 修改 | 导出新函数 |
| `src/my_agent_alpha/hooks/naming.py` | 修改(小) | `read_session_title` 挪到 `logmanager/sessions.py`(标题属于会话元数据;也避免 logmanager→hooks 的反向依赖循环),naming.py 改为引用 |

**验收(效果)**:`/log list` 显示"目录名 + 标题 + 最后修改时间",一眼分清哪个会话是哪个。

### S2 跨进程文件锁(半天级)

**做什么**:每个会话目录配 `.lock`,防止两个进程同时打开同一会话把日志写花。

| 文件 | 动作 | 说明 |
|---|---|---|
| `src/my_agent_alpha/logmanager/manager.py` | 修改 | `LogManager.load()` 增加锁:目录内 `.lock` 文件 + `fcntl.flock(LOCK_EX\|LOCK_NB)` + 锁文件写 PID;持锁失败时若 PID 已死则清废锁重试;同进程重复加载同会话放行;释放在 `finally`/`atexit` |
| `src/my_agent_alpha/logmanager/__init__.py` | 修改 | 导出新的异常类型(如 `SessionLockedError`) |
| `src/my_agent_alpha/__init__.py` | 修改(小) | `main()` 捕获锁异常,给人话报错("这个会话正被另一个窗口使用") |
| `tests/test_logmanager.py` | 扩展 | 两把锁互斥(子进程持锁)、废锁自动清(写死 PID)、同进程放行 |

**注意**:Linux/macOS 先行(fcntl),Windows 分支预留(与 dirs.py 的既有态度一致);subagent 子进程用的是自己的新会话目录,不受影响;测试隔离靠已有的 `ALPHA_LOGS_HOME`。

**验收(效果)**:两个终端窗口各开一个会话**同时干活**互不干扰(多开达成);第二个窗口打开同一会话被直接拒绝;进程崩溃后废锁自动清,不会锁死自己。

### S3 单进程多会话注册表 + 切换(1–2 天,仍串行)

**做什么**:一个进程里同时开多个会话,`/new` `/switch` `/close` 切换。此阶段**同一时刻只有一个会话在干活**(turn 在主线程跑,REPL 阻塞中本来就切不了——天然满足),先把"开多个、随便切、互不串"做稳。

| 文件 | 动作 | 说明 |
|---|---|---|
| `src/my_agent_alpha/session_manager.py` | 新建 | `SessionManager`(内存 dict:名字→会话)+ `LiveSession`(LogManager + 运行状态:正在生成标志/锁/输出缓冲占位)。**不持久化**,重启即失(磁盘才是家) |
| `src/my_agent_alpha/chat.py` | 修改(本阶段最大改造点) | `chat()` 拆两层:"装配一个会话"(MCP 连接、钩子/命令注册、系统提示词、记忆索引)与"跑对话循环"分开;REPL 顶层持 SessionManager,切换 = 换当前会话指针 |
| `src/my_agent_alpha/confirm.py` | 修改(必须) | `_hooks`/`_auto_confirm` 从模块级全局改为 **ContextVar**(和工具注册表同款)——否则新会话一装配就会 `clear_confirm_hooks()` 把别的会话的确认链清掉,"本会话不再询问"也会串 |
| `src/my_agent_alpha/commands/__init__.py` | 修改 | `CommandContext` 增加字段(当前注册表/当前会话),`execute_cmd` 签名跟着改(chat.py 调用处同步) |
| `src/my_agent_alpha/commands/builtin.py` | 修改 | 新增 `/sessions`(列出已打开)、`/new [名]`、`/switch <名>`、`/close`;**`/exit` 从 SystemExit 改为"关当前会话"**(多会话下 SystemExit 会误杀整个进程,所有会话关完才退出) |
| `src/my_agent_alpha/__init__.py` | 修改(小) | `main()` 入口适配新 REPL 顶层 |
| `tests/test_session_manager.py` | 新建 | 开 A、B 两会话交替追加消息,验证互不串、切换后 LogManager 状态正确 |

**验收(效果)**:一个终端窗口像微信一样:`/new 调研` 开新会话聊两句 → `/switch 修登录页` 切到旧会话接着聊(历史都在)→ 再切回来无缝继续。

### S4 并行执行 + 输入泵(2–3 天,重头戏)

**做什么**:所有 turn(包括前台会话的)都跑在 worker 线程;主线程变成"输入泵"——只读输入、做路由。

| 文件 | 动作 | 说明 |
|---|---|---|
| `src/my_agent_alpha/session_manager.py` | 修改(大) | LiveSession 增加:worker 线程管理、输入唤醒 Event、**待确认请求 + 答复 Event**、中断代际号、输出缓冲;worker 启动时**显式设置**该会话的 ContextVar(workspace/logdir/model/工具表)——治"新线程不继承"的雷 |
| `src/my_agent_alpha/chat.py` | 修改(大) | 主循环改造成输入泵:`/命令` → 执行;前台会话有挂起确认 → 这行输入当 y/n/e/a 答复路由给 worker;普通输入 → 追加进前台会话并唤醒 worker。`_print_message`/`_StreamPrinter` 的输出目标参数化(前台会话直打 stdout,后台会话写自己的缓冲)。**中层循环的继续判定逻辑一行不动** |
| `src/my_agent_alpha/confirm.py` | 修改 | 增加"挂起/答复"路径:worker 里的确认一律登记"待确认+预览"然后等 Event,不再 `input()`;Ctrl-C 对前台会话改为置中断标志 |
| `src/my_agent_alpha/commands/builtin.py` | 修改(小) | `/stop <会话>`(请求中断后台会话) |
| `tests/`(并行集成测试) | 新建 | 真·两会话并发(mock provider 已有);确认挂起→答复→恢复;中断代际号。线程测试注意用 join+超时防 flaky |

**机制说明(输入泵)**:终端只有一个输入流,但 N 个会话 + N 个确认都想问话。规定:主线程是**唯一**读输入的人,读到一行后三选一路由(命令/确认答复/普通输入);worker 需要确认时登记请求并睡着等答复。无抢读、无竞争。

**验收(效果)**:会话 A 后台跑"全项目跑测试并修失败项",切到 B 正常聊;A 完成 → 前台提示;A 中途要执行危险命令 → 提示"等确认",切过去输 y 继续;对 A 发 `/stop` 能停。

## 六、风险与对策

| 风险 | 对策 | 阶段 |
|---|---|---|
| confirm 全局状态 + `input()` 抢终端 | ContextVar 化;确认一律"登记+等答复",只有主线程读 stdin | S3/S4 |
| 新线程不继承 ContextVar | worker 启动时显式设置 | S4 |
| `/exit` 的 SystemExit 误杀进程 | 改为关当前会话 | S3 |
| MCP 子进程每会话一份 | 沿用 chat() 现有 finally close,关会话时回收 | S3 |
| 多线程 print 交错 | 前台会话 worker 直打(第一版容忍,devlog 注明);后台一律缓冲 | S4 |
| 后台会话 streaming 中途打不断 | 第一版只在 step 之间的安全点生效,如实标注限制 | S4 |
| fcntl 不支持 Windows | Linux/macOS 先行,Windows 分支预留 | S2 |
| hooks 注册表仍是全局 dict | 现有钩子全部无状态(ctx 传参),S3 先保持并注释说明;真需要时再 ContextVar 化 | 观察项 |

## 七、不变的纪律(本次改造的红线)

1. 循环继续判定只看"最后一条 assistant 是否还有可运行 ToolUse",不引入额外状态;
2. `conversation.jsonl` 永不改写(每会话一个文件,天然隔离);
3. 消息不可变;call_id 一一配对;
4. 新横切(通知/确认路由)一律 hook/回调,不改核心循环;
5. 每函数中文简注,过 ruff/mypy/pytest 三关才能收工。
