# 051 · 流式修复:原生调用行落进 think 导致工具永不执行 + 两处流式防护

## 目标

用户用 glm-coding/glm-5.3(`--tool-format tool`)跑真机测试,模型的工具调用全部
被包进 `<think>...</think>` 里,工具一次都没执行。用户要求:全面审计
`_stream_once` 这个流式函数到底靠不靠谱,对照 gptme 原实现修掉所有隐患。

## 现场与根因

真机会话日志(affine-cipher 任务)里,assistant 消息长这样:

```
<think>Let me start by reading...@read(call_8e76...): {"path":".docs/instructions.md"}
@read(call_fa27...): {"path":"affine_cipher.py"}
</think>
```

整条回复(含调用行)全在 think 里,且日志里**没有任何带 call_id 的结果消息**。
根因链:

1. glm 是思考模型,这一轮的真实输出是"思考分片 → 原生 tool_calls 分片",
   **全程没有一段正文(delta.content)**;
2. `_stream_once` 里只有"正文到达"才会先关 think 再输出;调用行产出时
   没有关 think → 调用行落在 `<think>` 里,流结束时才补一个 `</think>`;
3. 解析器 `ToolUse.iter_from_content` 按规矩先 `strip_think`("think 里的
   调用是草稿")→ 解析出 0 个调用;
4. `has_runnable_tooluse` 判 False → 回合结束,工具永不执行;
5. 下一轮请求没有工具结果可带,模型以为结果丢了,原样再调一遍。

终端"全黑"是 TUI 把 think 区整块暗色显示,调用行也在里面。

对照 gptme(`/tmp/gptme` 已重新克隆,`llm/llm_openai.py:2208-2261`):
它用 `elif` 结构——**任何非思考的增量(正文或工具调用)到达时先把
`</think>` 发出去**,所以调用行永远在 think 外。这是本次修复的样板。

## 决策及理由

审计发现同一函数里还有两处数据丢失隐患,一并修:

1. **调用行产出前先关 think**(主修复):工具调用是"正式动作"不属于思考。
   没有照抄 gptme 的 `elif` 结构,因为它的写法在"空增量"上也会关 think,
   而我们只在真正要产出非思考内容时收口,避免思考/正文交错时反复开关。
2. **参数"恰好闭合"判断改为去尾判断**(`rstrip` 后再查大括号配对):
   有的服务商发格式化过的多行 JSON,`}` 后面跟换行/空格时原判断永远不成立。
3. **流结束兜底补产出**:无参数工具的 arguments 全程是空串,永远等不到
   "大括号闭合" → 原实现静默丢掉这次调用。现在流结束时统一补
   `@名字(编号): {}`(参数非空但没闭合的也原样补出,交给解析器裁决)。
4. **没有结束标记(finish_reason)→ 抛错**:流中途被掐断时,原实现把半截
   回复当完整回复存下来(静默丢失,最难受排查的一类)。仿 gptme
   (`llm_openai.py:2270-2274`)在流正常结束但从未见到 finish_reason 时抛
   RuntimeError。注意:断点检测触发后的"读尾巴拿用量"路径必须吞掉这个错
   (完整调用已到手,不能被尾巴打死回合),所以 `reply()` 的排干循环从
   `except StopIteration` 改成 `contextlib.suppress(Exception)`——代价最多
   丢一条用量记录。

非流式路径 `chat()` 不受影响(它不包 think 标签),未动。

## 改动结构

- `src/my_agent_alpha/llm/openai_compat.py`(`_stream_once`):
  - 新增 `finish_reason` 跟踪;循环内记录;
  - 调用行产出前:若 think 开着 → 先 `yield "</think>"`;
  - 就绪判断用 `acc["args"].rstrip()`(去尾空白后配对);
  - 流收尾:先关 think,再兜底补产未完成的调用行,最后查 finish_reason;
  - 文档串补截断行为说明。
- `src/my_agent_alpha/llm/__init__.py`(`reply`):排干循环吞掉所有异常
  (`contextlib.suppress`),新增 `import contextlib`。
- `tests/test_streaming.py`:假 chunk 造具重构成 `_chunk/_tc_frag/_usage_chunk/
  _patch_stream` 四件套(补 `finish_reason` 字段);新增 5 个测试:
  思考→调用时调用行在 think 外(主回归)、空参兜底、多行参数、无结束标记
  抛错、断点后排干断流不打死回合。
- `tests/test_native_tools.py`:`_tool_events` 假流补 `finish_reason="tool_calls"`。
