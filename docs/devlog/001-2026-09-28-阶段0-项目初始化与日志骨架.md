# 001 · 阶段 0:项目初始化与日志骨架

- **日期**:2026-09-28
- **阶段**:0 / 骨架(Message + JSONL 日志)
- **验收标准**:日志能追加、重启能恢复 —— ✅ 达成

## 一、目标

按 [gptme 架构研究报告](../gptme-study.md) §12 路线图启动仿造开发:

1. 用 uv 初始化 Python 项目(零运行时依赖起步);
2. 实现三大支柱中"支柱一"的落盘核心:`Message` + append-only JSONL 日志;

4. 建立开发记录制度(本文件)。

## 二、决策及理由

### 从 gptme 照搬的

| 决策 | 理由 |
|---|---|
| `Message` 只有 system/user/assistant 三 role;工具输出是带 `call_id` 的 system 消息 | 支柱一:磁盘格式 provider 无关、人类可读;call_id 纪律从第一天保持 |
| 相等性只看 `(role, content)` | gptme 同款约定(message.py:300);注意推论:同内容消息"相等",工具配对永远不得用 Message 相等性 |
| 追加游标(路径 + 字节数 + 对象身份 + 尾随换行四重校验) | 研究精华 #9:常规写 O(新增),前缀被改写/外部篡改时自动降级原子重写 |
| 原子全量重写 = 临时文件 + fsync + os.replace + 目录 fsync | 崩溃任何时刻不毁上一份完整日志 |
| 序列化宽容:from_dict 丢弃未知字段 | 向前兼容未来日志版本 |
| 环境变量前缀 `ALPHA_`(对应 gptme 的 `GPTME_`) | 短且清晰;`ALPHA_LOGS_HOME` 供测试隔离 |

### 刻意推迟的(记录在案,防止将来走样)

- **文件锁(flock)**:阶段 0 单进程假设;引入 server/子代理时必须补;
- **events.jsonl WAL**、**视图/分支压缩**:属阶段 6+;
- **附件与 `files`/`file_hashes`/`ephemeral_ttl` 字段**:消息结构已留扩展位;
- **mock provider**:原计划放在阶段 0,移到阶段 1 —— 没有 LLM 门面层时它无处安放;
- **platformdirs**:手动解析 XDG 足够(仅 Linux/macOS;上 Windows 再换);
- 相对路径 logdir + 进程中途 chdir 会让游标路径失配(审查中被提出又驳回),约定:调用方一律传绝对路径。

## 四、对抗式审查(23 个 agent:4 维度找 → 逐条证伪)

结果:**14 条确认(含 3 条重复报告)、5 条驳回**。确认问题全部修复:

| # | 严重度 | 问题 | 修复 |
|---|---|---|---|
| 1 | **high** | `read_text` 整文件解码:崩溃撕裂多字节 UTF-8 字符时抛 `UnicodeDecodeError`,会话永久打不开 | 改为按字节读、逐行解码 |
| 2 | **high** | 跳过残尾后游标照常盖章 → 下次走增量追加 → 坏行被挤成中间行 → 永久损坏 | 跳过残尾时游标保持未知,强制下次全量重写自愈 |
| 3 | **medium** | 重写路径 fsync 被 `sync=False` 门控,但 rename 无条件执行 → "rename 落盘、数据没落盘"的经典空文件事故 | 重写路径无条件 fsync(gptme 同款决策) |
| 4 | **medium** | naive 时间戳原样通过,破坏"恒为 aware"约定 | `from_dict` 对 naive 一律按 UTC 解释 |
| 5 | **medium** | metadata 直接引用外部 dict;不可序列化对象会让整次写入崩 | 构造时浅拷贝;`json.dumps(default=str)` 兜底 |
| 6 | **medium** | 文档声称相等性 =(role, content),实际 dataclass 还比较 call_id/标志位 | 全部 `compare=False`,实现与文档一致 |
| 7 | **low** | 非 dict JSON 行(如 `123`)报 AttributeError 而非 ValueError | `from_dict` 显式校验类型 |
| 8 | **low** ×2 | sync=True 增量分支、messages 防御性拷贝无测试保护 | 各补回归测试 |

被驳回的 5 条(避免将来重复怀疑):naive 时间戳仅是校验缺口、游标路径不 resolve、`load` 忽略已存在会话的 initial_msgs、append 先改内存后落盘无回滚 —— 均判定为符合设计或超出阶段 0 范围。

### ⚠️ 事件记录:审查子代理篡改代码

审查工作流结束后发现 `logmanager/manager.py:139` 被某个子代理篡改:

**教训:跑完多代理审查后必须全文核对被审文件(建议尽快建立 git 基线,用 diff 检测此类篡改)。**

## 六、已知限制

- 无文件锁:多进程同时写同一会话会互相触发全量重写(当前单进程假设,阶段 7 前补);
- metadata 为浅拷贝,嵌套结构仍与外部共享(约定只读);
- `LogManager.load` 未 resolve 相对路径(约定传绝对路径);
- 会话目录名暂无语义 slug(自动命名线程属后续阶段)。
