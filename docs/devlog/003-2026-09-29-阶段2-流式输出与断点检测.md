# 003 · 阶段 2:流式输出与断点检测

- **日期**:2026-09-29
- **阶段**:2 / 流式(stream 契约 + break_on_tooluse + think 渲染 + 重试)
- **验收标准**:token 逐块上屏;检测到完整工具调用立即中断生成并执行;推理内容暗色渲染 —— ✅ 达成(mock 全链路验证)

## 一、目标

把"憋完整段才输出"变成 gptme 的招牌体验:看着 agent 一个字一个字地干活,
工具调用写完整就立刻执行,不为多余 token 付费。

## 三、关键设计决策(全部照搬 gptme,出处见研究报告)

1. **流式契约**:`Generator[str, None, usage]` —— yield 规范格式文本块,return 携带 usage;
2. **`_StreamWithMetadata`**:包装生成器,从 `StopIteration.value` 捕获元数据(研究精华 #4)。
   自身实现 `__iter__`/`__next__`,支持"断点后继续排干"—— 断点后把剩余流排完(丢弃文本),
   usage 一分不少;
3. **空行确认规则**(gptme codeblock.py:355):流式视角下,闭合围栏后必须跟空行,块才算完整 ——
   "```" 后面可能马上还有内容(其实是更长块的内栏)。绝不执行半截命令;
4. **断点检测**:每收到含换行的块,就用 streaming 规则重析累积文本;发现完整可运行调用即 break。
   markdown 格式没有并行工具调用,断掉后面的文本是纯赚(不为它付 token);
   非流式解析(执行路径)不受影响 —— 两套规则各司其职;
5. **reasoning → `<think>`**:DeepSeek-R 等的 reasoning_content 增量到达,状态机在首块前发
   `<think>`、正文开始时发 `</think>`,推理内容在规范格式里可识别、可暗色渲染;
6. **渲染器跨块标签缓冲**:标签可能被分块切断("<thi" + "nk>"),留出"可能是半个标签"的尾巴
   等下一块拼齐;标签本身不打印,只作暗色/正常的状态切换(ANSI 手写,不引 rich);
7. **重试策略**(gptme llm/retry_policy.py 的教训):SDK 内部重试**归零**(`max_retries=0`),
   自家 5 次封顶指数退避(`ALPHA_LLM_MAX_RETRIES` 可调);瞬态分类(连接/限流/5xx)才重试,
   鉴权/参数错误一次都不重试;生成器只在未 yield 时重试,避免重复输出;
8. **流式中断语义**:Ctrl-C 落在生成期间 → 返回已生成的部分内容 + "^C 已中断"标记 +
   `metadata["interrupted"]`,中层循环见标记即停 turn、追加 INTERRUPT_CONTENT 协议消息
   (完整围栏若恰好已闭合仍会执行 —— 与 gptme 的"部分消息立即执行"一致)。

## 五、已知限制(按计划推迟)

- 未接真实模型的手工体验(需要 API key;契约已被 mock + 假事件全覆盖);
- `stream_options={"include_usage": True}` 少数兼容端点可能不支持(遇到再按 provider 关闭);
- Retry-After 头未解析(固定 2^n 退避);无请求级速率限制;
- prompt cache 断点(apply_cache_control)属阶段 3 与原生工具调用一起;
- 终端渲染仍是 ANSI 手写(rich 属后续美化);无 token 计数(截断预算属阶段 6)。
