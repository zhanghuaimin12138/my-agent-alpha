# 046 —— 压缩视图 V5:turn.post 自动触发

## 目标

按开发方案 §8 V5(§6.6)落地自动化:回合结束后看一眼预算,当前有效历史
快超窗就自动压成视图。手动 /compact 与 step() 的溢出重试保持不变
(后者仍是同一 turn 内中途超窗的最后防线)。

## 决策及理由

- **hooks/autocompact.py 独立成模块**,turn.post 注册(优先级默认):
  回合边界是唯一安全的压缩时机 —— 工具调用都已收尾;naming hook 同点
  注册,互不干扰。模型从 context.get_current_model() 取(与 naming 同款,
  不用改 chat.py 的 dispatch 调用)。
- **触发比例 0.8**(环境变量 ALPHA_AUTO_COMPACT_RATIO 可调):留两成余量,
  别等真超窗才动手。
- **发现并修复一个真实设计缺陷 —— 触发死区**:第一版 hook 直接把"模型
  全预算"当压缩目标,而触发线只有 0.8×预算;一段"刚过触发线"的历史会
  触发压缩、却压不出一成收益(is_meaningful_reduction 拒绝建视图),
  每回合白忙。修法:compact_current_to_view 增加可选 budget 参数,
  自动压缩传"触发线 × 0.75"的紧目标 —— 触发(≥0.8B)与目标(≤0.6B)
  之间必有 25% 落差,保证触发即有真收益。
- **失败冷却 3 回合**:安检不过(回合没收尾干净,如中断留下的无结果
  调用)或磁盘问题 → 打一行原因,冷却期内安静跳过,保留一切原样。
  冷却计数是模块级状态(与 todo 门控同款),conftest 每测试重置。
- **钩子零消息产出**:压缩状态只打控制台一行,不进会话日志/模型上下文
  (模型不需要看见"自己被压缩了")。mypy 因此要求各分支显式
  `return iter(())`(session_info_hook 同款模式)。
- **重复注册天然幂等**:register_hook 同名替换,TURN_POST 上 autocompact
  永远只有一个。

## 改动结构

- `src/my_agent_alpha/hooks/autocompact.py`(新增):should_auto_compact /
  autocompact_hook / register_autocompact_hook / reset_autocompact。
- `src/my_agent_alpha/compaction.py`:compact_current_to_view 加可选
  budget 参数(手动 /compact 不传,行为不变)。
- `src/my_agent_alpha/hooks/builtin.py`:注册 autocompact。
- `tests/conftest.py`:autouse 夹具重置冷却计数。
- `tests/test_autocompact.py`(新增,9 用例):阈值判断、不触发零动作、
  触发生成 001/002、失败冷却(期间零尝试、耗完再试)、未收尾调用拒绝、
  重复注册幂等、chat() e2e(四轮大思考区真历史过线自动压缩 + 压缩后
  续聊含工具调用回合)。
