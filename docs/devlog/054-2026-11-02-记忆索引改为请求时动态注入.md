# 054 - 记忆索引改为请求时动态注入(不进日志)+ 索引内存缓存

## 目标

修复一个设计缺陷:长期记忆索引原先在会话开场时渲染一份、作为 pinned 消息
写进 `conversation.jsonl`,此后记忆无论怎么改,日志里这条永远停在开场快照
—— 模型看不到新记忆的索引;`/resume` 旧会话更是用着旧会话开场的索引。
这也是"子代理自动记忆巩固方案"(docs/子代理自动记忆巩固方案.md)的前置
障碍:子代理改了记忆,主 agent 感知不到。

方案(用户提出,评估后采纳):

1. **记忆不进日志**:索引只在每次调模型拼装上下文(prepare_messages)时注入;
2. **内存缓存**:算过的索引按工作区缓存;memory 工具一改记忆就删缓存,
   下次请求自动拿到最新版。

## 决策及理由

- **注入点选 prepare_messages(compaction.py),注入发生在压缩之前**:
  token 计数真实(索引占预算)、注入条带 pinned(hard_cap 兜底裁剪不删它)、
  step() 的溢出重试路径自动生效。这也是 gptme 三层提示词中 dynamic 层
  (时间/git 状态)的同款思路:易变内容每次请求现算,不落盘。
- **旧日志遗留的索引条不动持久层**:日志/视图里的旧条保留(pinned 恒留、
  日志永不改写的纪律不破),只在请求组装时按内容前缀(`# 长期记忆`,
  新常量 MEMORY_INDEX_HEAD)剔除并换成最新 —— 持久层零改动,请求层永远最新。
- **注入位置**:开头连续 pinned 块之后(系统提示词后面、对话之前),
  与旧版在日志中的位置等价。
- **缓存失效挂在 rebuild_index 上**:save_memory/delete_memory 都经过它,
  失效只需写一处。已知限制:手动编辑记忆文件不走工具链,缓存感知不到,
  重启会话才刷新(罕见路径,不值得加文件监听,注释已写明)。
- **空索引也是有效缓存值**(空串 vs None 区分"算过是空"和"没算过")。

## 改动结构

- `memory_store.py`:新常量 `MEMORY_INDEX_HEAD`;`_index_cache` +
  `get_memory_index()`(带缓存)+ `invalidate_memory_cache()`;
  `rebuild_index` 顺带失效;`render_memory_index` 头部改用常量。
- `prompts/__init__.py`:`session_opening_messages` 去掉记忆索引,
  签名去掉 workspace 参数。
- `compaction.py`:新 `_inject_memory_index()` / `_is_memory_index()`;
  `prepare_messages` 在压缩前注入。
- `chat.py`:开场初始化调用处同步(注释更新)。
- `tests/conftest.py`:测试隔离追加 `invalidate_memory_cache()`。
- `tests/test_phase8.py`:e2e 测试改为断言"日志无索引 + prepare 注入有";
  新增缓存生命周期、旧索引剔除、无记忆不注入三个测试。
