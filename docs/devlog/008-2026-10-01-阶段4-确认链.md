# 008 · 阶段 4:确认链与安全分级

- **日期**:2026-10-01
- **阶段**:4 / 确认链(支柱三的第一个实战:横切关注点做成钩子,不改核心循环)
- **验收标准**:危险操作执行前问用户;只读命令不烦人;灾难命令连 -y 也拦 —— ✅ 达成

## 一、目标

给 agent 装安全护栏:此前 shell/save 相当于 gptme 的 `-y` 模式,模型说执行就执行。

## 二、设计(仿 gptme 的 TOOL_CONFIRM)

### 确认链(confirm.py,新模块)

"要不要确认"不是写死在工具里的 if,而是**按优先级排序的钩子链**:

```
get_confirmation(调用) → 依次问每个钩子:
    钩子返回结论(放行/拒绝/改写)→ 采纳,不再问下一家
    钩子返回 None("我不管")    → 问下一家
    链走完没人管                → 自动放行(自主模式:脚本/测试/-y)
```

会话开始时装配三层:

| 优先级 | 钩子 | 职责 | 注册条件 |
|---|---|---|---|
| 200 | guardrail | 灾难命令(rm -rf /、mkfs、fork 炸弹、关机…)直接拒绝 | **永远**(连 -y 也拦) |
| 10 | readonly | 只读命令(ls/grep/git status…)自动放行 | **永远**(不烦用户) |
| 0 | cli | 打印预览问用户 y/n/e/a | 仅交互模式且未开 -y |

用户答复:y/回车=放行;n=跳过;**e=改写**(命令/内容换掉再执行);a=本会话不再问。

### 与执行端的接合(tools/base.py)

`ToolUse.execute()` 开头过确认(只读工具完全绕过):
- skip → 产出 `[declined]` 标记消息,不执行;
- edit → `with_edited_content()` 造新调用(markdown 换 content;原生换 kwargs 的 command/content);
- DECLINED 消息被中层循环看到 → 本回合停止(仿 gptme 的 DECLINED 语义,防"拒绝后模型无限重试")。

### 安全分级(shell_safety.py,新模块)

- 只读判定:按管道/分号/&& 切段,**每段**都要是白名单命令(ls、cat、grep、
  git 只读子命令…),且无重定向、无命令替换、find 不带 -delete/-exec;
- 灾难模式:正则表(rm 指向 / 或 ~、mkfs、dd 直写磁盘、fork 炸弹、关机重启、强推主分支…);
- 方向:**判不准就往下走** —— 宁可多问一句,不可错放一条;
  (引号内容暂不特殊处理,属"宁可误拦"方向,后续加严)。

## 五、已知限制(按计划推迟)

- 引号感知的拒绝匹配、shellcheck、逐命令标志白名单(gptme 完整安全梯的后续层);
- save/append 一律询问(没有"安全路径"概念);
- 确认钩子是模块级注册表(单会话);阶段 5 通用 hook 系统时并入并按会话隔离;
- 非交互模式下灾难命令被拒后模型会收到说明,可在下轮换方案(预期行为)。
