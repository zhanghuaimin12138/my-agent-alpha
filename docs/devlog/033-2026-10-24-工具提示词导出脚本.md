# 033 · 工具提示词导出脚本

## 目标

写一个独立小脚本,把全部工具的"说明书"一次性导出到两个文件,
方便人眼审阅模型到底看到了什么 —— 用户学习提示词时想对照着看。

## 决策及理由

- 两条通道各导出一份,和真实发给模型的内容严格一致:
  - 原生模型(function calling):`spec_to_openai_tool` 生成的 JSON,
    即请求里 `tools` 参数的模样(只含可执行工具,与 openai_compat
    发请求时的过滤一致);
  - markdown 约定:`ToolSpec.get_tool_prompt` 逐个渲染,用 `---`
    分隔拼成一篇,与 prompts/__init__.py 拼系统提示词的方式相同。
- 放 `scripts/`(新建目录):它是一次性工具,不属于 src 包,不写进
  包导出;输出路径可用命令行参数覆盖,默认写到当前目录。
- 不加单元测试:脚本只做"渲染 + 写文件"两步,渲染逻辑本体
  (`spec_to_openai_tool`、`get_tool_prompt`)在 tests/unit/tools/ 里
  已有直接覆盖,再测脚本是测 I/O。

## 改动结构

- 新增 `scripts/dump_tool_prompts.py`(约 60 行):
  `render_native` / `render_markdown` 两个纯函数 + `main` 写文件。

## 验证结果

- `uv run python scripts/dump_tool_prompts.py` →
  输出"共 9 个工具",生成 `tools_native.json`(238 行)和
  `tools_markdown.md`(176 行);原生文件里数得 9 个 function 条目,
  两份内容一一对应。
- `uv run ruff format --check` / `ruff check` 通过;
  `uv run pytest -q` → 375 passed(未动源码与测试,确认无回归)。

## 下一步

- 无既定后续;若工具说明后续要人工校对描述长度(原生通道
  description 超 1000 字符会被截断),可用此脚本快速核对。
