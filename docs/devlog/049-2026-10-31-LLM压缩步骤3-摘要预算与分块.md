# 049 —— LLM 语义压缩 步骤 3:摘要预算与分块总结

## 目标

按报告 L4(方案步骤 3)解决"摘要请求自己就超窗"的问题:历史比摘要
模型窗口还大时,先裁单条、再按交互组分块(逐块小结 → 合并成最终笔记),
超上限诚实失败;压缩结果还要过"新视图不超正常模型预算"的检查。

## 决策及理由

- **两套预算显式分开**(报告 §6.2):摘要请求预算(窗口×0.9 − 笔记输出
  预留 − 指令预留,指令预留 min(2000, 窗口÷4) 封顶防小窗口被吃光)
  与新视图预算(正常模型的 get_context_budget)互不混用、不重复扣减。
  窗口小到预算 ≤0 时直接 failed("装不下任何历史"),一次模型调用都不发。
- **单条裁剪 bound_summary_input**:超长消息(默认 2000 tok,且不超过
  证据预算的四分之一)保头保尾、中间换省略标记 —— 报错在头、结论在尾,
  拦腰砍正好丢重点。dataclasses.replace 保 call_id 等全部字段;裁的是
  给记录员看的副本,主日志原文不动。
- **分块只落在组边界**(chunk_prefix 复用 tool_groups):块内调用与结果
  永远完整;单组自己超预算时单独成块,宁可偏大不拆散。
- **chunk → merge 两段提示词**:分块小结只抽事实、明确声明"这是一段
  不是全部"(防模型越权下全局结论);合并请求把旧 Checkpoint(若有)
  与各块小结按时间序喂给七节模板。三种请求(单次/分块/合并)统一走
  _request_summary(剥思考 + 非空检查),异常统一包 failed。
- **超上限诚实失败**:需要块数 > max_chunk_requests(默认 6)时返回
  failed"拒绝假装覆盖全部历史",绝不"只总结最后几条"糊弄(报告 §6.4)。
- **分块诊断记入笔记 metadata**:chunked/chunk_count/covered_ranges
  (各块覆盖的前缀消息区间,首尾相接可核对)。
- **新视图总预算检查**:组装结果超正常模型预算 → skipped(极端小窗口
  + 胖笔记的场景),排在收益检查之前。

## 改动结构

- `src/my_agent_alpha/compaction_llm.py`:
  - 新增 summary_input_budget / _clip_content / bound_summary_input /
    chunk_prefix / build_chunk_request / build_merge_request;
  - assemble_semantic_view 加 extra_meta 参数(分块诊断并入笔记元数据);
  - 服务层改造:预算判断 → 单次或分块路径 → 超限/小窗失败 →
    新视图总预算检查;_request_summary 统一模型调用。
- `tests/test_compaction_llm.py` +8:预算公式、单条裁剪(保字段/头尾/
  省略标记)、组边界切块、chunk/merge 请求格式、分块 e2e(假 16k 窗口,
  三段 scripted 回复:两块小结+最终笔记,断言 metadata 诊断与区间相接)、
  超块上限失败、小窗口失败、胖笔记超预算跳过。
- `src/my_agent_alpha/compaction.py`:仅用户学习注释折行过 100 列。
