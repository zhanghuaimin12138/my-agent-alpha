## 一、定位:/resume 是"单会话跳转",不是解冻多会话

一个进程同一时刻只有一个活跃会话(纪律不变)。`/resume` = **封存当前会话、
把活跃会话换成指定旧会话、把它的历史打印到终端、接着聊**。
没有会话注册表、没有线程,只是 REPL 循环里的一次受控跳转;
027-S3 的 `/switch` 将来在这个机制上推广,不算越界。

命令行层面的恢复其实已隐式存在:`--name <完整uuid>` 就是"打开那个目录接着聊"
(logdir = 会话根 / session_name)。缺的只是人机工程——没人记得住 32 位 uuid。

## 三、/resume 设计

用法两种:

- `/resume` —— 不带参数:打印编号列表(复用 /log list 行格式),读一个数字选择;
- `/resume <前8位或更长>` —— 直接跳;桶内前 8 位撞码时列出全部候选、
  要求多输几位(git 短哈希同款处理)。

机制(异常做受控跳转,不原地改历史):

```
用户输入 /resume xxx
  → 命令处理器找到目标目录,抛出 ResumeRequested(目标logdir)
  → chat() 的 REPL 顶层捕获:
      当前会话天然安全(每条消息即时落盘,跳走零丢失)
      manager = LogManager.load(目标logdir)     ← 换会话(重开,不改内存历史)
      for msg in manager: _print_message(msg)    ← 历史回放到终端
      继续原有 REPL 循环
```

为什么不"原地改 manager 内容"而要重开:消息不可变 + 日志是唯一事实来源,
重开 = 干净地换书签,不留"内存改历史"的口子。

回放格式:复用 `_print_message` 现有规则(role 标记、代码块、工具调用、hide 不显示)。

边界:

- 跳转前提示一句"当前会话已封存,回到它可用 /resume <码>"(纯提示,无损不需要确认);
- /resume 指向 subagent 会话 → 拒绝并说明;
- **空会话目录清理**:退出时若目录里没有 conversation.jsonl(开了没聊就跳走)则删除,
  否则 /resume 会持续制造空目录垃圾;
- 跳转后同步 ContextVar 里的 logdir(shell 的 tool-outputs 要写进新会话目录)。
