## 一、定位与总原则

**/resume 是"单会话跳转",不是解冻多会话。** 一个进程同一时刻只有一个活跃会话(纪律不变):
/resume = 结束当前会话 → 活跃会话换成指定旧会话 → 历史回放到终端 → 接着聊。
没有会话注册表、没有线程,是 REPL 循环里的一次受控跳转;027-S3 的 /switch 将来在此机制上推广。

三条已核对的事实,方案全部建立在它们之上:

| 事实 | 出处 | 对方案的意义 |
|---|---|---|
| chat() 打开旧会话时**本来就会回放历史** | [chat.py:646-649](../../src/my_agent_alpha/chat.py) | "打印在终端"零新代码,提取成函数两处复用 |
| 新会话**创建即写系统提示词** | [chat.py:635-639](../../src/my_agent_alpha/chat.py) | "空目录垃圾"不存在;真垃圾是"只有系统提示、没有用户消息"的会话(见 §5) |
| MCP/钩子/命令/确认链/模型 都是**工作区级装配**,不随会话走 | [chat.py:613-633](../../src/my_agent_alpha/chat.py) | 切换会话**不需要**重新装配任何东西,只换 manager 和 logdir 指针 |

命令行层面的恢复已隐式存在:`--name <完整uuid>`。/resume 补的是人机工程。

## 四、/resume 命令

### 4.1 用法与交互

- `/resume <码>`:码 = 会话 id 前缀(≥8 位;更长更精确)。三种结局:
  - 恰好 1 个匹配 → 跳转;
  - 0 个 → `没找到以 xxx 开头的会话,用 /log list 查看`;
  - 多个 → 列出全部候选(带码),提示"多个会话以此开头,请多输几位"(git 短哈希同款);
- `/resume`(无参,**拍板 A**):打印编号列表 → `input("输入序号恢复(回车取消): ")` → 回车/非数字取消;
- 拒绝场景,各自一句人话提示、不跳转:
  - 码指向 subagent 会话:`这是子代理的工作记录,不能恢复续聊`;
  - 码就是当前会话:`这就是当前会话`;
  - non-interactive 模式:`非交互模式不支持 /resume`(防脚本里排队误跳)。

### 4.2 跳转机制(核心)

命令处理器只负责"找到目标 + 抛异常",真正的切换发生在 REPL 循环里:

```python
# commands/__init__.py 新增
class ResumeRequested(Exception):
    """/resume 命令请求切换会话;chat.py 的 REPL 循环捕获并执行切换。"""

    def __init__(self, meta: SessionMeta) -> None: ...
```

```python
# chat.py:_run_chat_loop 里,命令分支改为
if content.startswith("/"):
    try:
        if execute_cmd(content, manager, model):
            continue
    except ResumeRequested as r:
        manager = _switch_session(manager, r.meta, prompt_queue)
        continue
```

`_switch_session(旧manager, 目标meta, prompt_queue) -> 新manager`(chat.py 新增私有函数,全部逻辑集中在这):

1. **封存旧会话**:派发 SESSION_END 钩子;若旧会话"没有用户消息"→ 删掉整个目录(见 §5);
2. **装载新会话**:`manager = LogManager.load(meta.logdir)`(目标必存在——列表只收有用户消息的);
3. **指针更新**:`set_logdir(meta.logdir)`(在 agent_context 的嵌套里再 set,退出时会被 agent_context 复位,语义正确;shell 的 tool-outputs、压缩归档从此写进新会话目录);
4. **回放**:派发 SESSION_START(现有 session_info 钩子会打印新会话目录,天然当切换横幅);`for msg in manager.messages: _print_message(msg)` —— 与 chat() 启动回放**同一个循环提取成 `_replay(manager)` 复用**(hide/quiet 消息按 _print_message 现有规则不显示);
5. **清空 prompt_queue**:切换前排队的输入(含 LOOP_CONTINUE 钩子的接力)属于旧会话语境,不带到新会话;
6. 打印 `(已切换:标题 (码) · N问 · 回到旧会话可用 /resume <码>)`。

为什么用异常而不是命令直接改 manager:命令只拿到 manager 的引用,没有 REPL 循环的变量;
异常是"子层请求上层做事"的标准通道(本项目已有先例:/exit 抛 SystemExit)。

### 4.3 明确不重新装配的东西(以及为什么)

MCP 客户端、工具表、钩子、确认链、模型:全部是**工作区级**(同一 workspace、同一 config.toml、
同一进程),换会话不换工作区 → 一律不动。只有 logdir 指针和 manager 是会话级的。

## 五、会话卫生:清理"没人聊过"的会话(拍板 B)

初版方案说"空会话目录会残留"——**核对后这是错的**:chat() 对新会话立刻写系统提示词
(chat.py:635-639),所以目录永远非空。真正会积累的噪音是:

> 只有系统提示词、**一条用户消息都没有**的会话(启动了就 Ctrl-D,或 /resume 跳走)。

规则(简单、安全):

- **删除时机**:会话结束时。两个出口都覆盖:chat() 正常退出的 finally、_switch_session 封存旧会话时;
- **删除条件**:conversation.jsonl 里没有任何 `role=="user"` 的行 → 删整个会话目录;
- **永不误删**:有用户消息的会话(哪怕只有一句)绝不删;--name 起过名但没人聊的同样删(名字丢了无所谓,那本来就是没发生的会话)。

实现为 sessions.py 的 `prune_empty_session(logdir: Path) -> bool`(返回是否删了,调用处打印一句)。
